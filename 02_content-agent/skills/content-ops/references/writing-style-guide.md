# 작성 스타일 가이드

## 어투 규칙

### 기본 어투
- **존댓말(합쇼체)** 사용: ~입니다, ~합니다, ~됩니다
- 절대 반말 혼용 금지 (~이다, ~한다 ❌)
- 독자를 "여러분" 또는 2인칭 없이 서술

### 예외
- LifeLog: 편안한 존댓말(해요체) 허용 (~예요, ~해요)
- 코드 주석: 반말 허용

## 구조 규칙

### Post (인사이트)
```
# 제목 (H1 사용 금지 - 프레임워크가 자동 생성)

## 도입부
- 독자의 문제 상황 / 관심사 제시
- 글에서 얻을 수 있는 가치 언급
- 2-3문단

## 본론 섹션 1
### 하위 주제 (필요 시)
- 구체적 설명, 사례, 데이터
- 3-5문단

## 본론 섹션 2
...

## 결론 / 정리
- 핵심 요약 (3줄 이내)
- 실무 적용 팁 또는 다음 단계 안내
```

### FAQ
```
# 질문? (H1 → 프레임워크 제목)

## 핵심 답변
- 1-2문단으로 직답

## 상세 설명
### 세부 주제 1
### 세부 주제 2

## 실무 적용
- 구체적 예시 또는 코드

## 관련 참고
- 연관 개념이나 추가 리소스
```

### Class (용어사전)
```
## 정의
- 1-2문장 핵심 정의

## 상세 설명
- 개념의 배경, 등장 맥락
- 3-5문단

## 활용 예시
- 실무 적용 사례
- 코드 예시 (해당 시)

## 관련 개념
- 비교 개념, 상위/하위 개념
```

## 기술 용어 규칙

### 영어 그대로 사용
- API, SDK, SaaS, ROI, CTR, CPC, CPA
- Machine Learning, Deep Learning, LLM, RAG
- A/B Test, Funnel, Cohort, Retention

### 한국어 표기
- 콘텐츠 (O) / 컨텐츠 (X)
- 메시지 (O) / 메세지 (X)
- 앱 (O) / 어플 (X)
- 데이터 (O) / 데이타 (X)
- 인터페이스 (O) / 인터페이스 (O)

### 혼용 주의
- 한 글 내에서 같은 용어의 한/영 표기 통일
- 처음 등장 시 "한국어(English)" 형태 가능, 이후 한 가지로 통일

## 문단 길이
- 최소: 2문장
- 최대: 5문장
- 이상적: 3-4문장

## 리스트 규칙
- 불릿 리스트: 3-7개 항목
- 번호 리스트: 순서가 중요한 경우만 사용
- 항목 끝 마침표: 완전한 문장이면 마침표, 단어/구 나열이면 생략

## 코드 블록
- 언어 지정 필수: ```python, ```javascript 등
- 주석으로 핵심 설명 추가
- 실행 가능한 완전한 코드 선호 (스니펫보다)

## 태그 규칙

### 태그 선택 원칙
- 반드시 `CANONICAL_TAGS` 목록(`src/lib/constants.ts`)에서만 선택
- 글당 3-5개 (최대 5개)
- 영어 약어는 업계 표준 그대로 (CPC, GA4, SEO)
- 한국어 개념어는 가장 보편적인 표현 (어트리뷰션, 전환)
- 도구 이름(Claude Code, n8n 등)은 태그로 사용하지 않음
- 대상자(마케터, 비개발자)는 태그로 사용하지 않음

### 정규 태그 카테고리
- **마케팅 지표:** CPC, CPM, CTR, CVR, CPA, CAC, LTV, ROAS, ROI
- **마케팅 전략:** 퍼널, 어트리뷰션, 전환, 리타게팅, 퍼포먼스마케팅, SEO
- **분석/도구:** GA4, GTM, BigQuery
- **웹 기술:** HTML, CSS, JavaScript, React, DOM, API
- **AI/자동화:** AI, 자동화, 노코드, 바이브코딩
- **광고 플랫폼:** Meta 광고, Google 광고
- **데이터:** 데이터 분석, 데이터 추적
- **일반:** 마케팅 실무, 광고

## 마크다운 강조(Bold) 규칙

- `**텍스트**` 형태의 bold 사용 가능
- `**텍스트**` 뒤에 바로 한글이 오는 패턴 허용 (MarkdownRenderer가 자동 전처리로 해결)
- 예: `**버튼(Button Element)**입니다` → 정상 렌더링됨

## 퀴즈 규칙

### Post (인사이트) 퀴즈
- 글에서 다룬 경험/분석 기반의 "의견이 갈리는" 질문
- 모든 선택지가 일리 있어야 함 (명백한 오답 금지)
- explanation에서 글의 맥락을 근거로 답 설명
- "~일까요?", "~라고 생각하시나요?" 형태의 열린 질문

### Class (용어사전) 퀴즈
- 핵심 개념 이해도를 확인하는 질문
- 비슷한 개념 간 차이를 구별하는 형태
- "~의 역할은?", "~과 ~의 차이는?" 형태

### 공통
- 퀴즈 1개, 선택지 3-4개 (4개 권장)
- explanation 2-3문장
- correctIndex는 0-based 인덱스

## 이미지 규칙

- 모든 콘텐츠에 자동으로 2개의 일러스트가 삽입됨 — **이미지 생성은 필수 단계**
- **`--no-images` 플래그 사용 금지** — 콘텐츠 생성 스크립트 실행 시 이미지 생성을 건너뛰어서는 안 됨
- 이미지 스타일: 플랫 디자인, 깔끔한 개념도/다이어그램
- 이미지에 텍스트 포함하지 않음
- Alt text: 한국어 30-80자, "~를 보여주는 개념도" 형태
- 배치: 글 전체의 1/3, 2/3 지점에 균등 배치
- 첫 번째 이미지는 ogImage(SEO/소셜 미리보기 썸네일)로 자동 설정됨
- 생성 실패 시 이미지 없이 콘텐츠 진행 (비차단 처리)
- 기존 이미지 없는 콘텐츠: `npx tsx scripts/inject-images-all.ts`로 일괄 보강 가능
