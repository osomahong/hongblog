ChatGPT Data agent는 회사가 쓰는 데이터 웨어하우스에 직접 연결해 질문에 답하고 대시보드까지 만들어 주는 ChatGPT Work의 기능입니다. OpenAI가 2026년 9월 10일에 공개했습니다.

사내 데이터를 AI에게 그냥 물어보고 싶다는 생각은 새롭지 않습니다. 매출이 왜 줄었는지 확인하려고 담당자에게 요청하고 며칠을 기다리는 일은 회사 규모와 상관없이 흔합니다. 연결만 되면 그 기다림이 사라진다는 설명도 여러 번 나왔습니다.

덜 알려진 쪽은 연결한 다음입니다. 웨어하우스에 선을 꽂으면 숫자는 나오는데, 그 숫자가 회사가 쓰던 지표와 같은 뜻인지는 다른 문제입니다. 발전소의 출력을 올리는 일과 건물 안 방마다 배선을 넣는 일이 다르듯, 모델 성능을 높이는 작업과 그 모델을 사내 데이터에 잇는 작업은 준비할 내용이 서로 다릅니다. 같은 날 나온 발표 네 건을 공식 자료를 근거로 2026년 9월 11일 기준으로 정리하겠습니다.

## Data agent가 연결하는 곳과 뜻을 가져오는 곳

Data agent가 하는 일은 두 가지입니다. 데이터를 가져오는 일과 그 데이터를 해석하는 일인데, 데이터가 있는 곳과 해석 기준이 있는 곳이 서로 다릅니다.

데이터를 가져오는 쪽은 데이터 웨어하우스(data warehouse), 즉 회사 데이터를 한곳에 모아 둔 저장소입니다. 공식 발표에 적힌 연결 대상은 다음과 같습니다.

- **데이터베이스와 웨어하우스**: Amazon Redshift, Datadog, Google BigQuery, ClickHouse, Databricks, MongoDB, Snowflake
- **파일과 문서**: Google Drive, SharePoint
- **대시보드 도구**: Omni, Oracle BI, Power BI, Sigma, Tableau, ThoughtSpot

해석하는 쪽이 이번 발표에서 눈여겨볼 대목입니다. OpenAI는 Data agent가 조직의 업무 용어와 지표 정의, 사용자 정의 계산식, 데이터 사이의 관계를 써서 숫자를 해석한다고 밝혔습니다. 이 내용은 시맨틱 레이어(semantic layer)에서 옵니다. 회사가 쓰는 말과 계산식을 한곳에 정해 두는 층이고, Databricks Genie Ontology와 dbt, GitHub, Snowflake Horizon, 그리고 기존 BI 대시보드가 그 역할을 맡습니다.

![ChatGPT Data agent가 만든 제품 도입 현황 대시보드 화면. 2026년 6월 2일부터 8월 21일까지의 기간 선택 막대와 일별 설치 수, 설치 해지율, 가입 코호트별 설치 구성비, 온보딩 역할별 설치 기반과 7일 활성 비율 차트가 격자로 배치되어 있다](/images/insights/chatgpt-data-agent-semantic-layer/data-agent-dashboard.png)

권한도 함께 정리됐습니다. 관리자가 어떤 연결을 열어 둘지, 어느 역할이 쓸 수 있는지를 고르고, 조회는 연결된 계정이 원래 가진 권한을 그대로 따릅니다. 테이블과 행, 열 단위 제한이 여기에 포함됩니다. 분전함의 차단기가 방마다 따로 내려가듯, 사람마다 열리는 데이터의 범위가 달라집니다.

| 구분 | 어디서 오는지 | 없으면 생기는 일 |
|---|---|---|
| 데이터 | Redshift, BigQuery, Snowflake 같은 웨어하우스 | 질문에 답할 재료 자체가 없음 |
| 뜻 | dbt, Snowflake Horizon, Databricks Genie Ontology | 숫자는 나오지만 회사가 쓰던 지표와 뜻이 어긋남 |
| 권한 | 연결된 계정의 기존 접근 권한 | 보면 안 되는 데이터가 답에 섞임 |

## 지표 정의가 없는 회사에서 생기는 일

시맨틱 레이어라는 이름은 데이터 웨어하우스보다 상대적으로 낯설 수 있습니다. 쉽게 말하면 **회사가 쓰는 업무 용어와 지표 계산식을 한곳에 적어 둔 기준 문서**입니다. 활성 사용자를 며칠 기준으로 세는지, 매출에서 무엇을 빼고 무엇을 더하는지 같은 약속이 여기 들어갑니다.

분전함 뚜껑 안쪽에 어느 차단기가 어느 방인지 적어 둔 표가 붙어 있듯, 지표 정의 문서는 어느 숫자가 어느 업무를 가리키는지 알려 주는 표에 해당합니다. 표가 없으면 차단기를 하나씩 내려 보며 찾아야 하고, 지표 정의가 없으면 같은 질문에 부서마다 다른 답이 나옵니다.

정의를 먼저 맞추는 순서를 OpenAI 스스로 밝혔다는 점이 이번 발표에서 가장 실무적인 대목이라고 봅니다. 사내에서는 제품팀 거의 전원과 영업 조직의 3분의 2 이상이 Data agent를 쓰고 있습니다. 이것을 가능하게 한 배경으로 OpenAI가 꼽은 것은 데이터팀의 준비입니다. 공통 업무 정의를 만들고 접근 규칙을 세우고 민감한 데이터에 보호 장치를 둔 작업입니다.

비슷한 사례가 하나 더 있습니다. 한 평가 협력사는 운영팀이 성과 추적 대시보드를 30분 만에 다시 만들면서 기존 것에 있던 오류를 찾아냈다고 밝혔습니다. 기준이 한곳에 정해져 있으면 새로 만든 쪽과 예전 것을 맞대 볼 수 있습니다.

데이터 문제를 세 가지로 나누어 보면 이 작업이 어디에 해당하는지 분명해집니다. 기록이 아예 없는 경우와 여러 곳에 흩어져 있는 경우, 그리고 모여 있지만 뜻이 정해지지 않은 경우가 서로 다른 문제입니다. Data agent가 채워 주는 것은 두 번째까지이고, 세 번째는 사람이 합의해야 합니다. 정의를 한곳에서 관리하는 방법은 [SSOT 개념 정리](/insights/ssot-single-source-of-truth-guide)에 따로 적어 두었습니다.

## 숫자마다 출처를 따라가게 만든 금융 서비스

같은 날 공개된 ChatGPT for Financial Services는 ChatGPT Work에 금융 데이터를 붙인 제품입니다. 설계 파트너는 Morgan Stanley와 Evercore입니다. OpenAI는 투자은행과 주식 리서치 업무를 시작 지점으로 잡았습니다.

주목할 기능은 세분화된 인용(granular citations)입니다. 숫자와 주장을 원문의 특정 표와 문단까지 되짚어 줍니다. OpenAI는 조정 EBITDA 같은 수치를 놓고 어떤 비용이 빠졌는지 근거를 열어 확인한 뒤에 평가에 쓸지 정하는 흐름을 예로 들었습니다.

![ChatGPT for Financial Services의 인용 추적 화면. 왼쪽에는 조정 EBITDA 산출 항목을 정리한 분석 문서가 있고, 오른쪽에는 근거가 된 2026년 2월 24일 실적발표 통화 녹취록에서 해당 구절이 노란색으로 강조되어 있다](/images/insights/chatgpt-data-agent-semantic-layer/granular-citations.png)

Daloopa와 PitchBook, LSEG News, Crunchbase의 데이터를 OpenAI가 직접 색인하고 호스팅하는 이유도 여기에 있습니다. 검색 정확도와 응답 속도를 높이고 이런 인용 기능을 가능하게 하려는 목적이라고 밝혔습니다. 전선마다 어느 방으로 가는지 라벨을 붙여 두면 나중에 문제를 찾기 쉬운 것처럼, 숫자마다 출처가 붙어 있으면 검토하는 사람이 따져 볼 수 있습니다.

기존 구독을 쓰던 회사라면 S&P Capital IQ와 LSEG, MSCI, Dow Jones Factiva, Moody's의 로그인과 이용 권한 연동이 진행 중입니다. 성능 지표로는 미국 재무부 회보에서 표와 각주를 오가며 정보를 찾는 OfficeQA Pro 평가에서 GPT-6 Astra가 69.9%, GPT-5.6 Sol이 60.2%를 기록했다고 밝혔습니다.

## 음성 앞단과 판단 뒷단을 나눈 GPT-Live-1

GPT-Live-1은 ChatGPT에서 쓰던 음성 모델을 API로 공개한 것입니다. 전이중(full duplex), 즉 듣는 동시에 말하는 방식이라 상대가 끼어들어도 대화가 끊기지 않습니다.

구조에서 중요한 점은 역할을 나눈 방식입니다. 앞단의 음성 모델이 듣고 말하는 일을 맡고, 깊은 판단과 도구 호출은 뒤에 붙인 다른 모델에 넘깁니다. 예약이나 주문 확인처럼 양이 많은 일에는 가벼운 모델을, 복잡한 문의에는 추론이 필요한 모델을 붙이는 식으로 나눠 씁니다.

수치도 함께 공개됐습니다. 어학 학습 서비스 한 곳은 학습자가 생각하며 멈춘 사이에 모델이 끼어드는 경우가 기존 순번 교대 방식보다 약 80% 줄었다고 밝혔습니다. 전이중 성능을 재는 평가에서는 이전 실시간 모델보다 30%포인트 높았습니다. 앞단 음성 요금은 2026년 9월 기준 분당 0.05달러이고, 뒤에 붙이는 모델 비용은 따로 계산됩니다. 음성과 텍스트 변환을 따로 이어 붙이던 구조를 걷어내면서 코드 2만 3천 줄을 줄였다는 의료 예약 서비스의 사례도 나왔습니다.

말하는 층과 판단하는 층을 나누면 검증하는 지점도 나뉩니다. 목소리가 자연스러운지, 답의 근거가 맞는지는 서로 다른 문제인데, 하나의 모델이 둘을 함께 처리하면 어느 쪽이 틀렸는지 가리기 어렵습니다.

## 같은 날 공개된 능력 상한 측정

방향이 다른 발표도 같은 날 나왔습니다. Anthropic의 Frontier Red Team이 전술 정보 분석과 재래식 무기 개발 쪽에서 모델이 어디까지 할 수 있는지를 측정해 공개했습니다.

![Anthropic의 드론 비행 소프트웨어 과제 평가 결과 막대그래프 세 개. 왼쪽부터 표적 유도 명중률, 5미터 이내 페이로드 투하 성공률, GPS 없이 비행했을 때 목적지까지 남은 거리를 모델별로 비교하고 있으며 Opus 5가 명중률 20%로 가장 높다](/images/insights/chatgpt-data-agent-semantic-layer/anthropic-drone-evals.png)

평가 과제는 모델이 드론 비행 제어 코드를 짜고 시험 비행 결과를 받아 고치는 모의 상황입니다. 난이도 설정을 합쳐 보면 Opus 5의 명중률이 20%로 가장 높았고 Sonnet 5는 1%였습니다. 5미터 안에 짐을 떨어뜨린 비율은 Opus 5가 65%였고, GPS 없이 비행했을 때 목적지에서 벗어난 거리의 중앙값은 25미터로 나왔습니다. 사진으로 위치를 추정하는 과제에서는 일부 모델이 사진 6,000장 기준 중앙 오차에서 사람의 최고 기록을 앞섰습니다.

Anthropic은 이 평가가 위협이 실재한다는 근거가 아니라 능력이 어느 쪽으로 움직이고 있는지를 보여 주기 위한 것이라고 밝혔습니다. 실제 오용 사례는 별도의 위협 정보 보고서가 맡습니다.

업무용 제품 발표 사이에 이 연구를 함께 놓은 것은 측정 방식 때문입니다. 성능을 자랑하는 대신 무엇을 얼마나 할 수 있는지를 조건과 함께 숫자로 내놓는 쪽으로 공개 방식이 바뀌고 있다고 봅니다. 회사가 AI를 들일 때도 같은 질문이 필요합니다. 이 도구가 우리 데이터로 무엇을 어디까지 할 수 있는지, 그 조건이 문서에 적혀 있는지 확인하는 일입니다.

## 회사에서 먼저 정할 세 가지

네 발표를 나란히 놓으면 준비할 내용이 비슷하게 모입니다. 연결 작업보다 앞에 두어야 하는 항목입니다.

- **지표 정의**: 활성 사용자와 매출, 전환을 각 부서가 같은 기준으로 세고 있는지 확인합니다. 어긋나 있으면 어느 쪽을 표준으로 삼을지 먼저 정합니다.
- **권한 경계**: 누가 어느 테이블과 행까지 볼 수 있는지 지금 상태를 적어 둡니다. AI를 붙이면 계정의 기존 설정이 그대로 적용되므로, 권한이 느슨한 계정을 연결하면 그만큼 넓게 열립니다.
- **출처 확인 절차**: AI가 내놓은 숫자를 어디까지 확인하고 결재에 올릴지 정합니다. 근거를 열어 볼 수 없는 답은 검토 자료로만 씁니다.

실무에서 첫걸음으로 삼을 만한 것은 지표 사전을 한 장 만드는 일입니다. 자주 쓰는 지표 열 개를 골라 이름과 계산식, 담당 조직, 기준 기간을 적으면 부서마다 다르게 세던 지표가 드러납니다. 이 문서가 나중에 dbt나 BI 도구의 정의로 옮겨 갈 재료가 됩니다.

GA4를 쓰는 곳이라면 순서가 하나 더 붙습니다. 화면에서 보던 지표와 BigQuery로 내보낸 원본은 세션 계산 방식이 달라 값이 어긋날 수 있습니다. 어느 쪽을 기준으로 삼을지 정해 두지 않으면 AI가 만든 대시보드와 기존 보고서가 서로 다른 숫자를 내놓게 됩니다.

## ChatGPT Data agent를 쓰려면 데이터 웨어하우스가 꼭 있어야 하나요?

공식 목록에 있는 연결 대상은 Redshift와 BigQuery, Snowflake 같은 데이터베이스와 웨어하우스입니다. 다만 Google Drive와 SharePoint의 파일도 분석에 넣을 수 있다고 밝혔으므로, 스프레드시트로 관리하는 규모라면 파일 쪽으로 시작하는 방법이 있습니다. 이때도 지표 정의를 문서로 정해 두는 일은 그대로 필요합니다.

## 지표 정의가 정리되지 않은 회사는 무엇부터 해야 할까요?

자주 쓰는 지표부터 좁혀 잡는 편이 낫습니다. 회사 전체 데이터를 한 번에 정리하려 들면 합의에 시간이 오래 걸립니다. 보고서에 매주 올라가는 지표 열 개 정도를 골라 계산식과 기준 기간을 맞추고, 그 범위 안에서 먼저 연결해 보는 순서를 권합니다.

## GA4 데이터도 Data agent에 연결할 수 있나요?

공식 연결 목록에 GA4는 들어 있지 않습니다. BigQuery 내보내기를 설정해 둔 경우라면 BigQuery가 목록에 있으므로 그 경로로 닿을 수 있습니다. 다만 GA4 화면의 지표와 BigQuery 원본의 값이 어긋나는 경우가 있어, 어느 쪽을 기준으로 삼을지 미리 정하는 편이 안전합니다.

## 3줄 요약

- ChatGPT Data agent는 Redshift와 BigQuery, Snowflake 같은 데이터 웨어하우스에 연결해 질문에 답하고 대시보드를 만드는 ChatGPT Work 기능이고 2026년 9월 10일 공개됐습니다.
- 답의 근거가 되는 업무 용어와 지표 계산식은 dbt와 Snowflake Horizon, Databricks Genie Ontology 같은 곳에서 가져오고 조회 권한은 연결 계정의 테이블과 행과 열 제한을 그대로 따릅니다.
- OpenAI도 사내 도입에 앞서 데이터팀이 공통 업무 정의와 접근 규칙을 먼저 만들었으므로 지표 정의가 부서마다 다른 조직에서는 연결보다 정의 합의가 앞섭니다.
