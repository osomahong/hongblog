향상된 전환(Enhanced Conversions)은 해싱된 자사 고객 데이터를 구글에 전송해 전환 측정의 정확성을 높이고 더 효과적인 입찰을 돕는 Google Ads 기능입니다. 광고를 클릭한 사람과 전환을 완료한 사람이 같은 사람인지 쿠키만으로 확인하기 어려워진 상황을 보완합니다.

전환 추적을 설정해 둔 계정은 많습니다. 사파리의 쿠키 제한이나 광고 차단 이야기도 한 번쯤 들어 보셨을 겁니다. 그런데 그 제한 때문에 광고 성과의 일부가 아예 집계되지 않는다는 점은 잘 알려져 있지 않습니다. 모르는 채로 두면 전환이 실제보다 적게 잡히고, 그 데이터를 학습하는 자동 입찰도 어긋난 방향으로 움직일 수 있습니다.

이 글에서는 향상된 전환이 왜 필요한지, 어떤 원리로 작동하는지, 구글애즈와 GTM에서 어떻게 설정하는지 정리합니다. 2026년 6월부터 적용되는 통합 변경도 함께 다룹니다. 2026년 8월 기준 공식 문서를 근거로 합니다.

## 해싱된 자사 고객 데이터란 무엇일까요?

첫 문장에 쓴 표현을 먼저 풀고 가겠습니다. 두 부분으로 나누면 쉽습니다.

- **자사 고객 데이터**: 고객이 우리 웹사이트에 직접 남긴 정보입니다. 주문서나 상담 신청 양식에 적은 이메일, 전화번호, 이름이 여기에 해당합니다. 퍼스트 파티(1st Party) 데이터라고도 부릅니다.
- **해싱(Hashing)**: 원문을 알아볼 수 없는 문자열로 바꾸는 처리입니다. 같은 값을 넣으면 항상 같은 결과가 나오지만, 결과에서 원문을 되돌릴 수는 없습니다.

정리하면 해싱된 자사 고객 데이터는 **고객이 직접 남긴 연락처를, 사람이 알아볼 수 없는 암호 형태의 값으로 바꾼 것**입니다. 구글은 원문이 아니라 이 값만 받아서 전환 확인에 씁니다.

## 쿠키만으로 전환을 잇지 못하는 배경

전환 집계는 광고를 클릭한 사람과 [전환](/class/digital-marketing-terms/what-is-conversion)을 완료한 사람이 동일 인물임을 확인하는 일에서 시작합니다. 마트에서 영수증이 있어야 어떤 손님이 무엇을 샀는지 확인할 수 있듯, 광고 플랫폼은 쿠키가 있어야 클릭과 전환을 하나로 잇습니다.

문제는 이 영수증이 자주 사라진다는 점입니다. 사파리와 파이어폭스는 추적용 쿠키를 제한하고 있고, 광고 차단 프로그램을 쓰는 방문자도 있습니다. 광고는 휴대폰에서 클릭하고 구매는 PC에서 마치면 기기 사이에서 연결이 끊기기도 합니다. 이렇게 끊긴 전환은 플랫폼 입장에서 존재하지 않는 전환이 되고, 적지 않은 성과가 보고서에서 빠질 수 있습니다. 즉, 광고 성과에 좋은 영향을 줄 수 있는 근거 데이터가 사라진다는 것이죠. 흔히 말하는 서드파티 쿠키(제3자 쿠키)의 영향력이 약해지는 흐름과도 연관이 있습니다.

영수증을 잃어버린 손님도 계산대에서 멤버십 번호를 대면 구매 기록을 남길 수 있듯, 쿠키가 끊긴 자리를 다른 연결 고리로 메우는 방법이 향상된 전환입니다. 여기서 멤버십 번호 역할을 하는 것이 구매나 신청 과정에서 고객이 직접 남긴 이메일 주소와 전화번호입니다.

## 향상된 전환의 작동 방식 4단계

![향상된 전환의 작동 방식 4단계를 정리한 목업 이미지. 광고 유입, 전환 발생, 해싱 후 전송, 대조 후 반영 순서로 번호가 붙은 카드가 화살표로 이어진다](/images/insights/google-ads-enhanced-conversions-guide/enhanced-conversions-flow.png)

위 이미지는 웹사이트용 향상된 전환이 작동하는 순서를 정리한 목업입니다. 구글 공식 문서가 설명하는 흐름을 네 단계로 옮겼습니다.

1. **광고 유입**: 방문자가 구글 광고를 클릭해 웹사이트에 들어옵니다.
2. **전환 발생**: 구매 완료나 상담 신청 같은 전환 이벤트가 웹사이트에서 발생합니다.
3. **해싱 후 전송**: 방문자가 양식에 남긴 이메일 같은 자사 고객 데이터가 해싱되어 구글로 전송됩니다.
4. **대조 후 반영**: 구글이 이 값을 로그인된 구글 계정 정보와 대조해 전환 보고서에 반영합니다.

이때 이메일 주소가 원문 그대로 나가지 않습니다. 도장을 찍으면 자국만 남고 도장 자체는 넘어가지 않는 것처럼, SHA256이라는 단방향 해싱을 거친 값만 전송됩니다. 같은 이메일은 항상 같은 값을 만들므로 대조는 가능하지만, 그 값에서 원래 주소를 되짚을 수는 없습니다.

쓸 수 있는 데이터는 이메일과 전화번호, 그리고 주소입니다. 주소는 이름과 성, 우편번호, 국가를 한 묶음으로 칩니다. 이 가운데 하나 이상이 필요하고, 구글은 이메일 사용을 권장합니다.

## 마트 멤버십에 빗대 다시 정리하는 향상된 전환

앞의 4단계를 마트 비유로 한 번 더 살펴보겠습니다. 지금까지 쓴 비유를 한 자리에 모으면 향상된 전환의 등장인물이 한눈에 들어옵니다.

| 마트에서 | 향상된 전환에서 |
|---|---|
| 영수증 | 쿠키 |
| 멤버십 번호 | 고객이 남긴 이메일, 전화번호 |
| 도장 자국 | SHA256 해싱값(암호화된 값) |
| 멤버십 명부 | 로그인된 구글 계정 정보 |
| 데이터 확인으로 되살린 구매 기록 | 복구된 전환 |

전단지를 보고 온 손님이 계산대에서 영수증을 잃어버리면, 마트는 그 전단지가 효과가 있었는지 알 수 없습니다. 그런데 손님이 멤버십 번호를 대는 순간 명부에서 같은 사람이 확인되고, 전단지와 구매가 다시 이어집니다. 향상된 전환이 하는 일이 이 대조 작업이라고 볼 수 있습니다.

다른 점은 하나입니다. 마트는 번호를 그대로 받지만, 구글은 번호 대신 암호 형태로 되어 사람의 눈으로는 식별할 수 없는 해싱값(암호화된 값)만 받습니다. 그래서 대조는 되면서도 원래 연락처는 넘어가지 않습니다.

## 웹용과 리드 확보용의 구분

향상된 전환은 전환이 끝나는 위치에 따라 두 가지로 나뉩니다. 공식 문서 기준으로 차이를 정리하면 다음과 같습니다.

| 구분 | 웹용 향상된 전환 | 리드 확보용 향상된 전환 |
|---|---|---|
| 맞는 상황 | 구매, 신청이 웹사이트 안에서 끝나는 경우 | 웹에서 리드를 받고 계약은 전화나 오프라인에서 끝나는 경우 |
| 개선하는 측정 | 웹사이트 전환 측정 | 리드에서 이어진 오프라인 거래 측정 |
| 연결 키 | 이메일, 전화번호, 주소 | 이메일, 전화번호 |
| 데이터 흐름 | 전환 시점에 태그가 전송 | 리드 제출 시 해싱값 저장 후, 성사 시점에 대조 |

리드 확보용에서 눈여겨볼 점은 기존 오프라인 전환 가져오기와의 차이입니다. 기존 방식은 리드를 수집할 때 GCLID라는 클릭 식별자를 함께 받도록 양식과 CRM을 수정해야 했습니다. 향상된 전환은 이미 확보한 이메일 주소로 전환을 측정하므로 그 수정 작업이 필요 없다고 공식 문서가 안내합니다.

매장 방문 없이 전화로 주문을 마친 손님도 멤버십 명부에서 같은 사람임을 확인할 수 있듯, 리드 확보용은 웹 밖에서 끝난 계약을 웹에서 받은 리드와 이어 줍니다.

## 구글애즈에서 향상된 전환을 켜는 순서

아래는 2026년 6월 통합 전 UI 기준의 순서입니다. 설정은 계정 수준과 전환 액션 수준 두 곳에서 이뤄집니다.

1. **계정 수준 켜기**: 목표, 설정, 향상된 전환수 순서로 이동해 향상된 전환 사용에 체크합니다. 고객 데이터 약관에 동의하고 데이터 전송 방법(Google 태그, GTM, Google Ads API)을 고릅니다.
2. **전환 액션 수준 켜기**: 전환 액션을 만들거나 수정할 때 이 전환 액션에 향상된 전환 사용에 체크합니다. 기존에 만들어 둔 전환 액션에도 같은 항목이 있습니다.

켜기 전에 확인할 것은 두 가지입니다.

- **전환 태그가 실행되는 트리거**: 어떤 이벤트에서 전환 태그가 발동하는지 확인합니다.
- **그 시점의 고객 데이터**: 전환 태그가 실행되는 페이지에서 이메일, 이름, 전화번호 같은 자사 고객 데이터에 접근할 수 있어야 합니다. 구매 완료 페이지에 주문자 정보가 표시되는 경우가 대표적입니다.

## GTM으로 사용자 제공 데이터를 보내는 방법

![GTM 설정 흐름을 단순화한 목업. 왼쪽에 사용자 제공 데이터 변수의 수집 방법 세 가지, 오른쪽에 전환 ID와 변수를 연결하는 태그 구성이 그려져 있다](/images/insights/google-ads-enhanced-conversions-guide/gtm-user-provided-data-tag.png)

GTM에서는 변수를 먼저 만들고 태그에 연결합니다. 변수 메뉴에서 사용자 제공 데이터 유형을 선택하면 수집 방법 세 가지가 나옵니다.

| 방법 | 사용 상황 | 특징 |
|---|---|---|
| 자동 수집 | 전환 페이지에 고객 데이터가 표시되는 경우 | 태그가 페이지에서 자동 감지. 코드 삽입만큼 안정적이지 않음 |
| 수동 설정 | 데이터 위치를 직접 지정할 수 있는 경우 | CSS 선택자나 자바스크립트 변수를 지정 |
| 코드 | 개발 리소스가 있는 경우 | dataLayer로 값을 직접 전송. 정확성이 가장 높음 |

자동 수집과 수동 설정이 코드 삽입만큼 안정적이지 않다는 설명은 구글이 GTM 화면 안에서 직접 안내하는 내용입니다. 개발자 없이 시작한다면 자동 수집으로 켜 두고, 매칭 품질을 끌어올리는 단계에서 코드 방식으로 바꾸는 순서가 현실적이라고 볼 수 있습니다.

변수를 만든 뒤에는 위 그림처럼 Google Ads User-provided Data Event 태그에 전환 ID와 변수를 연결하고, 전환 추적 태그에서 웹사이트의 사용자 제공 데이터 포함에 체크하면 설정이 끝납니다.

## 2026년 6월부터 달라지는 것: 웹용과 리드용 통합

![2026년 6월 향상된 전환 설정 통합을 정리한 이미지. 왼쪽에 웹용과 리드 확보용 두 기능과 전송 방법 세 가지, 오른쪽에 켜기 스위치 하나로 합쳐진 모습이 그려져 있다](/images/insights/google-ads-enhanced-conversions-guide/enhanced-conversions-unification.png)

향상된 전환 설정은 2026년에 두 차례 바뀝니다. 위 이미지는 그 가운데 6월 통합을 정리한 것입니다. 구글이 공식 문서로 안내한 일정은 다음과 같습니다.

- **2026년 4월**: 구글애즈가 웹사이트 태그, Data Manager, API 연결에서 들어오는 사용자 데이터를 동시에 받기 시작했습니다.
- **2026년 6월**: 웹용과 리드 확보용이 하나의 기능으로 합쳐지고, 켜기와 끄기 스위치만 남습니다. 데이터 전송 방법을 고르는 메뉴는 사라집니다. 오프라인 전환 가져오기와 리드용 업로드는 Data Manager로 이동합니다.

기존 사용자는 별도 조치가 필요 없습니다. 고객 데이터 약관에 이미 동의한 계정이라면 자동으로 전환된다고 공식 문서에 명시되어 있습니다. 새로 시작하는 계정은 계정 또는 전환 액션 수준에서 향상된 전환을 켜면 됩니다.

이 글에서 다룬 설정 메뉴 일부는 통합 이후 더 단순해질 것으로 보입니다. 다만 어떤 데이터가 어떤 원리로 오가는지는 그대로이므로, 지금 구조를 이해해 두면 바뀐 화면에서도 헤매지 않습니다.

## 자주 묻는 질문

### 고객 이메일을 구글에 그대로 보내는 건가요?

아닙니다. 전송 전에 SHA256 단방향 해싱이 적용되어 원문을 복원할 수 없는 값만 구글에 전달됩니다. 다만 해싱 여부와 별개로 고객 데이터를 광고 측정에 쓰는 일 자체는 개인정보 처리에 해당하므로, 개인정보처리방침에 이 내용을 반영해 두는 편이 안전합니다.

### 향상된 전환을 켜면 전환수가 얼마나 늘어나나요?

정해진 폭은 없습니다. 쿠키 제한이 강한 브라우저나 광고 차단 환경에서 오는 방문 비중이 클수록 복구되는 전환이 늘어날 수 있습니다. 반영도 즉시가 아니라 시간이 지나며 나타나므로, 켠 직후가 아니라 2주에서 4주 정도 두고 추세를 보는 편이 낫습니다.

### 전자상거래 이커머스 사이트에도 해당되는 설정인가요?

해당됩니다. 구매가 웹사이트 안에서 끝나는 이커머스 사이트는 웹용 향상된 전환의 대표적인 사용처입니다. 구매 완료 페이지에 주문자 이메일 같은 고객 데이터가 이미 표시되는 경우가 많아, GTM의 자동 수집만으로 시작해도 됩니다. 호스팅형 쇼핑몰 솔루션을 쓰고 있다면 솔루션 쪽에서 관련 연동 기능을 제공하기도 하므로 먼저 확인해 보는 편이 좋습니다.

**3줄 요약:**
- 향상된 전환은 해싱된 자사 고객 데이터를 구글에 전송해 쿠키만으로 잇지 못하는 전환을 복구하는 Google Ads 기능입니다.
- 설정은 계정 수준과 전환 액션 수준에서 켜고, 전환 페이지에서 이메일 같은 고객 데이터에 접근할 수 있는지 먼저 확인합니다.
- 2026년 6월부터 웹용과 리드용이 켜기 스위치 하나로 통합되며, 기존 사용자는 별도 조치가 필요 없습니다.
