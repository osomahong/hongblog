> **2026년 9월 17일 안내:** 9월 16일 발표로 클로드 디자인을 대화 안에서도 쓸 수 있게 됐고, 단독 도구로도 그대로 남습니다. 같은 발표에서 Claude Docs와 Claude Slides가 유료 요금제에 베타로 열려 문서와 발표 자료도 같은 대화에서 만듭니다. 아래 요금제별 범위는 적용 뒤에 다시 확인하겠습니다. 바뀌는 내용과 적용 시점은 [클로드 코워크와 채팅 통합 정리](/insights/claude-cowork-chat-merge)에 따로 정리했습니다.

클로드 디자인(Claude Design)은 [앤트로픽](/class/claude-fundamentals/what-is-anthropic)이 2026년 4월 17일 공개한 대화형 디자인 도구입니다. 왼쪽 채팅에 원하는 것을 설명하면 오른쪽 캔버스에 시안이 만들어지고, 슬라이드와 프로토타입, 원페이저까지 같은 화면에서 다듬습니다.

새 도구가 나오면 사용법 글이 빠르게 올라옵니다. 그런데 도구 쪽이 조용히 바뀌면 그 글들은 그대로 남습니다. 읽는 사람은 최신 안내인 줄 알고 따라가게 됩니다.

클로드 디자인이 지금 그렇습니다. **사용량을 어떻게 세는지가 출시 뒤에 바뀌었는데, 검색 상위에 있는 한국어 글 대부분이 4월 기준을 유지하고 있습니다.** 지갑이 두 개인 줄 알고 예산을 짰다가 알고 보니 하나였던 것과 비슷한 상황이라, 쓰는 방법보다 이쪽을 먼저 정리하겠습니다. 공식 문서를 근거로 2026년 9월 14일 기준입니다.

## 요금제별로 어디에서 열리는지

클로드 디자인은 유료 요금제에만 있습니다. 무료 요금제에는 없습니다.

| 요금제 | 제공 | 켜는 방법 |
|---|---|---|
| 무료 | 없음 | |
| 프로 | 있음 | 바로 사용 |
| 맥스 | 있음 | 바로 사용 |
| 팀 | 있음 | 바로 사용 |
| 엔터프라이즈 | 있음 | **기본값이 꺼짐. 관리자가 조직 설정에서 켬** |

엔터프라이즈에서 메뉴가 보이지 않으면 계정 문제가 아니라 조직 설정입니다. 관리자에게 조직 설정에서 클로드 디자인을 켜 달라고 요청하면 됩니다.

들어가는 곳은 두 군데입니다. 웹에서는 `claude.ai/design`으로 들어가고, 클로드 데스크톱에서는 사이드바에 있습니다. **모바일 앱에는 없습니다.**

## 사용량은 채팅, 코드와 한 지갑에서 나갑니다

여기가 이 글에서 가장 중요한 대목입니다.

![앤트로픽 공식 문서의 사용량 및 가격 책정 섹션. 디자인 활동은 채팅과 클로드 코드, 코워크에 쓰는 공유 풀에서 가져오므로 별도의 클로드 디자인 할당량이 없다고 적혀 있고, 참고 문단에 이전에는 자체 주간 할당량이 있었으나 이제 플랜의 공유 제한에 포함된다고 적혀 있다](/images/insights/claude-design-guide/usage-shared-pool.png)

공식 문서는 두 가지를 적어 두었습니다. 디자인 활동이 채팅과 [클로드 코드](/class/claude-code-for-everyone/what-is-claude-code), [코워크](/insights/claude-cowork-what-you-can-do)가 쓰는 공유 한도에서 나간다는 것, 그리고 **이전에는 디자인 전용 주간 할당량이 따로 있었지만 이제는 공유 한도에 포함된다는 것**입니다.

실무에서 달라지는 점은 이렇습니다.

- **디자인을 많이 쓰면 채팅과 클로드 코드가 함께 줄어듭니다.** 반대도 같습니다. 오전에 코드 작업으로 한도를 많이 쓰면 오후 디자인 작업이 일찍 막힙니다.
- **한도에 닿으면 재설정될 때까지 디자인을 쓸 수 없습니다.** 사용 크레딧을 켜 두었다면 포함된 한도를 넘겨서도 작업을 이어갑니다.
- **큰 코드베이스를 연결하거나 반복을 많이 돌리면 소모가 큽니다.** 디자인 시스템을 만드는 작업이 특히 그렇습니다.

검색으로 찾은 글에 "디자인은 별도 주간 한도라 채팅 한도와 무관하다"고 적혀 있다면 4월 기준입니다. 널리 인용되는 소진 사례도 마찬가지입니다. 프로 요금제에서 30분 만에 주간 한도를 다 썼다거나 디자인 시스템 한 번 만드는 데 65%를 썼다는 수치가 돌아다니는데, 전부 전용 한도가 있던 시절의 기록이라 지금 계산에 그대로 대입하기 어렵습니다.

## 시작하는 순서

공식 문서가 제시하는 흐름은 일곱 단계입니다.

1. 프로젝트를 만듭니다.
2. 디자인 시스템을 첨부하거나 가져옵니다.
3. 스크린샷이나 코드베이스처럼 참고할 자료를 넣습니다.
4. 무엇을 만들지 설명합니다.
5. 캔버스에 나온 결과를 봅니다.
6. 채팅이나 인라인 댓글, 직접 편집으로 다듬습니다.
7. 내보내거나 공유합니다.

2번을 건너뛰지 않는 편이 좋습니다. 디자인 시스템을 먼저 넣어 두면 이후 만드는 것이 그 색과 서체, 컴포넌트를 기준으로 나옵니다. 깃허브 저장소나 디자인 파일을 연결하거나, 클로드 코드에서 `/design-sync`를 실행해 로컬 코드베이스에서 가져올 수 있습니다.

프롬프트에는 네 가지를 담습니다. 무엇을 만드는지, 어떻게 배치할지, 어떤 정보를 넣을지, 누가 쓸지입니다. 공식 문서가 예로 든 형태는 이렇습니다.

```
지역과 제품 라인 필터가 있는 월별 수익 대시보드를 만들어 줘.
핵심 기능을 안내하는 화면 4개짜리 모바일 앱 온보딩 흐름을 디자인해 줘.
히어로 섹션과 코드 예제, 가격이 있는 API 제품 랜딩 페이지를 만들어 줘.
```

반응형도 처음에 말해 둡니다. 모바일과 태블릿, 데스크톱 가운데 어디에서 작동해야 하는지 먼저 밝히면 다시 만드는 횟수가 줄어듭니다.

## 고치는 방법 세 가지

첫 결과는 시작점입니다. 공식 문서는 고치는 방법을 세 가지로 나누고 각각 언제 쓰는지를 정해 두었습니다.

| 방법 | 쓰는 때 | 예 |
|---|---|---|
| 채팅 | 구조를 바꾸거나 설명이 필요할 때 | 색을 더 어둡게 바꿔 줘, 대안 레이아웃 두세 개를 보여 줘 |
| 인라인 댓글 | 특정 컴포넌트를 고칠 때 | 이 버튼 여백을 키워 줘, 여기에 기본 브랜드 색을 써 줘 |
| 직접 편집 | 위치와 크기를 눈으로 맞출 때 | 요소를 끌어다 놓거나 크기를 조절 |

위치를 말로 설명하는 것보다 그 부분을 눌러 댓글을 다는 쪽이 빠릅니다. 다만 댓글이 화면에 나타나지 않는 문제가 알려져 있어서, 선택되지 않으면 피드백을 채팅에 붙여 넣으라고 공식 문서가 안내합니다.

피드백은 구체적으로 씁니다. "이건 아닌 것 같아요"보다 "양식 필드 사이 간격을 8px로 좁혀 줘"가 바로 반영됩니다.

## 내보내기와 클로드 코드 연결

만든 결과는 오른쪽 위 내보내기 버튼에서 꺼냅니다.

| 형식 | 쓰는 때 |
|---|---|
| zip 다운로드 | 파일로 보관 |
| PDF | 검토 요청, 인쇄 |
| PPTX | 발표 자료 |
| 독립형 HTML | 그대로 열어 보는 시안 |
| 캔바로 전송 | 마케팅 소재로 이어서 작업 |
| 클로드 코드로 전달 | 구현 단계로 연결 |

어도비와 감마, 러버블, 미로, 리플릿, 버셀, 윅스로 보내는 항목도 있고 대상은 계속 추가되고 있습니다. 조직 안에서는 링크로 공유할 수 있고 보기 전용과 댓글, 편집 권한을 나눠 줍니다.

구현까지 이어갈 계획이라면 클로드 코드 쪽 연결을 먼저 만들어 둡니다. 디자인을 코드로 옮길 때 스크린샷부터 다시 시작하지 않고 만들던 작업에서 이어집니다.

```
claude mcp add --scope user --transport http claude-design https://api.anthropic.com/v1/design/mcp
```

명령어를 넣은 뒤 `/design-login`으로 로그인하면 터미널에서 디자인을 만들고 고칠 수 있습니다. 반대 방향으로는 `/design-sync`가 디자인 시스템을 가져옵니다.

## 공식이 밝힌 제한 여섯 가지

베타 단계라 아직 걸리는 곳이 있습니다. 공식 문서가 직접 적어 둔 항목입니다.

![앤트로픽 공식 문서의 알려진 제한 사항 섹션. 댓글 지속성, 큰 코드베이스, 채팅 오류, 가용성, 다중 사용자 편집, 디자인 시스템 가져오기 여섯 항목이 정리되어 있다](/images/insights/claude-design-guide/known-limitations.png)

- **댓글이 화면에 안 보일 수 있습니다.** 댓글 보기를 열면 확인됩니다.
- **아주 큰 저장소는 클로드 코드에서 연결합니다.** 브라우저가 느려지는 것을 피하는 방법입니다.
- **채팅 업스트림 오류가 나면** 같은 프로젝트에서 새 채팅 탭을 엽니다.
- **웹과 데스크톱에서만 씁니다.** 모바일은 지원하지 않습니다.
- **두 사람이 동시에 편집하는 기능은 아직 불안정합니다.** 실시간 공동 편집이 필요하면 다른 도구를 함께 씁니다.
- **디자인 시스템 가져오기는 원본만큼만 좋습니다.** 정리되지 않은 코드베이스를 넣으면 결과에 그대로 나타납니다.

여기에 더해 피그마로 내보내는 기능과 PNG 이미지로 바로 내보내는 기능이 없다는 점이 사용자들 사이에서 자주 언급됩니다. 피그마에서 마무리하는 흐름이라면 이 부분을 먼저 확인하는 편이 좋습니다.

## 자주 묻는 질문

### 무료 요금제에서도 클로드 디자인을 쓸 수 있나요?

쓸 수 없습니다. 프로와 맥스, 팀, 엔터프라이즈 요금제에만 포함됩니다. 엔터프라이즈는 요금제에 포함돼 있어도 관리자가 조직 설정에서 켜야 구성원에게 보입니다.

### 디자인을 많이 쓰면 채팅 한도도 줄어드나요?

줄어듭니다. 디자인 활동이 채팅과 클로드 코드, 코워크가 함께 쓰는 한도에서 나갑니다. 출시 초기에는 디자인 전용 주간 할당량이 따로 있었지만 지금은 공유 한도로 합쳐졌습니다.

### 만든 디자인을 피그마로 옮길 수 있나요?
