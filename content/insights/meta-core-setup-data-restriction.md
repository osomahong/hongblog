## 메타에서 온 데이터 공유 제한 메일의 뜻

Meta Core 설정은 메타가 건강 및 웰빙 같은 제한 대상 카테고리로 분류한 웹사이트와 앱에 적용하는 데이터 공유 제한으로, 픽셀이 보내는 맞춤 매개변수와 도메인 뒤의 URL을 잘라냅니다. 이벤트 자체는 계속 받되 세부 정보만 빠진다는 뜻입니다.

메타 광고를 운영하는 분이라면 픽셀이 웹사이트의 방문과 구매를 메타로 보내고, 그 데이터로 맞춤 타겟을 만들고 전환 최적화를 한다는 것은 알고 계실 겁니다. 그런데 2026년 9월 2일 밤에 "중요: 곧 추가 데이터 공유 제한이 시작됩니다"라는 제목의 메일이 왔고, 본문에는 Core 설정과 데이터 소스 카테고리라는 말이 설명 없이 나옵니다. 이 메일을 읽지 않고 두면 맞춤 타겟이 조용히 줄어들고, 광고 세트가 최적화하던 이벤트가 어느 날 막힐 수 있습니다.

준이아빠블로그는 실제로 받은 메일과 메타 비즈니스 지원 센터의 공식 문서를 바탕으로 이 제한이 무엇인지, 언제부터 적용됐는지, 반영되면 광고 계정에 무슨 일이 생기는지, 이벤트 관리자에서 할 수 있는 일은 무엇인지 순서대로 정리합니다.

![2026년 9월 2일 Meta for Business 알림 계정에서 온 데이터 공유 제한 안내 메일의 첫 화면](/images/insights/meta-core-setup-data-restriction/01-meta-email-notice.png)

메일은 Meta for Business 알림 계정(notification@facebookmail.com)에서 왔고, 받는 사람 이름과 도메인, 픽셀 이름은 가렸습니다.

## Core 설정은 무엇이고 왜 내 계정에 적용됐을까요?

Core 설정이라는 이름은 픽셀이나 전환 API보다 상대적으로 낯설 수 있습니다. 쉽게 말하면 메타가 "이 사이트에서는 이런 데이터까지만 받겠다"고 정해 둔 제한 묶음입니다. 실제로 메타 공식 문서도 Core 설정을 "Meta 또는 회원님이 Meta 비즈니스 도구에 적용할 수 있는 데이터 공유 제한 집합"이라고 설명합니다.

편지 봉투에 도시와 동, 호수까지 적어 보내도 우체국이 도시 이름만 남기고 나머지를 지운 채 배달하듯, Core 설정이 적용된 사이트는 픽셀이 URL 전체를 보내도 메타에는 도메인까지만 남습니다. 봉투 뒷면에 따로 적어 둔 메모, 즉 맞춤 매개변수도 같이 지워집니다.

이 제한이 왜 내 계정에 붙었는지를 알려면 데이터 소스 카테고리부터 봐야 합니다. 메타는 데이터를 보내는 웹사이트와 앱, 즉 데이터 소스에 그 사이트가 다루는 주제를 기준으로 카테고리를 붙입니다. 그 가운데 일부 카테고리에는 메타 비즈니스 도구 약관이 공유를 금지하는 정보를 다룰 가능성이 높다고 보고 메타가 추가 제한을 겁니다. 공식 문서에 올라 있는 제한 대상 카테고리는 다음과 같습니다.

- **건강 및 웰빙**: 질병이나 특정 건강 상태, 환자 포털, 웰빙 추적 도구, 원격 의료, 약국, 건강보험, 질병별 지원 그룹
- **금융 서비스**: 금융 상품과 상담, 소비자 신용 보고서
- **적합하지 않은 콘텐츠**: 커뮤니티 규정과 광고 표준을 위반하는 콘텐츠
- **정치**: 특정 정당 구성원이나 정치적 이슈
- **인종, 종교, 성 및 성 정체성, 국적, 노동조합**: 특정 집단에 속한 개인과 관련된 주제
- **개인적인 어려움, 경제적 취약성**: 주거나 식량 안정에 직접 영향을 주는 어려움을 겪을 가능성이 높은 개인

메타는 이 목록이 일부만 담고 있고 시간이 지나면서 바뀔 수 있다고 적어 두었습니다. 이번 메일에서는 후원 사이트 하나가 "건강 및 웰빙 상태"로 분류됐는데, 질병별 지원 그룹과 환자 관련 서비스가 건강 및 웰빙의 예시로 올라 있어서 병원이 아닌 비영리 후원 사이트도 여기에 들어갈 수 있습니다.

Core 설정이 데이터 소스에 붙는 경우는 공식 문서 기준으로 네 가지입니다.

- 메타가 그 데이터 소스를 Core 설정이 필요한 카테고리로 판단한 경우
- 광고주 본인이나 같은 계정의 다른 사람이 데이터 세트나 데이터 소스를 제한 대상 카테고리로 직접 분류한 경우
- 공유하는 데이터가 약관을 위반할 수 있다는 알림을 여러 번 받은 경우
- 이벤트 관리자에서 광고주가 스스로 Core 설정의 데이터 제한을 켠 경우

이번 메일은 첫 번째 경우입니다. 메타가 분류했으므로 광고주가 카테고리를 직접 바꿀 수 없고, 뒤에서 설명할 검토 요청만 할 수 있습니다.

## Core 설정이 잘라내는 데이터 두 가지

공식 문서는 Core 설정이 제한하는 데이터를 두 가지로 적습니다.

| 잘리는 데이터 | 뜻 | 예 |
|---|---|---|
| 맞춤 매개변수 | 메타가 미리 정한 표준 매개변수 목록에 없는 매개변수 | plan_type, 진료 과목, 후원 프로그램 이름처럼 광고주가 직접 만든 항목 |
| 도메인 뒤의 URL | 도메인 다음에 오는 경로와 물음표 뒤의 값 전부 | https://jaspersmarket.com/clothes/summer/dresses?item=10이 https://jaspersmarket.com/으로 줄어듦 |

표준 매개변수와 맞춤 매개변수의 차이는 이벤트 이름보다 상대적으로 낯설 수 있습니다. 쉽게 말하면 표준 매개변수는 메타가 "구매 이벤트에는 금액과 통화를 적으세요"라고 미리 만들어 둔 칸이고, 맞춤 매개변수는 광고주가 새로 만든 칸입니다. 구매 이벤트의 value와 currency, 콘텐츠 조회 이벤트의 content_ids가 미리 만들어 둔 칸에 해당합니다. Core 설정은 새로 만든 칸만 지우고 미리 있던 칸은 남깁니다.

도메인 뒤가 잘린다는 것은 물음표 뒤에 붙는 utm_source 같은 값도 메타에는 도착하지 않는다는 뜻입니다. 어느 상품 페이지를 봤는지, 어느 캠페인 링크로 들어왔는지가 메타 쪽 데이터에서 사라지므로, 페이지 주소를 조건으로 삼는 기능은 전부 영향을 받습니다. 어떤 기능이 영향을 받는지는 아래 광고 계정에 생기는 일 부분에서 이어서 설명합니다.

## Core 설정의 적용 시점과 앞으로 더 막히는 것

메일 본문의 "회원님의 웹사이트 또는 앱이 일부 또는 모든 이벤트에 Core 설정을 적용하는 카테고리에 속해 있습니다"는 현재형입니다. Core 설정은 메일이 온 시점에 이미 적용 중이고, 바로 뒤 문장이 데이터 공유 추가 제한이 곧 시작될 수 있다며 그다음 단계를 예고합니다.

![안내 메일의 제한 정보와 성과에 미치는 영향, 다음 단계 안내 부분](/images/insights/meta-core-setup-data-restriction/02-email-restriction-details.png)

메타 공식 문서에는 이 제한이 시작된 날짜가 적혀 있지 않습니다. 업계 안내 글들은 2024년 11월부터 해당 광고주에게 분류 알림이 가기 시작했고 2025년 1월부터 건강 및 웰빙 카테고리에 제한이 적용됐다고 설명합니다. 이번 메일이 2026년 9월에 온 것을 보면 분류와 알림이 한 번에 끝난 것이 아니라 지금도 데이터 소스 단위로 계속 진행되는 것으로 보입니다. 내 도메인의 정확한 일정은 메일이 안내한 대로 이벤트 관리자의 상세 정보 보기에서만 확인할 수 있습니다.

메일이 말하는 "추가 제한"이 무엇인지도 공식 문서에는 단계 이름으로 정리되어 있지 않습니다. 다만 메일 본문이 "차단된 이벤트에 최적화했던 모든 광고의 성과가 영향을 받을 수 있다"고 적고 있어 이벤트 자체가 차단되는 단계가 있다는 것은 확인됩니다. 업계 안내 글들은 이 제한을 세 단계로 설명합니다.

| 단계 | 막히는 것 | 광고에 생기는 일 |
|---|---|---|
| Core 설정 | 맞춤 매개변수, 도메인 뒤의 URL | 이벤트는 들어오고 세부 정보만 빠짐 |
| 표준 이벤트 제한 | 장바구니 담기, 구매 같은 중하단 퍼널 이벤트 | 그 이벤트로 최적화하던 광고 세트가 멈추고 콘텐츠 조회나 트래픽 같은 상단 목표로 바꿔야 함 |
| 전체 제한 | 데이터 소스의 모든 이벤트 | 픽셀과 전환 API가 보내는 데이터를 메타가 받지 않음 |

지금 받은 메일은 첫 단계가 적용 중이고 두 번째 단계가 예고된 상태를 알리는 것으로 볼 수 있습니다.

## 반영되면 광고 계정에 실제로 생기는 일

공식 문서가 Core 설정의 영향으로 적어 둔 항목은 여섯 가지입니다. 항목마다 실제 화면에서 어떻게 드러나는지 한 줄씩 덧붙였습니다.

- **맞춤 타겟이 예상대로 작동하지 않음**: 맞춤 매개변수나 URL을 규칙으로 쓴 맞춤 타겟은 미리 채워지지 않고, 채워지는 데 오래 걸리거나 아예 쓸 수 없게 됩니다. "특정 상품 페이지를 본 사람"처럼 페이지 주소로 만든 타겟이 여기에 해당합니다. 주소가 도메인까지만 오니 누가 그 페이지를 봤는지 메타가 알 수 없기 때문입니다.
- **광고 세트가 영향을 받음**: 위 맞춤 타겟을 쓰던 광고 세트는 타겟 규모가 줄거나 업데이트가 멈춥니다. 메타는 광고 세트의 타겟을 새로 만들거나 바꾸라고 안내합니다.
- **이벤트 관리자 정보가 달라짐**: 이벤트 관리자의 샘플 활동과 테스트 이벤트 도구에서도 맞춤 매개변수와 URL 뒷부분이 보이지 않습니다. 세팅을 점검할 때 값이 안 보인다고 픽셀 오류로 착각하기 쉬운 부분입니다.
- **자동 고급 매칭을 못 쓸 수 있음**: 자동 고급 매칭은 픽셀이 폼에 입력된 이메일이나 전화번호를 자동으로 읽어 매칭에 쓰는 기능인데, Core 설정에서는 꺼질 수 있습니다. 이 경우 개발자 문서의 수동 고급 매칭으로 대체하면 됩니다.
- **픽셀로 카탈로그를 갱신하지 못함**: 픽셀 데이터로 카탈로그에 품목을 자동 추가하던 기능이 멈출 수 있어 품목을 직접 넣어야 합니다.
- **맞춤 이벤트 검토가 필요함**: 광고주가 직접 만든 맞춤 이벤트는 하나씩 검토해 확인할지 차단할지 정해야 하고, 확인한 이벤트만 캠페인과 맞춤 전환, 맞춤 타겟에 쓸 수 있습니다.

메일은 여기에 두 가지를 더 적습니다. 차단된 이벤트에 최적화했던 광고의 성과가 영향을 받을 수 있고, 광고 관리자의 캠페인 표와 캠페인을 만들거나 수정하는 화면에 영향을 받는 캠페인이라는 경고가 표시됩니다.

이 여섯 가지에 공통점이 하나 있습니다. 편지가 안 오는 것이 아니라 봉투에서 동과 호수가 지워진 채 오는 상황이라, 도착 건수만 보면 아무 일도 없어 보인다는 점입니다. 전환 수는 그대로인데 맞춤 타겟 규모가 서서히 줄고 URL 기준 맞춤 전환이 0에 가까워지는 방식으로 드러나므로, 메일을 받았을 때 바로 확인하는 편이 안전합니다.

## 이벤트 관리자에서 할 수 있는 일

메타가 분류한 카테고리는 광고주가 고칠 수 없지만, 확인과 검토 요청, 세팅 변경은 할 수 있습니다. 공식 문서와 메일이 안내하는 순서대로 정리했습니다.

### 어느 도메인이 어느 카테고리로 분류됐는지 확인

이벤트 관리자에서 확인하는 경로는 공식 문서 기준으로 다음과 같습니다. 비즈니스 포트폴리오의 전체 관리 권한이나, 그 데이터 세트를 소유한 광고 계정의 관리자 역할이 있어야 합니다.

1. 이벤트 관리자 왼쪽 메뉴에서 데이터 세트를 클릭합니다.
2. 데이터 세트 이름과 ID를 선택하고 상단의 설정 탭을 엽니다.
3. 데이터 소스 카테고리 관리 섹션으로 내려가 관리를 클릭합니다.
4. 도메인 또는 앱 ID, 소스, 카테고리, 검토 상태를 확인합니다.

![이벤트 관리자의 데이터 소스 카테고리 관리 화면. 후원 사이트의 데스크톱 도메인과 모바일 도메인이 건강 및 웰빙 상태로 분류되어 있고 검토 상태는 비어 있다](/images/insights/meta-core-setup-data-restriction/03-events-manager-data-source-categories.png)

어느 카테고리에도 속하지 않은 데이터 소스는 이 섹션이 아예 보이지 않기도 합니다. 위 화면에서는 같은 사이트의 데스크톱 도메인과 모바일 도메인이 따로 잡혀 있고, 하나는 "건강 및 웰빙 상태"와 "건강 및 웰빙 - 기타" 두 카테고리가 함께 붙어 있습니다. 도메인마다 카테고리가 다를 수 있으니 하나만 보고 끝내지 않는 편이 좋습니다.

### 분류가 틀렸으면 검토 요청

메타가 붙인 카테고리가 사이트 성격과 맞지 않으면 상세 정보 보기를 클릭한 뒤 검토 요청을 누릅니다. 요청이 접수됐다는 메시지가 뜨고, 결과는 이메일로 옵니다. 광고주가 직접 분류한 데이터 세트라면 검토 요청 없이 상세 정보 보기 옆의 화살표에서 카테고리 수정을 눌러 바로 바꿀 수 있습니다.

검토 요청은 사이트가 실제로 그 카테고리에 해당하지 않을 때 쓰는 기능입니다. 병원이나 질병 관련 후원 단체처럼 사이트 자체가 건강 및 웰빙에 해당하면 검토를 요청해도 분류가 유지될 가능성이 높으므로, 이 경우에는 다음 항목의 세팅 변경이 실질적인 대응입니다.

### 모르는 도메인이면 차단 리스트에 추가

메일에는 데이터를 보내는 웹사이트를 알아볼 수 없으면 이벤트 관리자의 차단 리스트에 그 도메인을 추가하라는 안내도 있습니다. 픽셀 코드가 다른 사이트에 복사돼 엉뚱한 도메인에서 데이터가 들어오는 경우가 있는데, 그 도메인이 어떤 카테고리로 분류될지는 광고주가 통제할 수 없으므로 목록에 낯선 도메인이 있으면 먼저 차단하는 편이 안전합니다.

### 잘리는 데이터에 기대지 않도록 세팅 변경

Core 설정이 유지된다는 전제로 광고 세팅을 바꾸는 방법은 공식 문서가 적은 영향 항목을 거꾸로 뒤집으면 나옵니다.

- **맞춤 타겟과 맞춤 전환은 URL 규칙 대신 표준 이벤트 규칙으로 만듭니다.** "URL에 /donate가 포함된 방문자" 대신 "Donate 표준 이벤트를 보낸 방문자"로 잡습니다.
- **필요한 정보는 맞춤 매개변수가 아니라 표준 매개변수에 담습니다.** 후원 금액은 value와 currency에, 어느 프로그램인지는 content_name이나 content_ids에 넣습니다.
- **자동 고급 매칭이 꺼졌으면 수동 고급 매칭을 설정합니다.** 픽셀 코드에서 해싱한 이메일과 전화번호를 직접 넘기는 방식입니다.
- **맞춤 이벤트는 이벤트 관리자에서 하나씩 검토해 확인 처리합니다.** 확인하지 않은 맞춤 이벤트는 캠페인 최적화에 쓸 수 없습니다.

업계 안내 글들은 여기에 더해 URL 경로와 이벤트 이름에서 질병명 같은 민감한 단어를 빼고 중립적인 이름을 쓰라고 권합니다. 다만 이 방법으로 카테고리 분류 자체가 바뀐다는 근거는 공식 문서에 없으므로, 분류를 바꾸려는 목적보다는 두 번째 단계에서 이벤트가 막힐 때 피해를 줄이는 준비로 보는 편이 맞습니다.

## 자주 묻는 질문

### Core 설정이 적용되면 픽셀 이벤트가 아예 안 들어오나요?

아니요. Core 설정 단계에서 잘리는 것은 맞춤 매개변수와 도메인 뒤의 URL 두 가지이고, 이벤트 자체와 표준 매개변수는 계속 들어옵니다. 이벤트가 차단되는 것은 메일이 예고한 추가 제한 단계이고, 그때는 광고 관리자에서 영향을 받는 캠페인에 경고가 표시됩니다.

### 검토 요청을 하면 제한이 풀리나요?

메타가 검토한 결과 그 사이트가 해당 카테고리에 맞지 않는다고 보면 분류가 바뀌고 제한도 함께 풀립니다. 메타가 붙인 카테고리는 광고주가 직접 수정할 수 없고 검토 요청만 할 수 있으며, 결과는 이메일로 통보됩니다. 사이트가 실제로 건강이나 금융 주제를 다루면 검토 요청보다 세팅 변경이 현실적인 대응입니다.

### GA4와 UTM 분석도 같이 영향을 받나요?

아니요. Core 설정은 메타 비즈니스 도구, 즉 픽셀과 전환 API가 메타로 보내는 데이터에만 적용됩니다. GA4는 별도 태그로 수집하므로 UTM 값과 페이지 경로가 그대로 남습니다. 다만 메타 광고 관리자 쪽에서 URL 매개변수를 조건으로 쓰는 맞춤 타겟과 맞춤 전환은 영향을 받으므로, 메타 성과와 GA4 성과를 나란히 볼 때 이 차이를 알고 봐야 합니다.

## 3줄 요약

- Meta Core 설정은 메타가 건강 및 웰빙 같은 제한 대상 카테고리로 분류한 웹사이트와 앱에 적용하는 데이터 공유 제한으로, 픽셀이 보내는 맞춤 매개변수와 도메인 뒤의 URL을 잘라냅니다.
- 픽셀이 보낸 URL은 도메인 뒤의 경로와 물음표 뒤의 값이 전부 잘려 도메인까지만 남기 때문에 URL 규칙으로 만든 맞춤 타겟과 자동 고급 매칭, 픽셀 카탈로그 업데이트가 멈출 수 있습니다.
- 메타가 정한 카테고리는 광고주가 고칠 수 없고 이벤트 관리자의 데이터 소스 카테고리 관리 화면에서 검토 요청만 할 수 있으며, 결과는 이메일로 옵니다.
