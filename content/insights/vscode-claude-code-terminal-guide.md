## PowerShell 대신 VS Code를 쓰는 이유

[클로드 코드(Claude Code)](/class/claude-code-for-everyone/what-is-claude-code) (클로드 코드가 무엇인지 설명한 글 바로가기)를 설치하고 나면 다음 질문이 따라옵니다. 어디에서 실행하느냐입니다. 윈도우 기본 도구인 PowerShell에서도 실행되지만, 며칠 써 보면 아쉬운 점이 드러납니다. 클로드 코드가 만든 파일을 확인하려면 창을 나가 파일 탐색기를 열어야 하고, 어느 폴더에서 작업 중인지도 한눈에 들어오지 않습니다.

> VS Code에서 클로드 코드를 실행하는 방법은 폴더를 먼저 연 뒤 그 안에서 터미널을 열고 `claude`를 입력하는 것입니다. 왼쪽에 파일 목록, 아래에 터미널이 함께 보여 작업 상황을 한 화면에서 확인할 수 있습니다.

VS Code는 마이크로소프트가 무료로 배포하는 코드 편집기입니다. 원래는 개발자가 코드를 쓰는 도구지만, 클로드 코드 사용자에게는 다른 쓰임이 더 큽니다. 터미널과 파일 목록, 파일 미리보기가 한 화면에 들어 있어 작업 창 역할을 해 줍니다.

이 글은 윈도우 PC를 기준으로 합니다. 클로드 코드 설치는 이미 마친 상태를 전제하며, 아직이라면 [윈도우 설치 가이드](/insights/claude-code-windows-easy-setup-guide) (윈도우 설치 순서 바로가기)를 먼저 보시면 됩니다. 맥을 쓰시는 분은 화면 구성은 같고 메뉴 이름과 단축키만 다릅니다.

## VS Code 내려받기

브라우저 주소창에 `code.visualstudio.com`을 입력해 접속합니다. 화면 가운데 파란 다운로드 버튼을 누릅니다.

![VS Code 공식 사이트 화면. 파란색 Download for Windows 버튼에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/01-download.png)

접속한 기기를 인식해 버튼에 자동으로 Windows가 표시됩니다. 다른 운영체제 이름이 보이면 버튼 옆 목록에서 Windows를 고릅니다.

## 설치할 때 체크할 항목

내려받은 파일을 두 번 눌러 실행합니다. 약관 동의와 설치 위치는 기본값 그대로 두고 다음을 누르다가, **추가 작업 선택** 화면에서 멈춥니다. 여기서 체크 항목을 확인해야 합니다.

![VS Code 설치 마법사의 추가 작업 선택 화면. Windows 탐색기 메뉴에 추가 항목과 PATH에 추가 항목에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/02-install-options.png)

**PATH에 추가**는 반드시 체크합니다. PATH는 윈도우가 명령을 찾는 경로 목록입니다. 이 항목이 빠지면 터미널에서 `claude`를 입력했을 때 `용어가 cmdlet, 함수, 스크립트 파일 이름으로 인식되지 않습니다`라는 오류가 납니다. 설치가 끝난 뒤 이 문제로 되돌아오는 사례가 있습니다.

**Windows 탐색기 메뉴에 추가**도 체크해 두면 편합니다. 나중에 폴더에서 마우스 오른쪽 버튼을 눌러 바로 VS Code로 열 수 있습니다.

체크를 마치면 다음과 설치를 눌러 끝까지 진행합니다. 설치가 끝나면 컴퓨터를 한 번 다시 켜는 편이 안전합니다. PATH 설정은 새로 시작한 뒤에 적용되기 때문입니다.

## 작업할 폴더 먼저 열기

VS Code를 실행하면 빈 화면이 나옵니다. 여기서 순서가 중요합니다. **터미널을 열기 전에 작업할 폴더를 먼저 엽니다.**

클로드 코드는 실행된 위치를 기준으로 파일을 읽고 만듭니다. 폴더를 정하지 않고 터미널부터 열면 엉뚱한 위치에서 작업하게 됩니다.

상단 파일 메뉴에서 폴더 열기를 고릅니다.

![VS Code의 파일 메뉴가 펼쳐진 화면. 파일 메뉴와 폴더 열기 항목에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/03-open-folder-menu.png)

폴더 선택 창이 뜨면 작업할 폴더를 지정합니다. 문서 안에 작업용 폴더를 하나 만들어 두고 쓰는 방식을 권합니다.

![윈도우 폴더 선택 창. 목록의 작업 폴더와 폴더 선택 버튼에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/04-select-folder.png)

여기서 실수하기 쉬운 지점이 있습니다. 폴더를 **두 번 눌러 안으로 들어가면 안 됩니다.** 한 번만 눌러 선택한 상태에서 폴더 선택 버튼을 누릅니다. 안으로 들어간 상태에서 버튼을 누르면 그 아래 폴더가 열립니다.

## 폴더 신뢰 여부 확인

폴더를 처음 열면 파일 작성자를 신뢰하느냐고 묻는 창이 뜹니다. 직접 만든 폴더라면 신뢰합니다.

![VS Code의 폴더 신뢰 확인 창. 예 작성자를 신뢰합니다 버튼에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/05-trust-folder.png)

신뢰하지 않음을 고르면 제한 모드로 열립니다. 이 상태에서는 클로드 코드가 파일을 만들거나 고치지 못합니다. 같은 폴더는 한 번만 물어보고 다음부터는 묻지 않습니다.

## 터미널 열기

이제 클로드 코드를 실행할 터미널을 엽니다. 상단 터미널 메뉴에서 새 터미널을 고릅니다.

![VS Code의 터미널 메뉴가 펼쳐진 화면. 터미널 메뉴와 새 터미널 항목에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/06-new-terminal.png)

단축키 `Ctrl` + `Shift` + 백틱(숫자 1 왼쪽 키)으로도 열립니다. 화면 아래쪽에 검은 영역이 나타나면 준비된 것입니다.

## claude 입력해 실행하기

터미널에 `claude`를 입력하고 엔터를 누릅니다.

![VS Code 아래쪽 터미널에 claude를 입력한 화면. 경로 부분과 claude 명령에 각각 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/07-type-claude.png)

```
claude
```

입력하기 전에 줄 앞에 적힌 경로를 확인합니다. 경로 끝이 방금 연 폴더 이름과 같아야 합니다. 다른 폴더 이름이 보인다면 폴더를 다시 여는 단계부터 진행합니다.

아래 화면이 나오면 준비가 끝났습니다. 이제 한글로 지시하면 됩니다.

![클로드 코드가 실행되어 입력을 기다리는 터미널 화면. 입력란에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/08-claude-running.png)

여기까지가 기본 흐름입니다. 다음부터는 세 단계로 끝납니다. VS Code 실행, 터미널 열기, `claude` 입력입니다. 지난번 폴더가 그대로 열려 있으면 첫 단계도 생략됩니다.

## 승인 질문을 건너뛰는 bypass 모드

클로드 코드는 파일을 읽거나 고치기 전에 매번 진행 여부를 묻습니다. 실수를 막는 장치라 기본값으로는 그대로 두는 편이 좋습니다. 다만 긴 작업을 맡기고 자리를 비울 때는 중간에 멈춰 서서 답을 기다리게 됩니다.

이때 쓰는 것이 bypass 모드입니다. 한 번 실행하면 작업이 끝날 때까지 묻지 않고 진행합니다. 실행할 때 `claude` 뒤에 옵션을 붙입니다.

```
claude --dangerously-skip-permissions
```

![VS Code 터미널에 claude --dangerously-skip-permissions를 입력한 화면. 명령어 전체에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/09-bypass-command.png)

명령 이름에 `dangerously`가 들어 있는 이유가 있습니다. 이 모드에서는 파일을 고치거나 지우는 작업까지 확인 없이 진행합니다. 잘못된 지시를 내려도 중간에 멈춰 주지 않습니다.

처음 한 번은 이 모드가 맞는지 확인하는 영문 경고문이 나옵니다.

![클로드 코드의 bypass 모드 경고문 화면. 2번 Yes I accept 항목에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/10-bypass-warning.png)

화면에 나오는 영문의 뜻은 다음과 같습니다.

| 화면의 영문 | 뜻 |
| --- | --- |
| WARNING: running in Bypass Permissions mode | 승인을 건너뛰는 모드로 실행됩니다 |
| will not ask for your approval | 위험할 수 있는 작업도 동의를 구하지 않습니다 |
| 1. No, exit | 쓰지 않고 나가기 |
| 2. Yes, I accept | 내용을 알고 쓰겠다는 선택 |

방향키로 2번을 고르고 엔터를 누릅니다. 입력란 아래에 `bypass permissions on`이 보이면 적용된 상태입니다.

![bypass 모드가 적용된 클로드 코드 화면. 입력란 아래 bypass permissions on 표시에 빨간 상자가 표시되어 있다](/images/insights/vscode-claude-code-terminal-guide/11-bypass-active.png)

기본 모드로 되돌리려면 터미널에서 `Ctrl` + `C`를 두 번 눌러 끄고, 다시 `claude`만 입력해 실행합니다. bypass 모드는 그 터미널에서만 유지됩니다.

## bypass 모드를 쓸 때와 쓰지 않을 때

| 상황 | 권장 |
| --- | --- |
| 오래 걸리는 작업을 맡기고 자리를 비울 때 | bypass 모드로 실행합니다 |
| 자료 조사나 문서 작성처럼 읽고 만들기만 하는 일 | bypass 모드로 실행해도 무방합니다 |
| 기존 파일을 고치거나 정리하는 일 | 기본 방식으로 실행해 한 번씩 확인하며 진행합니다 |
| 메일 발송, 결제, 외부 전송으로 이어지는 자동화 | bypass 모드를 쓰지 않습니다 |
| 작업 폴더 바깥(바탕 화면, 사진 폴더, 회사 공유 폴더) | bypass 모드를 쓰지 않습니다 |

마지막 두 줄이 중요합니다. 외부로 나가는 작업에서는 승인 절차가 실수를 막는 마지막 장치입니다. 메일이나 메시지가 잘못 발송되면 되돌릴 수 없습니다.

모드 종류를 더 알고 싶으시면 [Ultraplan, Auto 모드, bypass 모드 비교](/insights/claude-code-ultraplan-auto-bypass-mode) (세 가지 실행 방식의 차이 바로가기)에 정리해 두었습니다.

## 잘 안 될 때 확인할 것

| 증상 | 원인과 해결 |
| --- | --- |
| claude를 입력하니 용어가 인식되지 않는다는 오류가 납니다 | 설치할 때 PATH에 추가가 빠졌거나 설치 후 다시 켜지 않은 경우입니다. 컴퓨터를 다시 켜고 시도합니다 |
| 터미널 메뉴가 보이지 않습니다 | 창이 좁으면 메뉴가 접힙니다. VS Code 창을 최대화합니다 |
| 파일을 만들어 달라고 했는데 왼쪽 목록에 보이지 않습니다 | 폴더가 열려 있는지 확인합니다. 폴더 여는 단계부터 다시 합니다 |
| 진행이 멈춘 것처럼 보입니다 | 작업 중에는 아래에 소요 시간 표시가 계속 바뀝니다. 바뀌고 있으면 진행 중입니다 |
| 글씨가 작아 읽기 어렵습니다 | `Ctrl`을 누른 채 `+`를 누르면 커집니다. 터미널 안에서도 같습니다 |

설치 단계에서 막히는 오류는 [클로드 코드 설치 오류 해결](/insights/claude-code-install-errors) (설치 오류별 해결법 바로가기)에 유형별로 정리해 두었습니다.

## 3줄 요약

- VS Code는 클로드 코드를 실행하는 터미널과 결과 파일을 한 화면에서 보게 해 주는 작업 창입니다. 설치할 때 PATH에 추가 항목을 체크해야 터미널에서 `claude` 명령이 인식됩니다.
- 순서는 폴더 열기, 터미널 열기, `claude` 입력입니다. 폴더를 먼저 열어야 클로드 코드가 원하는 위치에서 작업합니다.
- 긴 작업을 맡기고 자리를 비울 때는 `claude --dangerously-skip-permissions`로 승인 질문을 건너뛸 수 있습니다. 외부 발송이나 작업 폴더 바깥에서는 쓰지 않습니다.
