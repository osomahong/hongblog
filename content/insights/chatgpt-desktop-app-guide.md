챗GPT 데스크톱 앱은 오픈AI가 맥과 윈도우, 리눅스에 내놓은 공식 앱입니다. 브라우저를 열지 않아도 대화와 업무 모드(Work), 코딩 에이전트 [Codex](/insights/codex-cli-practical-guide)를 한 창에서 쓸 수 있습니다. 2026년 9월 15일 기준 맥과 윈도우는 chatgpt.com/download 한 곳에서 내려받고, 리눅스는 별도 설치 문서를 봅니다.

브라우저로 챗GPT를 쓰는 방법은 이미 익숙하실 겁니다. 주소창에 chatgpt.com을 치고 대화창에 질문을 넣으면 끝이라, 따로 설치할 것도 정할 것도 없습니다.

정작 앱을 깔았을 때 무엇이 더 되는지, 맥과 윈도우에서 어디가 달라지는지는 화면만 봐서는 드러나지 않습니다. 게다가 내려받기 페이지는 접속한 운영체제를 감지해 버튼을 바꾸기 때문에, 맥에서 본 화면을 근거로 윈도우를 안내하면 틀린 말을 하게 됩니다. 2026년 9월 15일에 직접 연 화면과 오픈AI 공식 문서를 기준으로 설치와 로그인, 데스크톱에만 있는 기능, 운영체제별 차이를 정리하겠습니다.

![맥에서 연 챗GPT 공식 내려받기 페이지. 오른쪽 설명 아래에 macOS용 다운로드 버튼 하나만 놓여 있고 윈도우 버튼은 보이지 않는다](/images/insights/chatgpt-desktop-app-guide/01-download-page-macos.png)

위 화면은 2026년 9월 15일에 맥에서 연 chatgpt.com/download입니다. 큰 버튼은 macOS용 다운로드 하나뿐이고, 윈도우용 버튼은 어디에도 보이지 않습니다. 같은 주소를 윈도우에서 열면 버튼이 윈도우용으로 바뀌므로, 윈도우 설치 방법은 이 화면이 아니라 윈도우용 안내 문서에서 확인해야 합니다.

## 브라우저판과 데스크톱 앱이 달라지는 지점

브라우저로 쓰는 방식은 창고를 다녀오는 쪽에 가깝습니다. 필요할 때마다 탭을 열고, 쓸 자료를 끌어다 올리고, 일이 끝나면 탭을 닫습니다. 데스크톱 앱은 같은 도구를 책상 옆 서랍에 넣어 두는 쪽입니다. 서랍은 손만 뻗으면 열리고, 지금 펼쳐 둔 서류를 옮겨 담지 않아도 됩니다.

문서에 적힌 범위로 두 방식을 견주면 다음과 같습니다.

| 항목 | 브라우저(chatgpt.com) | 데스크톱 앱 |
|---|---|---|
| 여는 방법 | 탭을 열고 주소를 입력합니다 | 단축키로 창을 부릅니다 |
| 지금 보는 화면 전달 | 직접 캡처해서 올립니다 | 앱샷으로 맨 앞 창을 그대로 넘깁니다 |
| 컴퓨터 조작 | 안내된 기능이 없습니다 | 컴퓨터 사용으로 앱을 직접 다룹니다 |
| Codex 고르기 | 안내에 나오지 않습니다 | 왼쪽 위 메뉴에서 고릅니다 |
| 업무 모드와 Codex의 음성 대화 | 안내가 없습니다 | 말로 지시하고 진행 상황을 듣습니다 |
| 내 컴퓨터의 폴더 | 파일을 하나씩 올립니다 | 폴더를 열어 그 안에서 일합니다 |
| 내장 브라우저 | 클라우드 브라우저로 제공됩니다 | 채팅 안 내장 브라우저로 제공됩니다 |

실제 작업에 영향이 큰 항목은 가운데 네 줄입니다. 브라우저에서는 화면을 캡처해 올리고 결과를 다시 옮겨 붙이는 단계가 매번 들어가지만, 데스크톱 앱은 그 오가는 단계를 창 하나에서 끝냅니다. Codex를 다루는 공식 문서도 데스크톱 앱을 기준으로만 안내합니다.

## 설치: 운영체제마다 내려받는 경로가 다릅니다

맥과 윈도우는 출발점이 chatgpt.com/download로 같습니다. 그다음부터 경로가 나뉩니다.

**맥**은 경로가 하나입니다. 내려받기 페이지의 macOS용 다운로드 버튼을 누르면 되고, 받는 파일은 dmg입니다. 영문 공식 문서 페이지의 내려받기 버튼에는 Apple Silicon이 괄호로 붙어 있으므로, 인텔 맥을 쓰고 있다면 받기 전에 버튼 문구부터 확인하시는 편이 낫습니다.

**윈도우**는 경로가 두 가지입니다. 하나는 같은 페이지의 웹 설치 관리자이고, 다른 하나는 명령줄입니다. 명령줄로 깔 때는 PowerShell에 아래 한 줄을 넣습니다.

```powershell
winget install --id 9PLM9XGG6VKS -s msstore
```

앱은 Microsoft Store 서명을 달고 배포되지만, 설치하거나 업데이트하려고 스토어를 직접 열 필요는 없습니다. 스토어 페이지에 적힌 요구 사양은 Windows 10 버전 19041.0 이상이고, 윈도우용 샌드박스 문서는 Windows 11을 권합니다. 회사에서 여러 대에 한꺼번에 깔아야 한다면 Microsoft Intune 같은 관리 도구를 쓰고, 마이크로소프트 배포 서비스를 쓸 수 없는 환경이면 기기 아키텍처에 맞는 MSIX 패키지를 내려받아 직접 설치합니다. 제공되는 패키지는 x64와 Arm64 두 종이고, 단독 MSI나 스토어를 거치지 않는 EXE는 제공되지 않습니다.

**리눅스**는 공식 설치 문서가 따로 있습니다(learn.chatgpt.com/docs/linux/linux-app). 배포판별 패키지와 검증된 환경이 어떤 배경에서 정해졌는지는 준이아빠블로그의 [챗GPT 리눅스 데스크톱 앱 프리뷰](/insights/chatgpt-desktop-linux-preview) 글에 정리해 두었습니다.

이름이 비슷한 앱이 하나 더 있습니다. 지금의 데스크톱 앱은 코딩용 Codex 앱과 하나로 합쳐진 결과물이고, 그 전에 쓰던 앱은 ChatGPT Classic으로 이름이 바뀌어 따로 제공됩니다. 내려받기 페이지 맨 아래에 별도 링크가 놓여 있고 맥은 dmg 파일, 윈도우는 웹 설치 관리자로 연결됩니다. 업무 모드나 Codex가 필요하다면 아래쪽 Classic 링크가 아니라 위쪽의 큰 다운로드 버튼을 눌러야 합니다.

## 로그인 방식 두 가지

앱을 처음 열면 로그인 화면이 뜹니다. 오픈AI가 안내하는 방법은 다음 두 가지입니다.

- **ChatGPT 계정으로 로그인**: 이 화면에서 Continue to sign in을 누르면 브라우저 창이 열리고, 로그인을 마치면 브라우저가 자격 증명을 앱으로 돌려줍니다. 이렇게 연결하면 구독 플랜에 딸린 사용량을 그대로 씁니다.
- **API 키로 로그인**: 같은 화면에서 Sign in another way를 고르고 키를 넣습니다. 이때는 구독 사용량 대신 API 표준 요금으로 계산되고, 워크스페이스 접근이 필요한 일부 기능은 제한됩니다.

로그인 정보는 한 번 받으면 캐시로 남습니다. 저장 위치는 `~/.codex/auth.json` 파일이나 운영체제의 자격 증명 저장소이고, 윈도우에서는 `%USERPROFILE%\.codex` 폴더가 같은 파일을 담습니다. 터미널에서 쓰는 Codex CLI와 코드 편집기 확장은 이 캐시를 공유하므로, 한쪽에서 로그아웃하면 다른 쪽도 다시 로그인해야 합니다.

## 데스크톱 앱에서 달라지는 기능 네 가지

앱을 깔았을 때 달라지는 부분을 문서에 적힌 범위로 추리면 네 가지입니다. 앞의 둘은 데스크톱 앱에만 있고, 뒤의 둘은 브라우저에도 있지만 조건이 다릅니다.

**앱샷(Appshots)**은 지금 맨 앞에 떠 있는 창을 그대로 대화에 넣는 기능입니다. 맥에서는 커맨드 키 두 개를, 윈도우에서는 알트 키 두 개를 누르면 됩니다. 넘어가는 것은 창을 찍은 그림과 그 창에서 읽어 낸 글자이고, 스크롤을 내려야 보이는 글자까지 포함될 때가 있습니다. 앱샷은 대화에 붙은 첨부 파일처럼 다뤄지고 세션 파일에 로컬로 저장됩니다.

**컴퓨터 사용(Computer Use)**은 챗GPT가 화면을 보고 버튼을 누르거나 글자를 입력해 앱을 직접 다루는 기능입니다. 지원 지역에서 맥과 윈도우 모두 제공되며, 업무 모드나 Codex에서 플러그인을 설치한 뒤 켭니다. 다만 두 운영체제의 동작이 같지 않습니다. 윈도우에서는 활성 화면에서만 돌아가기 때문에 작업이 진행되는 동안 포인터와 키 입력을 챗GPT가 가져갑니다.

**음성 대화(ChatGPT Voice)**는 GPT-Live를 바탕으로 한 기능입니다. 데스크톱 앱의 대화와 업무 모드, Codex에서 말로 지시하고 진행 상황을 들을 수 있습니다. 새 대화에서는 Start new voice chat, 이미 진행 중인 작업에서는 Start voice chat으로 시작합니다. 진행 중인 작업의 음성은 순차 배포 중이라 항목이 보이지 않으면 말을 글로 받아쓰는 기능을 씁니다. 한 번에 하나의 음성 대화만 진행되며 허용량은 최근 5시간을 기준으로 계산됩니다. 음성 기능의 설계가 어떻게 바뀌었는지는 [GPT-Live 음성 개편](/insights/gpt-live-voice-redesign) 글에서 따로 다뤘습니다.

**단축키**는 브라우저 탭으로 대신하기 어려운 부분입니다. 서랍에 손잡이가 달려 있어야 한 번에 열리듯, 데스크톱 앱도 단축키가 있어야 창을 찾아 헤매지 않습니다. 자주 쓰는 조합은 다음과 같습니다.

- **명령 메뉴**: 맥은 Cmd+Shift+P 또는 Cmd+K, 윈도우는 Ctrl+Shift+P 또는 Ctrl+K
- **빠른 대화**: 맥은 Cmd+Option+N, 윈도우는 Ctrl+Alt+N (ChatGPT 모드에서만)
- **찾은 결과 다음으로 이동**: 맥은 Cmd+G, 윈도우는 Ctrl+G
- **사이드바 접기**: 맥은 Cmd+B, 윈도우는 Ctrl+B
- **받아쓰기 시작**: 맥과 윈도우 모두 Ctrl+Shift+D

지난 대화를 찾는 검색에는 기본 조합이 없어서 설정의 키보드 단축키 항목에서 직접 지정해야 합니다. 나머지 조합도 같은 곳에서 바꿉니다.

![오픈AI 공식 문서의 앱샷 설명 화면. 앱샷을 맥과 윈도우의 데스크톱 앱에서 쓸 수 있고 맥은 커맨드 키 두 개, 윈도우는 알트 키 두 개를 누른다는 안내 상자가 표시되어 있다](/images/insights/chatgpt-desktop-app-guide/02-appshots-hotkey-docs.png)

위 화면은 오픈AI 문서의 앱샷 페이지입니다. 안내 상자에 두 운영체제의 조합이 나란히 적혀 있고, 조합을 따로 정해 쓸 수 있다는 설명도 함께 붙어 있습니다.

실무로 옮기면 순서는 이렇습니다. 광고 관리자 화면에서 숫자가 어긋난 곳을 발견했다면, 그 창을 맨 앞으로 올리고 앱샷을 찍은 뒤 "이 화면에서 전환 수와 전환 가치가 맞지 않는 행을 골라 달라"고 적습니다. 캡처 파일을 저장하고 다시 올리는 두 단계가 빠지고, 화면 밖으로 넘어간 행의 글자까지 함께 전달됩니다. 다만 구글 문서와 지메일, 구글 시트, 구글 슬라이드는 화면에 보이는 그림만 넘어갈 때가 있어서, 표 전체를 다뤄야 하면 파일을 따로 올리는 쪽이 확실합니다.

## 운영체제별로 달라지는 점

같은 앱이라도 맥과 윈도우에서 조건이 다른 항목이 있습니다. 문서로 확인된 것만 모으면 다음과 같습니다.

| 항목 | 맥 | 윈도우 |
|---|---|---|
| 앱샷 조합 | 커맨드 키 두 개 | 알트 키 두 개 |
| 컴퓨터 사용 실행 방식 | 정해 둔 범위 안에서 화면 뒤에서 돌아갑니다 | 활성 화면 위에서만 돌아갑니다 |
| 화면을 잠근 뒤 작업 | 잠금 사용을 켜면 이어집니다 | 제공되지 않습니다 |
| 음성 대화의 화면 참고 | 설정에서 켜면 앱샷으로 넘깁니다 | 공식 안내가 없습니다 |
| 미리 챙길 조건 | 화면 기록과 손쉬운 사용 권한 | 대상 앱을 활성 화면에 띄워 두기 |
| 기업 배포 패키지 | 내려받기 페이지의 설치 파일 | MSIX x64와 Arm64 |
| 에이전트 실행 환경 | 별도 설정이 없습니다 | PowerShell 또는 WSL2 가운데 고릅니다 |

윈도우 쪽 마지막 줄은 개발 작업을 할 때 먼저 정해 둘 항목입니다. 기본값은 PowerShell에서 돌아가는 윈도우 네이티브 방식이고, 설정에서 WSL로 바꾼 뒤 앱을 완전히 종료했다 다시 열면 적용됩니다. 통합 터미널은 이 설정과 별개라서, 에이전트는 WSL에 두고 터미널만 PowerShell로 쓰는 조합도 가능합니다. WSL1은 Codex 0.114까지 지원됐고 0.115부터는 리눅스 샌드박스가 bubblewrap으로 바뀌면서 빠졌습니다.

## 무료 계정으로도 데스크톱 앱을 쓸 수 있나요?

앱 자체는 무료입니다. Microsoft Store 페이지의 가격 표기도 무료로 되어 있습니다. 막히는 곳은 앱이 아니라 앱 안의 기능 쪽이고, 기능마다 걸리는 조건은 이렇습니다.

- **업무 모드**: Plus와 Pro, Business, Enterprise 플랜에서 제공됩니다
- **데스크톱 앱의 음성 대화**: Plus와 Pro, Business, Edu, Enterprise 플랜에서 쓸 수 있습니다
- **클라우드 브라우징**: Free와 Go에서는 막혀 있습니다

업무 모드의 플랜 표기는 출처마다 조금 다릅니다. 내려받기 페이지는 Plus와 Pro, Business, Enterprise로 적고, 요금 문서의 기능 표는 Enterprise와 Education을 한 칸으로 묶어 제공으로 표시합니다.

정리하면 **설치하고 로그인하는 단계에는 막힌 곳이 없지만, 업무 모드와 음성 대화처럼 이 앱을 쓰는 이유가 되는 기능은 유료 플랜 조건에 걸립니다.** 팀에 안내해야 한다면 무료로 전부 된다고 적기 전에 실제 계정에서 어디까지 되는지 확인하는 편이 안전합니다.

Enterprise와 Edu는 두 주 동안 미리 써 보는 기간을 거친 뒤에 음성 대화가 기본으로 켜집니다. 같은 플랜이라도 시점에 따라 화면이 다를 여지가 있습니다.

## 공식 자료에서 확인하지 못한 것

시간이 지나면 조건이 바뀌므로, 공식 페이지에서 확인되지 않은 항목은 이 글에 적지 않았습니다. 뺀 내용은 두 가지입니다.

- **맥의 최소 macOS 버전과 인텔 맥 지원 여부**: 새 앱의 최소 버전을 밝힌 안내를 찾지 못했습니다. 공식 문서 페이지의 내려받기 버튼에 Apple Silicon이 붙어 있는 것만 확인됐고, 인텔 맥에서 어디까지 되는지는 공식 안내가 없습니다. 윈도우는 스토어 페이지에 Windows 10 버전 19041.0 이상으로 적혀 있습니다.
- **윈도우에서 연 내려받기 화면의 실제 모습**: 맥에서 접속하면 macOS 버튼만 나와서, 윈도우 화면은 그대로 담지 못했습니다. 윈도우 설치 경로는 화면 대신 윈도우용 문서와 기업 배포 문서로 확인했습니다.

## 자주 묻는 질문

### 데스크탑과 데스크톱 가운데 어느 쪽이 맞는 표기일까요?

외래어 표기법 기준으로는 데스크톱이 맞습니다. 검색창에는 데스크탑으로 치는 분이 더 많지만, 문서나 공지에 적을 때는 데스크톱으로 씁니다. 두 표기 모두 같은 앱을 가리키므로 검색할 때는 어느 쪽을 쳐도 상관없습니다.

### 브라우저판을 쓰던 대화 기록이 앱에도 그대로 나오나요?

같은 계정으로 로그인하면 그동안 쌓인 대화가 앱에도 그대로 나옵니다. 다만 앱샷처럼 데스크톱에서만 만들어지는 첨부는 성격이 다릅니다. 앱샷은 세션 파일에 로컬로 저장된다고 안내되어 있습니다. 앱샷이 들어 있는 대화를 터미널의 Codex CLI에서 이어 열면 기존 첨부는 기록으로 남지만, 새로 찍는 것은 되지 않습니다.

### 회사에서 쓸 때 관리자가 정해 둘 수 있는 항목이 있나요?

업데이트 정책이 대표적입니다. 앱은 기본적으로 스스로 새 버전을 확인하고 설치하지만, 관리자가 정책으로 이 동작을 끌 수 있습니다. 관리형 설정의 `requirements.toml`에 `[features]` 항목을 만들고 `in_app_updates = false`를 넣으면 됩니다. 이렇게 끄면 새 버전과 보안 수정을 제때 배포하는 책임이 조직으로 넘어가므로, 배포 절차를 먼저 갖춘 뒤에 끄는 편이 맞습니다.
