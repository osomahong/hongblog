클로드 프로젝트(Projects)는 앤트로픽이 2026년 9월 17일 클로드 코드에서 먼저 개편해 공개한 기능입니다. 대화 하나에 해야 할 일을 말하면 클로드가 작업마다 클라우드 세션을 스레드로 띄워 병렬로 진행하고, 결과를 다시 그 대화로 모아 줍니다. 앤트로픽은 이 기능을 "폴더에서 대화로"라는 표현으로 소개했습니다.

클로드를 써 본 분이라면 프로젝트라는 메뉴가 원래 있었다는 것을 알고 있을 것입니다. 자료와 지시문을 한 폴더에 묶어 두고 그 위에서 대화를 여는 기능이었고, 준이아빠블로그에서도 [클로드 업무 활용 사례 4가지와 프로젝트 설정법](/insights/claude-work-use-cases-and-projects)에서 다뤘습니다.

그런데 이번에 같은 이름으로 나온 것은 그 폴더와는 다른 물건입니다. 무엇이 달라졌는지와 노트북을 덮어도 작업이 어디까지 이어지는지, 지금 내 계정에서 열리는지를 먼저 봐야 합니다. 구조를 모르고 스레드를 여러 개 띄우면 요금제 한도에 훨씬 빨리 걸릴 수 있습니다. 공식 블로그와 클로드 코드 문서를 근거로 2026년 9월 18일 기준으로 정리하겠습니다.

![개편된 프로젝트 대화에서 클로드가 지금 시작할 수 있는 작업 세 개를 카드로 제안하는 화면. 각 항목 옆에 Start 버튼이 있고 아래에 스레드 세 개를 한 번에 시작하는 검은 버튼이 있다](/images/insights/claude-code-projects-beta-guide/01-start-new-threads-card.png)

## 클로드 프로젝트 개편 발표 내용 한눈에 보기

| 항목 | 내용 |
|---|---|
| 공개일 | 2026년 9월 17일(미국 기준). 공식 블로그와 X 계정으로 발표 |
| 쓰는 곳 | claude.ai/code 사이드바의 Projects, 데스크톱 앱의 Code 탭, iOS와 안드로이드 앱 |
| 쓸 수 없는 곳 | 터미널 CLI, 아마존 베드록, 구글 클라우드 에이전트 플랫폼, 마이크로소프트 파운드리 |
| 베타 대상 | Pro와 Max 요금제 가운데 클라우드 세션을 써 봤고 웹과 데스크톱에 기존 프로젝트가 없는 계정 |
| 확대 계획 | 한 주 안에 같은 요금제의 더 많은 클로드 코드 사용자로, 그 뒤 클로드 전체와 Team, Enterprise로 |
| 저장소 조건 | github.com 저장소에 Claude GitHub App 설치와 push 권한. 깃허브 엔터프라이즈 서버, 깃랩, 비트버킷은 불가 |
| 실행 위치 | 클라우드만. 내 컴퓨터의 도구와 코드, 내부망에서 돌리는 기능은 곧 나온다고 예고 |
| 한도 | 별도 요금 없이 기존 요금제 한도를 씀. 하루 새 스레드 200개 상한 |

표에서 먼저 볼 것은 쓸 수 없는 곳입니다. 이름에 클로드 코드가 붙어 있어도 터미널에서 `claude`를 치는 방식으로는 열리지 않습니다. 터미널에 있는 `claude project` 명령은 폴더별 로컬 상태를 관리하는 다른 명령입니다.

## 개편된 프로젝트가 대화 하나와 스레드 여러 개로 나뉘는 구조

프로젝트는 대화 하나와 스레드 여러 개로 이루어집니다. 대화는 코디네이터 역할을 맡아 요청을 받고 일을 나누며, 스레드는 그 일을 실제로 하는 쪽입니다. 식당에서 홀 매니저에게 주문하면 주방의 조리사 여럿이 각자 화구를 맡아 동시에 요리하듯, 대화에 일을 말하면 스레드가 각자 저장소 사본과 브랜치를 갖고 동시에 움직입니다.

스레드의 실체는 클로드 코드 클라우드 세션입니다. 쉽게 말하면 **클라우드 세션은 내 컴퓨터가 아니라 앤트로픽이 관리하는 가상 머신에서 돌아가는 클로드 코드 한 벌**입니다. 스레드마다 컨텍스트 창과 브랜치, 저장소 복제본이 따로 있어서 서로 방해하지 않고, 스레드 둘이 같은 코드를 건드리면 일반 PR과 똑같이 병합 충돌로 처리됩니다.

대화에 메시지를 보내면 클로드가 어디로 보낼지 정합니다. 기준은 세 가지입니다.

- **간단한 질문**은 스레드를 만들지 않고 대화에서 바로 답합니다.
- **새 작업**은 새 스레드로 띄우거나, 그 영역에서 이미 일하는 스레드에 붙입니다.
- **서로 무관한 작업 여러 개**를 한 메시지에 넣으면 스레드를 나눠서 띄웁니다.

스레드는 그 안에서 서브에이전트와 루프, 워크플로로 일을 더 잘게 쪼갤 수 있습니다. 코디네이터는 스레드가 보고한 내용만 보고 각 단계를 들여다보지는 않습니다. 대화는 결과 보고를 받아 다음 일을 정하는 쪽입니다.

![프로젝트 대화 화면 뒤로 메모리부터 지시문까지 다섯 층이 겹쳐 있고 오른쪽에 파트너 이메일 스레드가 partners.pdf를 읽는 중이라고 표시된 공식 소개 이미지](/images/insights/claude-code-projects-beta-guide/02-project-conversation-layers.png)

모든 스레드가 함께 읽고 쓰는 것은 프로젝트 메모리입니다. `MEMORY.md` 색인과 개별 파일로 이루어지고, 터미널의 자동 메모리나 저장소의 `CLAUDE.md`와는 별개입니다. 새 스레드마다 전달되는 프로젝트 지시문은 16,000자까지 적을 수 있습니다. 새 프로젝트의 기본 모델은 대화와 스레드 모두 오퍼스이고, 스레드는 effort high, 대화는 effort low로 시작합니다.

결과는 세 곳으로 나옵니다. 스레드가 끝나면 대화에 보고가 올라오고, 파일은 Overview의 Library 탭에, PR은 Pull requests 탭에 모입니다. 스레드는 요청을 받거나 고칠 내용이 분명하면 스스로 PR을 열고, 그 뒤 CI 실패와 리뷰 코멘트에 자동으로 대응합니다. 저장소 없이 문서나 구글 드라이브 폴더만 올려 쓰는 프로젝트도 만들 수 있고, 이때 산출물은 Library 탭으로 나옵니다.

## 노트북을 덮어도 작업이 이어지는 이유와 그 한계

노트북을 덮어도 계속된다는 말은 스레드가 클라우드에서 돌아가기 때문에 성립합니다. 내 컴퓨터는 주문을 넣고 접시를 받는 창구일 뿐이라, 창구가 잠시 닫혀도 주방은 돌아갑니다. 스마트폰 앱에서도 진행 상황을 보고 스레드에 지시를 보낼 수 있습니다.

다만 한계도 세 가지 있습니다.

- **내 컴퓨터의 파일과 도구, 내부망에는 접근하지 못합니다.** 로컬 세션은 프로젝트에 넣을 수 없고, 로컬 실행은 예고만 된 상태입니다.
- **커밋하지 않은 변경은 사라질 수 있습니다.** 스레드의 샌드박스는 턴 사이에 멈췄다가 다시 이어지는데, 재개에 실패하면 스레드가 새 저장소 사본에서 작업을 이어가기 때문입니다.
- **승인 요청에는 스레드 안에서만 답할 수 있습니다.** 대화에 "진행해"라고 써도 스레드로 전달되지 않습니다. 스레드는 모델이 지원하면 auto mode로 돌아가지만, 승인이 필요한 대목에서는 그 스레드를 열어야 합니다.

Overview의 Threads 탭은 스레드 상태를 Ready for review부터 Resolved까지 여섯 가지로 나눠 보여 줍니다. 돌아와서 Waiting on you부터 열면 됩니다. 알림은 데스크톱 앱에서만 오고 브라우저에서는 Overview 버튼에 점 표시만 뜹니다.

## 기존 클로드 프로젝트와의 관계

같은 이름이라 혼동하기 쉬우므로 표로 비교하겠습니다. 공식 문서는 기존 것을 "스레드나 코디네이터 없이 대화와 참고 파일을 묶어 두는 이전 프로젝트 경험"으로 부르고, 개편된 방식으로 바뀔 때까지 그대로 동작한다고 적었습니다.

| 기준 | 기존 프로젝트(chat, Cowork) | 개편된 프로젝트(클로드 코드) |
|---|---|---|
| 무엇을 묶는지 | 대화와 참고 파일, 지시문 | 코디네이터 대화 하나와 작업 스레드들 |
| 일하는 주체 | 내가 대화창에서 직접 진행 | 스레드가 클라우드에서 대신 진행 |
| 동시 작업 | 대화 하나씩 | 스레드 여러 개 병렬 |
| 내 컴퓨터를 꺼도 | 해당 없음(응답 한 번으로 끝남) | 계속 진행 |
| 결과물 | 대화 답변과 아티팩트 | PR, Library의 파일, 대화 보고 |
| 공유 | Team과 Enterprise 요금제에서 공유 가능 | 한 사용자 소유, 공유 불가 |
| 현재 상태 | 그대로 동작 | Pro와 Max 베타 |

앤트로픽은 기존 프로젝트를 새 방식으로 바꿔 나갈 계획이라고 밝혔습니다. 대기자 페이지는 이 기능을 "클로드 코드에서는 새 기능이고, chat과 Cowork에 이미 있는 프로젝트에는 업그레이드"라고 설명합니다. 베타 조건이 "웹과 데스크톱에 기존 프로젝트가 없는 계정"인 것도 한 계정에서 두 방식이 섞이는 상태를 피하려는 뜻으로 보입니다. 기존 지식 파일이 새 구조로 어떻게 옮겨지는지는 이번에 확인한 공식 블로그와 문서에 없습니다.

## 개편된 프로젝트의 베타 조건과 사용량 한도

지금 쓸 수 있는 계정 조건은 좁습니다. Pro나 Max 요금제를 쓰면서 클로드 코드 클라우드 세션을 써 본 적이 있고, 웹과 데스크톱(chat, Cowork)에 기존 프로젝트가 없어야 합니다. Team과 Enterprise는 아직 대상이 아닙니다. 조건에 맞지 않으면 대기자 페이지에 등록하고 기다리는 방법뿐입니다.

요금은 따로 없지만 한도는 기존 요금제 것을 그대로 씁니다. 스레드 하나가 곧 클로드 코드 세션 하나이므로, 스레드를 다섯 개 띄우면 세션 다섯 개를 동시에 돌리는 것과 같습니다. 그래서 한도에 더 빨리 걸리고, 특히 Pro는 그 속도가 빠르다는 경고가 문서에 있습니다. 요금제별 한도가 어떻게 계산되는지는 [클로드 코드 Pro 요금제 팩트체크](/insights/claude-code-pro-plan-fact-check)에 정리해 두었습니다.

- **하루 새 스레드 200개**가 모든 프로젝트를 합친 상한입니다. 동시 스레드 수 제한은 따로 없습니다.
- **한도에 걸리면 스레드가 기다립니다.** Service is busy로 표시됐다가 한도가 풀리면 스스로 이어집니다. 다만 루틴(예약 실행)이 시작한 스레드는 기다리지 않고 에러로 멈춥니다.
- **사용량은 Project settings의 Usage에서** 스레드별, 모델별 토큰으로 확인합니다.

식재료 창고가 하나인데 화구를 늘리면 재료가 그만큼 빨리 바닥나듯, 스레드를 늘릴수록 같은 한도가 빨리 소진됩니다. 대화에서 "스레드는 세 개까지만"이라고 말해 둘 수는 있지만, 그것은 선호일 뿐 강제 상한이 아닙니다.

## 개편된 프로젝트를 지금 시험해 볼 때 따르는 순서

조건에 맞는 계정이라면 작은 작업으로 시작하는 편이 안전합니다. 예를 들어 블로그 저장소 하나를 두고 이렇게 시작할 수 있습니다.

1. github.com 저장소에 Claude GitHub App을 설치하고 push 권한을 확인합니다. `/web-setup` 토큰만으로는 부족합니다.
2. claude.ai/code/projects/browse에서 새 프로젝트를 만들거나, 기존 클라우드 세션 메뉴의 Continue as a project를 누릅니다.
3. 프로젝트 지시문에 검사 명령과 금지 사항을 적습니다. 새 스레드마다 이 지시문이 전달됩니다.
4. 첫 메시지에 서로 무관한 작업 두세 개를 넣습니다. "깨진 링크 점검, 글 세 편 맞춤법 교정, OG 이미지 누락 목록"처럼 파일이 겹치지 않는 일이 좋습니다.
5. Project settings의 Usage에서 스레드별 토큰을 보고, 다음 작업의 크기를 정합니다.

파일이 겹치지 않는 작업을 고르는 것은 병합 충돌 때문입니다. 같은 파일을 스레드 둘이 고치면 PR 단계에서 충돌을 직접 풀어야 하므로, 처음에는 영역이 다른 일을 주는 편이 낫다고 봅니다.

## 자주 묻는 질문

### 터미널의 클로드 코드에서도 프로젝트를 쓸 수 있나요?

쓸 수 없습니다. 개편된 프로젝트는 claude.ai/code와 데스크톱 앱, 모바일 앱에서만 열립니다.

### 기존에 쓰던 클로드 프로젝트는 없어지나요?

그대로 동작합니다. 앤트로픽은 기존 프로젝트가 지금처럼 유지되고, 롤아웃이 chat과 Cowork로 넓어질 때 새 방식으로 업그레이드하겠다고 밝혔습니다. 다만 기존 프로젝트가 있는 계정은 지금 베타 대상에서 빠져 있습니다.

### 요금이 따로 드나요?

별도 요금은 없고 기존 요금제 한도를 씁니다. 다만 스레드마다 세션이 하나씩 붙으므로 병렬로 돌릴수록 한도가 빨리 찹니다. 하루에 새로 만들 수 있는 스레드는 모든 프로젝트를 합쳐 200개입니다.

## 3줄 요약

1. **클로드 프로젝트는 앤트로픽이 2026년 9월 17일 클로드 코드에서 먼저 개편해 공개한 기능이고, 지금은 클라우드 세션을 써 본 Pro와 Max 계정 가운데 기존 프로젝트가 없는 계정에만 열려 있습니다.**
2. **대화 하나가 코디네이터가 되어 작업마다 클라우드 세션을 스레드로 띄우고, 스레드는 저장소 사본과 브랜치를 따로 갖고 병렬로 돌아가다 PR과 파일로 결과를 보고합니다.**
3. **스레드 하나가 세션 하나라 요금제 한도가 빨리 차고 하루 200개 상한이 있으며, 터미널 CLI에서는 쓸 수 없고 내 컴퓨터의 파일에도 아직 접근하지 못합니다.**
