구글 애즈 MCP는 구글이 공식 배포하는 광고 계정 조회용 오픈소스 서버입니다. 클로드나 제미나이 같은 AI 도구에 연결해 두면 광고 관리자 화면을 열지 않고도 계정 성과를 말로 물어보고 리포트 형태로 받습니다.

구글은 이 서버를 2026년 4월 말에 공식 문서와 함께 공개했습니다. 같은 시기에 나온 [Meta MCP](/insights/meta-mcp-ads-automation-guide)와 이름은 비슷하지만 성격이 꽤 다릅니다. 이 글에서는 먼저 무엇을 만들 수 있는지 보여드리고, 이어서 제약과 준비물을 순서대로 다룹니다.

MCP라는 용어가 처음이라면 [비전문가를 위한 MCP 쉽게 이해하기](/insights/mcp-easy-guide-for-non-developers) 글에 개념을 풀어 두었습니다. 짧게 말하면 AI가 외부 서비스에 접근하는 방식을 하나로 통일한 규격입니다.

## 구글 애즈 MCP로 어떤 리포트를 만들 수 있을까요?

연결이 끝나면 광고 관리자에서 열 지표를 고르고 기간을 맞추던 작업이 문장 하나로 바뀝니다. 목적이 다른 리포트 두 가지를 예로 들어 설명하겠습니다.

첫 번째는 계정 전체를 훑는 주간 성과 리포트입니다. 매일 아침 또는 매주 월요일에 쓰는 형태입니다.

![구글 애즈 계정 성과 리포트 화면으로 일별 비용과 전환 추이, 검색 노출 점유율, 비용과 클릭과 CTR과 전환당 비용 지표, 캠페인별 성과 표가 배치된 모습](/images/insights/google-ads-mcp-report-automation-guide/gads-mcp-account-performance-report.png)

비용, 노출, 클릭, CTR, 평균 CPC, 전환, 전환당 비용, 전환값을 비용으로 나눈 값은 모두 구글 애즈 MCP가 직접 돌려주는 항목입니다. 검색 노출 점유율과 예산 부족으로 잃은 노출 비율도 마찬가지입니다. 어느 캠페인이 예산 상한에 걸려 있는지까지 한 화면에서 확인합니다.

두 번째는 목적이 다릅니다. 검색 캠페인에서 돈이 새는 지점을 찾는 진단 리포트입니다.

![구글 애즈 검색어 낭비 진단 화면으로 전환 0건 검색어 비용, 제외 후보 검색어 목록, 품질평가점수 분포, 품질평가점수 구성 요소가 배치된 모습](/images/insights/google-ads-mcp-report-automation-guide/gads-mcp-search-term-waste-report.png)

검색어별 비용과 전환, 검색어를 불러온 키워드, 키워드의 품질평가점수와 세 가지 구성 요소는 모두 조회 대상입니다. 광고 관리자에서 검색어 보고서를 내려받아 엑셀에서 정렬하고 걸러 내던 과정이 질문 한 줄로 줄어듭니다.

두 리포트의 공통점은 조회에서 끝난다는 것입니다. 제외 후보 검색어를 찾아 주기는 하지만 제외어를 등록해 주지는 않습니다. 이유는 다음 항목에 있습니다.

## 구글 애즈 MCP를 쓸 때 알아둬야 할 제한적인 점은 어떤 것이 있을까요?

기대를 먼저 조정하는 편이 낫습니다. 구글 애즈 MCP는 Meta MCP처럼 광고를 만들고 수정하는 도구가 아닙니다.

**첫째, 읽기 전용입니다.** 구글 공식 문서는 이 서버의 모드를 읽기 전용이라고 명시했습니다. 입찰가 변경, 캠페인 일시중지, 애셋 생성은 도구 자체가 존재하지 않습니다.

![구글 애즈 API 공식 문서의 MCP 서버 페이지로 주요 사양 항목에 모드가 읽기 전용이고 전송이 stdio라고 적힌 모습](/images/insights/google-ads-mcp-report-automation-guide/google-ads-mcp-official-doc.png)

**둘째, 도구가 세 개뿐입니다.** 제공되는 도구는 접근 가능한 계정 목록을 가져오는 `list_accessible_customers`, 조회 질의를 실행하는 `search`, 필드 정보를 확인하는 `get_resource_metadata`입니다. Meta MCP가 예산 수정과 유사 타겟 생성 같은 기능별 도구를 수십 개 제공하는 것과 대조됩니다.

**셋째, 조회는 GAQL이라는 질의 언어로 돌아갑니다.** GAQL은 Google Ads Query Language의 줄임말이고, 구글 애즈 데이터를 뽑을 때 쓰는 전용 문법입니다. AI가 이 문법을 대신 써 주지만 필드 이름을 틀리면 엉뚱한 결과가 조용히 나옵니다. 숫자가 이상하면 어떤 질의를 썼는지 되물어 확인하는 습관이 필요합니다.

**넷째, 비용은 마이크로 단위로 옵니다.** `metrics.cost_micros` 값은 실제 금액에 1,000,000을 곱한 정수입니다. AI가 나눗셈을 빠뜨리면 비용이 백만 배로 표시됩니다. [구글 Ads API 데이터를 정리한 글](/insights/google-ads-api-data-for-non-developers)에서도 같은 함정을 다룬 적이 있습니다.

**다섯째, 구글이 서버를 운영해 주지 않습니다.** 구글은 코드를 공개할 뿐이고 접속할 주소를 제공하지 않습니다. 내 컴퓨터에서 실행하거나 클라우드에 직접 올려야 합니다.

**여섯째, 손대지 못하는 영역이 있습니다.** 스마트 자동 입찰의 내부 판단 근거, 퍼포먼스 맥스가 어떤 애셋을 골랐는지, 경매 상세 내역은 조회 대상이 아닙니다. 소재의 완성도나 랜딩 페이지 경험도 평가하지 못합니다.

## 구글 애즈 MCP는 Meta MCP와 무엇이 다를까요?

같은 시기에 나온 두 서버의 차이를 표로 정리하면 다음과 같습니다. 2026년 8월 기준입니다.

| 구분 | Meta MCP | 구글 애즈 MCP |
|---|---|---|
| 운영 주체 | 메타가 직접 서버 운영 | 구글은 코드만 공개, 실행은 직접 |
| 접속 주소 | `https://mcp.facebook.com/ads` | 없음 |
| 도구 수 | 수십 개 | 3개 |
| 쓰기 기능 | 있음, 생성물은 일시중지 상태 | 없음 |
| 인증 | 브라우저에서 비즈니스 계정 로그인 | 개발자 토큰과 구글 클라우드 프로젝트와 OAuth |
| 관리자 계정 | 필요 없음 | MCC 필수 |
| 준비 시간 | 5분에서 10분 | 승인 대기를 빼도 한두 시간 |
| 클로드 웹 | 커넥터로 바로 연결 | 로컬 실행 클라이언트 필요 |

마지막 항목은 설명이 필요합니다. 구글 공식 문서에 적힌 전송 방식은 stdio입니다. 내 컴퓨터에서 프로그램을 띄우고 그 프로그램과 직접 주고받는 방식이라, 웹 브라우저의 claude.ai에서는 주소를 붙여 넣을 대상이 없습니다. 클로드 데스크톱이나 클로드 코드, 제미나이 CLI, 커서처럼 로컬에서 프로그램을 실행할 수 있는 도구가 필요합니다.

굳이 웹에서 쓰고 싶다면 구글 클라우드 런에 직접 배포해 주소를 만든 뒤 커스텀 커넥터로 등록하는 방법이 있습니다. 공식 문서에 배포 절차가 나와 있지만, 도커 이미지를 만들고 환경 변수를 넣는 과정이라 난이도가 올라갑니다.

## 구글 애즈 MCP를 쓰려면 왜 MCC(관리자 계정)가 필요할까요?

MCC는 여러 광고 계정을 하나로 묶어 관리하는 상위 계정입니다. 대행사나 여러 브랜드를 운영하는 곳에서 쓰는 구조인데, 구글 애즈 MCP에서는 계정이 하나뿐이어도 MCC가 필요합니다. 이유는 두 가지입니다.

**개발자 토큰이 관리자 계정에서만 발급됩니다.** 개발자 토큰은 22자리 문자열이고 Google Ads API를 부를 때 신원을 증명하는 열쇠입니다. 구글 공식 문서는 이 토큰을 보려면 관리자 계정으로 로그인해야 하며 테스트용 관리자 계정으로는 안 된다고 적어 두었습니다. 일반 광고 계정의 설정 화면에는 발급 항목 자체가 나오지 않습니다.

**관리자 계정을 거쳐 접근할 때 로그인 고객 ID를 지정해야 합니다.** MCC 아래의 하위 계정을 조회하려면 `GOOGLE_ADS_LOGIN_CUSTOMER_ID` 값에 MCC의 계정 ID를 넣습니다. 하이픈을 뺀 숫자만 넣으면 되고, 실제로 조회할 하위 계정 ID는 질문할 때마다 따로 지정합니다.

MCC 자체는 무료이고 몇 분이면 만듭니다. 문제는 그다음 단계입니다.

## 개발자 토큰은 어떤 등급을 받아야 할까요?

개발자 토큰에는 접근 등급이 있고, 등급에 따라 실제 광고가 나가는 계정을 조회할 수 있는지가 달라집니다. 2026년 8월 기준 구글 공식 문서의 내용은 다음과 같습니다.

| 등급 | 운영 계정 조회 | 하루 작업 한도 | 심사 |
|---|---|---|---|
| 테스트 계정 | 불가 | 15,000건 | 가입 즉시 |
| Explorer | 가능 | 2,880건 | 자동 부여 |
| Basic | 가능 | 15,000건 | 영업일 5일 |
| Standard | 가능 | 무제한 | 영업일 10일 |

구글 애즈 MCP를 돌리려면 최소한 Explorer 등급이 필요합니다. 신규 토큰은 대개 Explorer로 자동 부여되지만, 자동 심사가 되지 않으면 테스트 계정 등급으로 떨어집니다. 이 경우 실제 계정 데이터가 조회되지 않고 오류가 납니다.

하루 2,880건이라는 한도는 혼자 리포트를 뽑는 용도라면 넉넉합니다. 다만 여러 계정을 매일 훑는 대행사 규모에서는 금방 닿습니다. 그때는 Basic 등급을 신청하는데, 2026년 2월 무렵부터 구글의 토큰 심사가 밀려 있다는 보도가 나온 적이 있어 여유를 두고 신청하는 편이 안전합니다.

## 구글 애즈 MCP는 어떻게 연결할까요?

준비물이 세 갈래라 순서를 지키는 것이 중요합니다. 앞 단계가 끝나야 다음 단계가 진행됩니다.

**1. MCC를 만들고 광고 계정을 연결합니다.** 이미 MCC가 있으면 넘어갑니다.

**2. 개발자 토큰을 신청합니다.** MCC에서 도구 및 설정으로 들어가 API 센터를 엽니다. 신청서를 내고 등급이 Explorer 이상인지 확인합니다.

**3. 구글 클라우드 프로젝트를 만들고 Google Ads API를 사용 설정합니다.** 프로젝트 ID를 메모해 둡니다.

**4. OAuth 2.0 클라이언트를 만듭니다.** 사용자 인증 정보 화면에서 데스크톱 앱 유형으로 만들고 클라이언트 ID와 시크릿을 받습니다. OAuth 개념이 낯설면 [OAuth 2.0을 정리한 글](/insights/what-is-oauth2-beginner-guide)이 도움이 됩니다.

**5. 서버를 설치합니다.** 공식 저장소는 아래 주소입니다.

![깃허브의 googleads 조직 아래 google-ads-mcp 저장소 화면으로 파일 목록과 아파치 2.0 라이선스, 파이썬 비중이 표시된 모습](/images/insights/google-ads-mcp-report-automation-guide/google-ads-mcp-github-repo.png)

파이썬으로 만들어졌고 아파치 2.0 라이선스로 공개되어 있습니다. 설치 명령은 다음과 같습니다.

```bash
pipx run --spec git+https://github.com/googleads/google-ads-mcp.git google-ads-mcp
```

**6. MCP 클라이언트 설정 파일에 등록합니다.** 클로드 코드를 예로 들면 설정 파일에 서버와 환경 변수를 함께 적습니다.

```json
{
  "mcpServers": {
    "google-ads-mcp": {
      "command": "pipx",
```

## 리포트는 어떻게 물어봐야 할까요?

도구가 세 개뿐이라 질문을 어떻게 던지느냐가 결과 품질을 좌우합니다. 순서대로 정리했습니다.

### 1단계: 계정 상태 확인

가장 먼저 던지는 질문입니다.

> 지난 7일 동안 집행된 캠페인을 비용 순으로 정리하고, 캠페인별 노출, 클릭, CTR, 평균 CPC, 전환, 전환당 비용을 표로 보여 줘. 비용은 원 단위로 환산해 줘.

기간, 지표, 정렬 기준, 출력 형태에 더해 단위 환산까지 함께 적는 것이 요령입니다. 마이크로 단위 문제를 처음부터 막습니다.

### 2단계: 예산에 걸린 캠페인 찾기

검색 캠페인에서 놓치기 쉬운 지점입니다.

> 검색 캠페인의 검색 노출 점유율과 예산 부족으로 잃은 노출 점유율을 뽑아 줘. 예산 손실이 10%를 넘는 캠페인을 따로 표시해 줘.

### 3단계: 검색어 낭비 진단

앞의 두 번째 리포트에 해당하는 질문입니다.

> 지난 30일 검색어 중에서 클릭이 50회 이상인데 전환이 0건인 항목을 비용 순으로 20개 뽑아 줘. 각 검색어를 불러온 키워드도 같이 보여 줘.

결과를 받아 제외어로 등록하는 작업은 사람이 광고 관리자에서 합니다. 판단 근거를 AI가 모아 주고 실행은 사람이 하는 분업입니다.

### 4단계: 질문 묶음 저장하기

매번 같은 문장을 다시 쓸 필요는 없습니다. 클로드를 쓴다면 자주 쓰는 질문을 스킬이나 프로젝트로 저장해 둡니다. 팀에서 쓰는 지표 정의와 리포트 양식을 함께 적어 두면 결과 형식이 매번 같아집니다.

한 가지 더 붙이면 좋은 조합이 있습니다. 구글은 [구글 애널리틱스용 MCP 서버](https://github.com/googleanalytics/google-analytics-mcp)도 공식 배포하고 있고, 이쪽 역시 읽기 전용입니다. 두 서버를 함께 연결해 두면 광고 성과와 사이트 안에서의 행동을 한 대화에서 이어 물어보게 됩니다.
