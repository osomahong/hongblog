## 마크다운은 이미 우리 옆에 있었습니다

노션(Notion)에서 `/`를 눌러 블록을 추가하거나, `#` + 스페이스로 제목을 만드는 것. 슬랙(Slack)에서 `*굵게*`가 **굵게** 표시되고, `>`로 인용하는 것. 옵시디언(Obsidian)에서 `~~취소선~~`이 ~~취소선~~으로 바뀌는 것: 이 모든 게 마크다운입니다. 개발자들이나 쓰는 어려운 언어가 아니라, 이미 매일 쓰고 있는 서식 방법입니다.

그런데 2026년 현재, 마크다운의 위상이 완전히 달라졌습니다.

예전의 마크다운은 문서를 **예쁘게 보이게** 하는 도구였습니다. README 파일을 꾸미고, 블로그 글을 쓰는 정도였습니다. 지금의 마크다운은 **AI를 움직이는 지시서**입니다. `.md` 파일 하나에 적어둔 규칙이 AI 에이전트의 행동 방식을 결정하고, 스킬 하나의 워크플로우 전체를 정의합니다.

문서 포맷에서 **AI의 운영 체제**로 마크다운의 역할이 근본적으로 바뀐 것입니다.

## .md 파일 하나가 AI 에이전트를 지배합니다

AI 에이전트란 사람의 개입 없이 스스로 판단하고 작업을 수행하는 AI 시스템입니다. [Claude Code](/class/claude-code-for-everyone/what-is-claude-code), Cursor, GitHub Copilot 같은 도구가 대표적입니다. 이 에이전트들이 "어떻게 행동할지"를 결정하는 핵심 파일이 바로 `.md` 파일입니다.

### CLAUDE.md: 에이전트의 헌법

Claude Code에는 `CLAUDE.md`라는 파일이 있습니다. 이 파일에 적힌 내용을 AI가 **자동으로 읽고 따릅니다.** 예를 들어 이렇게 적어두면:

```markdown
## 코드 스타일
- TypeScript 사용
- 함수명은 camelCase
- 모든 함수에 JSDoc 주석 필수

## 금지 사항
- any 타입 사용 금지
- console.log 대신 logger 사용
```

AI는 코드를 생성할 때마다 이 규칙을 따릅니다. 매번 "TypeScript로 써줘, camelCase로 해줘"라고 반복할 필요가 없습니다. `.md` 파일 하나가 수백 번의 지시를 대신하는 것입니다.

### SKILL.md: AI의 업무 매뉴얼

더 놀라운 건 **[스킬(Skill)](/class/claude-in-practice/what-are-claude-skills)** 시스템입니다. `SKILL.md` 파일에 워크플로우를 정의해두면, AI가 복잡한 다단계 작업을 자동으로 수행합니다.

예를 들어, 마케팅팀에서 주간 뉴스레터를 자동으로 만드는 스킬을 정의한다고 가정해보겠습니다.

```markdown
## 워크플로우 (5단계)

### 1단계: 이번 주 트렌드 수집
- 업계 뉴스 사이트 5곳에서 주요 기사 수집
- 자사 블로그 신규 게시물 목록 확인

### 2단계: 콘텐츠 선별
- 타겟 독자(마케터)에게 가장 유용한 기사 5개 선정
- 각 기사를 3줄로 요약

### 3단계: 뉴스레터 본문 작성
- 인사말 + 이번 주 핵심 트렌드 정리
- 각 기사 요약 + 원문 링크 포함

### 4단계: HTML 이메일 템플릿 생성

### 5단계: 초안을 담당자에게 검토 요청
```

이 `.md` 파일 하나로 AI가 **정보 수집 → 선별 → 요약 → 이메일 작성**까지 일괄 처리합니다. 사람이 하면 반나절 걸릴 작업을 AI 에이전트가 짧은 시간 안에 완료합니다.

### 비개발자에게 이것이 의미하는 바

여기서 핵심은, 이 `.md` 파일을 작성하는 데 **코딩 지식이 필요 없다**는 점입니다. `#`으로 제목 쓰고, `-`로 목록 만들고, `**`로 강조하는 게 전부입니다. 즉, 마크다운만 알면 누구나 AI 에이전트에게 복잡한 업무를 맡길 수 있습니다.

| 역할 | .md 파일 활용 예시 |
|------|-------------------|
| 마케터 | 광고 소재 생성 스킬: 타겟, 채널, 톤 규칙을 정의 |
| 기획자 | 회의록 정리 스킬: 요약 형식, 액션 아이템 추출 규칙 정의 |
| 콘텐츠 크리에이터 | 뉴스레터 제작 스킬: 트렌드 수집→요약→이메일 템플릿 자동 생성 |
| 데이터 분석가 | 리포트 생성 스킬: 데이터 소스, 시각화 형식, 해석 가이드 정의 |

**마크다운을 아는 것 = AI에게 나만의 업무 매뉴얼을 만들어줄 수 있는 것**입니다.

## 검색 엔진도 마크다운을 읽고 있습니다

마크다운이 중요한 이유는 AI뿐만이 아닙니다. 우리가 매일 사용하는 **검색 엔진(Google, Naver)**이 웹페이지를 평가하는 방식과 마크다운은 직접적으로 연결되어 있습니다.

### 마크다운 = 시맨틱 HTML의 가장 쉬운 작성법

검색 엔진은 웹페이지의 **HTML 태그**를 읽고 콘텐츠의 구조를 파악합니다. 여기서 핵심이 되는 것이 **시맨틱(Semantic) HTML**: 의미를 가진 태그입니다.

| 마크다운 | 변환되는 HTML | 검색 엔진이 이해하는 의미 |
|----------|-------------|----------------------|
| `# 제목` | `<h1>제목</h1>` | "이 페이지의 핵심 주제" |
| `## 소제목` | `<h2>소제목</h2>` | "주제 아래의 세부 항목" |
| `**강조**` | `<strong>강조</strong>` | "이 단어가 특히 중요함" |
| `- 항목` | `<ul><li>항목</li></ul>` | "나열된 정보 목록" |
| `[텍스트](URL)` | `<a href="URL">텍스트</a>` | "관련 페이지와의 연결" |
| `![설명](이미지)` | `<img alt="설명" src="이미지">` | "이미지의 내용 설명(alt 텍스트)" |

마크다운으로 `## 소제목`을 쓰면, 이것이 자동으로 `<h2>` 태그로 변환됩니다. 검색 엔진은 `<h2>` 태그를 보고 "이 섹션의 주제가 이것이구나"라고 판단합니다. 즉, **마크다운을 잘 쓰는 것 자체가 SEO 최적화**입니다.

### 헤딩 계층 구조가 SEO의 핵심입니다

Google의 검색 알고리즘은 **헤딩 태그의 계층 구조**를 중요하게 봅니다. `H1`은 페이지당 하나, 그 아래 `H2`, `H3`이 논리적으로 이어져야 합니다.

마크다운은 이 계층 구조를 자연스럽게 만들어줍니다.

```markdown
# 페이지 제목 (H1: 페이지당 1개)

## 첫 번째 주제 (H2)
### 세부 내용 (H3)
### 세부 내용 (H3)

## 두 번째 주제 (H2)
### 세부 내용 (H3)
```

`#`의 개수만 맞추면 검색 엔진이 좋아하는 완벽한 헤딩 구조가 자동으로 완성됩니다. HTML을 직접 쓰면 `<h2>`를 닫지 않거나 `<h1>` 다음에 `<h4>`가 오는 실수를 하기 쉽지만, 마크다운에서는 이런 실수가 구조적으로 일어나기 어렵습니다.

### 이미지 alt 텍스트도 자동으로 챙겨집니다

SEO에서 자주 빠뜨리는 것 중 하나가 **이미지 alt 텍스트**입니다. alt 텍스트는 검색 엔진이 이미지의 내용을 이해하는 유일한 단서이며, 이미지 검색 노출에 직접 영향을 미칩니다.

마크다운에서 이미지를 삽입하는 문법은 이렇습니다.

```markdown
![GA4 대시보드 전환율 그래프](이미지_URL)
```

`![]` 안에 쓰는 텍스트가 곧 `<img alt="...">` 의 alt 속성이 됩니다. 마크다운 문법 자체가 alt 텍스트 작성을 **강제**하기 때문에, 빠뜨릴 일이 없습니다.

### 깨끗한 HTML, 높은 페이지 품질 점수

워드프로세서나 WYSIWYG 에디터로 작성한 글을 웹에 붙여넣으면, 불필요한 `<span style="...">`, `<div class="...">` 같은 인라인 스타일이 잔뜩 붙습니다. 이런 태그는 검색 엔진이 콘텐츠를 파싱하는 데 방해가 됩니다.

마크다운은 **순수한 시맨틱 태그**만 생성합니다. 스타일 관련 코드가 전혀 섞이지 않기 때문에, 검색 엔진은 콘텐츠 자체에만 집중할 수 있습니다. 결과적으로 페이지의 기술적 품질 점수가 높아지고, 검색 순위에 긍정적인 영향을 미칩니다.

## AI 프롬프트에서도 마크다운이 결과를 바꿉니다

에이전트 설정 파일뿐 아니라, 일상적인 AI 대화에서도 마크다운은 응답 품질을 확연히 끌어올립니다. AI 모델은 학습 데이터의 상당 부분이 마크다운 형식이기 때문에, 마크다운 구조를 자연스럽게 이해합니다.

### 같은 요청, 다른 결과

**일반 텍스트로 요청한 경우:**

```
우리 회사 SNS 마케팅 전략을 짜줘. 타겟은 20대 여성이고 예산은 월 500만원이야. 인스타그램이랑 틱톡 위주로 해줘. KPI도 넣어줘.
```

AI는 이 요청을 하나의 긴 문단으로 인식합니다. 조건을 빠뜨리거나, 원하지 않는 형식으로 응답할 가능성이 높습니다.

**마크다운으로 요청한 경우:**

```markdown
## 요청 사항
SNS 마케팅 전략 수립

## 조건
- **타겟:** 20대 여성
- **월 예산:** 500만원
- **채널:** 인스타그램, 틱톡

## 출력 형식
1. 채널별 예산 배분 (표로 정리)
2. 월간 콘텐츠 캘린더
3. **KPI 목표** (CTR, 전환율, 팔로워 증가율)
```

차이가 보이시나요? `##`으로 섹션을 나누니 AI가 **요청, 조건, 출력 형식을 별도로 인식**합니다. `-`와 `**`로 핵심 조건을 강조하니 **빠뜨리는 정보가 없습니다.** 번호 목록으로 출력 순서를 지정하니 **원하는 형태로 응답**이 나옵니다.

마크다운 프롬프트를 사용하면 AI가 다단계 지시사항을 더 정확하게 따르고, 복잡한 요구사항을 빠짐없이 처리한다는 것이 이미 검증되어 있습니다.

### 토큰도 절약됩니다

AI 서비스는 **토큰** 단위로 비용을 계산합니다. HTML은 `<h2>제목</h2>`처럼 태그가 길지만, 마크다운은 `## 제목` 두 글자면 끝입니다. 문서가 길어질수록 이 차이가 누적되어 비용과 처리 속도 모두에 영향을 미칩니다.

## 5분이면 충분한 마크다운 핵심 문법

마크다운은 아래 6가지면 AI 활용에 충분합니다.

| 문법 | 쓰는 법 | 결과 |
|------|---------|------|
| 제목 | `## 제목` | 큰 제목 (`#` 개수로 크기 조절) |
| 굵게 | `**중요**` | **중요** |
| 목록 | `- 항목` | 글머리 기호 목록 |
| 번호 목록 | `1. 항목` | 순서 있는 목록 |
| 코드 | `` `코드` `` | 인라인 코드 |
| 표 | `\| A \| B \|` | 표 형태 |

이 6가지를 조합하면 AI 프롬프트, 업무 문서, 에이전트 설정 파일까지 모두 작성할 수 있습니다. 복잡한 건 하나도 없습니다.

## 오늘부터 시작하는 법

마크다운을 배우는 가장 좋은 방법은 **AI에게 질문할 때 바로 써보는 것**입니다.

1. 다음 AI 대화에서 `##`으로 제목을 나눠보세요
2. `-`로 조건을 목록으로 정리해보세요
3. `**`로 절대 빠뜨리면 안 되는 조건을 강조해보세요

이것만으로 응답의 질이 달라지는 걸 바로 체감할 수 있습니다. 그리고 거기서 한 발 더 나가면, `.md` 파일로 AI 에이전트의 행동 규칙을 정의하고, 나만의 자동화 스킬을 만드는 단계에 도달하게 됩니다.

마크다운은 더 이상 개발자의 도구가 아닙니다. **AI 시대에 AI와 가장 효과적으로 소통하는 방법**입니다.

---

**3줄 요약:**
- 마크다운은 이제 문서 서식이 아니라 AI 에이전트의 행동 규칙과 업무 스킬을 정의하는 핵심 도구입니다.
- `.md` 파일 하나로 AI에게 복잡한 다단계 작업을 자동화시킬 수 있으며, 코딩 지식은 필요 없습니다.
- 오늘 바로 AI 대화에서 `##`, `-`, `**` 세 가지만 써보면 응답 품질의 차이를 체감할 수 있습니다.
