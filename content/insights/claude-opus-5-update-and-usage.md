## Claude Opus 5는 2026년 7월 24일 공개된 앤트로픽의 새 Opus 모델입니다

[앤트로픽](/class/claude-fundamentals/what-is-anthropic)이 2026년 7월 24일 Claude Opus 5를 공개했습니다. API 모델 이름은 `claude-opus-5`이고, 클로드 앱, [클로드 코드](/class/claude-code-for-everyone/what-is-claude-code), Claude Cowork, Claude API에서 같은 날부터 쓸 수 있습니다.

이 글은 Opus 5를 실제로 쓰기까지 필요한 절차를 정리한 것입니다. 클로드 코드 업데이트 명령어, 모델 선택 방법, 모델 목록에 Opus 5가 보이지 않을 때 확인할 항목, effort 레벨 조절, 요금 조건 순으로 다룹니다. 이 글의 내용은 2026년 7월 기준입니다.

아래 이미지는 앤트로픽 공식 발표 페이지에 실린 모델별 벤치마크 비교표입니다.

![Opus 5, Fable 5, Opus 4.8, GPT-5.6 Sol의 벤치마크 점수 비교표. 에이전틱 터미널 코딩, 지식 업무, 신규 문제 해결, 컴퓨터 사용 등 항목별 점수가 정리되어 있다](/images/insights/claude-opus-5-update-and-usage/opus-5-benchmark.webp)

공식 발표 기준으로 Opus 5는 에이전틱 터미널 코딩(Frontier-Bench v0.1)에서 43.3%를 기록해 Opus 4.8의 21.1%보다 높은 점수를 받았습니다. 컴퓨터 사용(OSWorld 2.0)과 업무 자동화(AutomationBench) 항목에서도 이전 Opus 모델보다 높은 값이 표시되어 있습니다.

## 플랜과 제품별 Opus 5 이용 조건

Opus 5를 쓸 수 있는지, 기본 모델로 잡히는지는 가입한 플랜에 따라 다릅니다.

| 이용 형태 | Opus 5 사용 | 기본 모델 |
|---|---|---|
| Claude Max, Team Premium | 가능 | Opus 5 |
| Claude Pro, Team Standard | 가능 | Sonnet 5 |
| Claude API(종량제) | 가능 | Opus 5 |
| Amazon Bedrock, Google Cloud | 가능 | Opus 5 |
| Microsoft Foundry | 가능 | Opus 4.6(별칭 기준) |

Pro 플랜에서도 Opus 5 선택이 가능합니다. 다만 세션을 시작할 때 자동으로 잡히는 모델이 Sonnet 5이기 때문에, 모델을 직접 바꾸지 않으면 Opus 5로 대화가 시작되지 않습니다. Max 플랜은 반대로 별도 조작 없이 Opus 5가 기본값입니다.

Microsoft Foundry처럼 `opus` 별칭이 아직 이전 버전을 가리키는 환경도 있습니다. 이 경우 별칭 대신 `claude-opus-5`라는 전체 이름을 직접 지정해야 합니다.

## 클로드 코드에서 Opus 5로 모델을 변경하는 방법

클로드 코드라는 도구 이름이 생소하실 수 있습니다. 터미널에서 자연어로 코딩 작업을 시키는 앤트로픽 공식 도구이고, 아래 명령어는 모두 그 터미널 안에서 입력합니다.

### Step 1. 현재 버전 확인

터미널을 열고 아래 명령어를 실행합니다.

```bash
claude --version
```

버전 번호가 출력됩니다. **Opus 5는 클로드 코드 v2.1.219 이상에서만 나타납니다.** 그보다 낮은 버전이면 다음 단계로 넘어갑니다.

### Step 2. 업데이트 실행

```bash
claude update
```

네이티브 설치 방식으로 설치했다면 백그라운드에서 자동 업데이트가 진행되지만, 즉시 최신 버전으로 올리고 싶을 때는 이 명령어를 직접 실행하면 됩니다. Homebrew로 설치한 경우에는 `brew upgrade claude-code`를 씁니다.

업데이트가 끝나면 `claude --version`을 다시 실행해 v2.1.219 이상인지 확인합니다.

### Step 3. 모델 전환

클로드 코드 세션 안에서 다음 명령어를 입력합니다.

```
/model opus
```

Anthropic API 기준으로 `opus` 별칭은 최신 Opus 모델인 Opus 5로 연결됩니다. 버전을 명시하고 싶다면 전체 이름을 씁니다.

```
/model claude-opus-5
```

인자 없이 `/model`만 입력하면 선택 화면이 열립니다. v2.1.153 이후로는 `/model`로 고른 모델이 사용자 설정 파일에 기록되어 다음 세션에도 그대로 적용됩니다.

## Opus 5가 모델 목록에 보이지 않을 때 확인해야 할 4가지

모델 선택 화면에 Opus 5 항목이 없다면 아래 순서로 확인합니다.

- **버전**: v2.1.219 미만이면 항목 자체가 표시되지 않습니다. `claude update`를 먼저 실행합니다.
- **플랜**: Pro나 Team Standard는 기본 모델이 Sonnet 5입니다. 목록에는 있지만 자동으로 선택되지는 않습니다.
- **조직 설정**: Enterprise 플랜에서는 관리자가 특정 모델을 비활성화하기도 합니다. 이 경우 목록에서 제외되거나 비활성 상태로 표시됩니다.
- **별칭 해석**: Microsoft Foundry 같은 일부 환경에서는 `opus` 별칭이 이전 버전을 가리킵니다. `claude-opus-5`를 직접 입력합니다.

> Opus 5가 클로드 코드 모델 목록에 나타나지 않는 가장 흔한 원인은 클로드 코드 버전이 v2.1.219보다 낮은 것입니다. `claude update`로 업데이트한 뒤 다시 `/model`을 실행하면 목록에 표시됩니다.

## 클로드 앱과 데스크톱 앱에서 Opus 5 선택하기

클로드 앱(claude.ai)과 데스크톱 앱에서는 새 대화를 시작할 때 입력창 근처의 모델 선택 메뉴에서 Opus 5를 고르면 됩니다. Max 플랜은 기본 모델이 Opus 5라 별도 조작이 필요 없고, Pro 플랜은 선택 메뉴에서 직접 바꿔야 합니다.

데스크톱 앱은 대체로 자동 업데이트되지만, 모델 선택 메뉴에 Opus 5가 없다면 앱을 완전히 종료했다가 다시 실행하거나 최신 버전을 내려받아 설치하면 반영됩니다.

## effort 레벨이란?: 얼마나 깊게 생각하게 할지 조절하는 설정

effort라는 설정은 모델 이름보다 상대적으로 낯설 수 있습니다. 모델이 답을 내기 전에 얼마나 깊게 추론할지를 조절하는 값이고, 깊게 생각할수록 결과 품질은 올라가지만 토큰 사용량과 대기 시간도 함께 늘어납니다. 클로드 코드에서 실제로 지정하는 값을 아래 표에 정리했습니다.

Opus 5는 다섯 단계를 모두 지원합니다.

| 레벨 | 쓰는 상황 |
|---|---|
| `low` | 범위가 좁고 빠른 응답이 중요한 작업 |
| `medium` | 비용을 줄이면서 어느 정도 품질을 유지할 때 |
| `high` | 기본값. 대부분의 작업에 적합 |
| `xhigh` | 토큰을 더 쓰더라도 깊은 추론이 필요할 때 |
| `max` | 비용보다 정확도가 중요한 어려운 작업 |

클로드 코드 세션에서 다음과 같이 조절합니다.

```
/effort           # 현재 레벨 확인 및 선택 화면 열기
/effort medium    # 특정 레벨로 변경
```

Opus 5의 기본 effort는 `high`입니다. Fable 5나 Opus 4.8은 처음 실행할 때 그 모델의 기본 effort를 강제로 적용하지만, Opus 5는 이전에 설정해 둔 레벨이 그대로 넘어옵니다.

아래는 앤트로픽이 공개한 effort 레벨별 성능과 비용 관계 차트입니다.

![Frontier-Bench v0.1 기준 effort 레벨별 에이전틱 코딩 점수와 시도당 비용을 표시한 선 그래프. Opus 5, Fable 5, Opus 4.8, GPT-5.6 Sol 네 모델의 곡선이 비교되어 있고 Opus 5가 가장 위쪽에 위치한다](/images/insights/claude-opus-5-update-and-usage/opus-5-frontier-bench.webp)

가로축이 시도당 비용, 세로축이 점수입니다. effort를 올릴수록 점수와 비용이 함께 오르는 형태이고, 오른쪽 끝으로 갈수록 점수 상승 폭이 완만해집니다. 모든 작업에 `max`를 쓸 이유는 없고, `high`에서 시작한 뒤 결과가 아쉬울 때만 한 단계 올리는 편이 무난합니다.

## Fast 모드와 요금 조건

Fast 모드는 같은 모델을 더 빠른 속도로 실행하는 옵션입니다. 클로드 코드에서는 `/fast`로 켜고 끄며, 2026년 7월 기준 Opus 5와 Opus 4.8에서만 동작합니다. Opus 4.7은 Fast 모드 지원이 제거되었습니다.

API 기준 요금은 다음과 같습니다.

- **표준**: 입력 100만 토큰당 5달러, 출력 100만 토큰당 25달러. Opus 4.8과 같은 금액입니다.
- **Fast 모드**: 입력 100만 토큰당 10달러, 출력 100만 토큰당 50달러. 출력 속도가 최대 2.5배까지 빨라지는 대신 요금이 2배입니다.

> Claude Opus 5의 API 요금은 입력 100만 토큰당 5달러, 출력 100만 토큰당 25달러로 Opus 4.8과 동일합니다. Fast 모드를 사용 설정하면 요금이 2배가 됩니다.

구독 플랜(Pro, Max)에서는 토큰 단위 과금 대신 플랜별 사용량 한도가 적용됩니다. 또 하나 확인할 점은 Opus 5의 사용량 한도가 Opus 4.x 계열과 별도로 관리된다는 것입니다. 기존 Opus 모델을 쓰다 남은 여유분이 Opus 5로 이어지지는 않습니다.

## API로 직접 호출할 때 달라지는 2가지

코드에서 API를 직접 호출한다면 Opus 4.8에서 넘어올 때 확인할 항목이 두 가지 있습니다.

**첫째, 추론(thinking)이 기본으로 사용 설정돼 있습니다.** Opus 4.8과 Opus 4.7에서는 `thinking` 값을 넘기지 않으면 추론 없이 동작했지만, Opus 5는 값을 생략하면 적응형 추론이 적용됩니다. `max_tokens`는 추론과 응답을 합친 상한이므로, 기존에 응답 길이만 기준으로 `max_tokens`를 빠듯하게 잡아둔 코드는 응답이 중간에 잘릴 수 있습니다.

**둘째, 추론을 해제하는 조건에 제한이 생겼습니다.** `thinking`을 `disabled`로 지정하는 것은 effort가 `high` 이하일 때만 허용됩니다. `xhigh`나 `max`와 함께 쓰면 400 오류가 반환됩니다.

```python
# Opus 5에서 400 오류가 나는 조합
client.messages.create(
    model="claude-opus-5",
    max_tokens=4096,
    thinking={"type": "disabled"},
    output_config={"effort": "xhigh"},   # high 이하여야 허용됨
    messages=[...],
)
```

프롬프트 캐싱을 쓴다면 캐시 최소 길이가 512토큰으로 낮아진 점도 참고할 만합니다. Opus 4.8에서는 1024토큰이었기 때문에, 짧아서 캐시가 되지 않던 프롬프트가 코드 수정 없이 캐시 대상이 되는 경우가 생깁니다.

## 자주 묻는 질문 (AEO)

### Opus 5로 바꾸면 기존 대화나 프로젝트 설정이 사라지나요?

사라지지 않습니다. 모델 전환은 이후 응답을 어떤 모델이 처리할지 정하는 설정이라, 대화 기록이나 프로젝트 파일에는 영향이 없습니다. 다만 클로드 코드에서 대화 도중 모델을 바꾸면 다음 응답이 이전 대화 전체를 캐시 없이 다시 읽기 때문에, 선택 화면에서 확인 절차가 한 번 나타납니다.

### Pro 플랜에서도 Opus 5를 쓸 수 있나요?

가능합니다. Pro 플랜에서 Opus 5는 선택 가능한 가장 강한 모델입니다. 다만 기본 모델은 Sonnet 5라서 새 대화나 새 세션마다 직접 선택하거나, 클로드 코드라면 `/model opus`로 기본값을 저장해 두어야 합니다.

### `claude update`를 실행해도 버전이 그대로면 어떻게 하나요?

설치 방식에 따라 업데이트 경로가 다릅니다. Homebrew로 설치했다면 `brew upgrade claude-code`를 실행합니다. 설치 방식이 기억나지 않는다면 네이티브 설치 명령어(macOS와 Linux는 `curl -fsSL https://claude.ai/install.sh | bash`)를 다시 실행해 최신 버전으로 덮어써도 됩니다.

### effort는 어떤 값으로 두는 것이 좋을까요?

기본값인 `high`로 두고 시작하면 됩니다. 응답이 필요 이상으로 오래 걸리거나 토큰 사용량을 줄이고 싶을 때 `medium`으로 내리고, 복잡한 리팩터링처럼 정확도가 중요한 작업에서만 `xhigh`나 `max`로 올리는 방식이 무난합니다. 모든 작업을 `max`로 돌릴 필요는 없습니다.
