검색 결과에 내 페이지가 보이기까지 검색엔진은 발견과 저장, 표시라는 세 단계를 거칩니다. 이 코스는 그중 앞의 두 단계, 그러니까 검색엔진이 페이지를 찾아내고 데이터베이스에 넣는 구간을 다룹니다. 크롤링과 색인이 무엇인지, robots.txt와 사이트맵이 어떤 신호를 주는지, 주소가 여러 개일 때 무엇을 정답으로 알려 주는지를 하나씩 정리했습니다.

개발 지식은 필요하지 않습니다. 각 편은 일상에서 겪는 장면에 빗대어 개념을 먼저 잡고 그다음에 실제 화면과 코드를 봅니다. 기준으로 삼은 자료는 구글 검색 센터의 공식 문서이고, 화면 예시는 서치 콘솔에서 직접 확인한 것입니다.

## 📚 다루는 개념 10가지

- **검색엔진이 하는 일**: [SEO의 범위](/class/seo-fundamentals/what-is-seo), 크롤러, 색인
- **크롤러에게 주는 신호**: robots.txt, 사이트맵, 정규 URL
- **사이트 구조**: 내부 링크와 URL 구조, 코어 웹 바이탈
- **확인과 구분**: 서치 콘솔로 색인 상태 확인, SEO와 SEM의 차이

어떤 검색어에서 몇 위인지를 다루는 내용은 이 코스에 넣지 않았습니다. 색인이 되지 않은 페이지는 순위를 따지는 단계에 아예 오르지 못하기 때문입니다.

## ❓ 자주 묻는 질문

### 페이지가 색인되지 않을 때 무엇부터 봐야 할까요?

서치 콘솔의 URL 검사로 구글이 그 주소를 어떻게 보고 있는지부터 확인합니다. 크롤링은 됐는데 색인이 되지 않았다면 robots.txt나 정규 URL 설정이 아니라 내용의 중복을 의심하는 순서로 갑니다. 해당 편에서 판정별로 나눠 정리했습니다.

### 워드프레스나 노션처럼 만들어진 도구를 쓰면 신경 쓸 게 없지 않나요?

사이트맵과 robots.txt는 도구가 자동으로 만들어 주지만 정규 URL과 내부 링크 구조는 글을 쓰는 사람이 정합니다. 주소가 여러 개로 생기는 상황도 도구를 쓸수록 자주 나옵니다.

### 코어 웹 바이탈 점수가 낮으면 순위가 떨어지나요?

점수 하나로 순위가 정해지지는 않습니다. 다만 화면이 늦게 뜨거나 버튼이 밀리면 사람이 먼저 떠납니다. 해당 편에서 세 지표가 각각 무엇을 재는지와 어디를 고치면 움직이는지를 정리했습니다.
