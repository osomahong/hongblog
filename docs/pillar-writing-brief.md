# 클래스 작성 공통 지침 (마케팅과 데이터 키워드 선점 작업 전용)

이 문서는 `docs/marketing-data-pillar-plan-2026-09.md` 계획을 실행하는 작업자가 클래스 한 편을 쓸 때 매번 여는 문서다. 전체 배경은 계획 문서에 있고, 여기에는 파일 하나를 쓰는 데 필요한 것만 둔다.

## 먼저 읽을 것 (생략 불가)

| 순서 | 파일 | 무엇을 가져오나 |
|---|---|---|
| 1 | `content/classes/what-is-kpi.md` | **기준판.** 헤딩 구성, 문장 호흡, 표 밀도, 비유 쓰는 방식 |
| 2 | `.claude/skills/write-insight/references/prose-rules.md` | 쓰지 말 것 |
| 3 | `.claude/skills/write-insight/references/writing-craft.md` 1절과 2절 | 중심 비유와 문장 층위 |
| 4 | 같은 코스의 기존 클래스 1편 | 그 코스의 표기 관행 |

## 파일 구조

`content/classes/{slug}.md` 하나를 만들거나 고친다. frontmatter 필드는 기준판과 같은 순서로 둔다.

```yaml
slug, term, definition, category, tags, publishedAt, (updatedAt), courseSlug,
orderInCourse, aliases, relatedTerms, difficulty, quiz, metaTitle,
metaDescription, ogImage, summary3
```

- `category`는 `MARKETING`, `AI_TECH`, `DATA`, `CLAUDE_EDUCATION` 중 하나다
- `tags`는 3개에서 5개. **`src/lib/constants.ts`의 `CANONICAL_TAGS`에 있는 값만 쓴다.** 도구 이름과 대상자는 태그로 쓰지 않는다
- `relatedTerms`는 **실재하는 슬러그만** 쓴다. 없는 슬러그를 적으면 빌드가 멈춘다. 같은 작업 묶음에서 함께 만드는 슬러그는 써도 된다
- `ogImage`는 `/og/{slug}.png`로 적어 두고, 이미지 생성은 코디네이터가 한다
- 기존 파일을 고치는 경우 `slug`, `publishedAt`, `courseSlug`, `orderInCourse`를 바꾸지 않고 `updatedAt: '2026-09-14T00:00:00.000Z'`를 추가한다

## 제목 규칙

- `term`(H1)과 `metaTitle`의 **첫 어절이 같아야 한다.** `CAC (Customer...)`와 `CAC 계산 공식`은 첫 어절이 같아 통과한다
- `metaTitle` 표시 폭은 36 이하다. 한글 1, 그 밖 0.5로 센다
- `metaTitle`에 `준이아빠블로그`와 파이프(`|`)를 넣지 않는다. 구분은 콜론으로 한다
- 제목 앞 30자 안에 **사람들이 실제로 검색창에 치는 말**을 둔다. 과제마다 지정된 타깃 검색어가 그것이다
- 마케팅 수사, 감탄사, 호기심 유발 표현을 쓰지 않는다

## 본문 골격

기준판과 같은 순서를 쓴다. 이모지는 헤딩 앞에 하나씩 붙인다.

```
## 🤔 (읽는 사람이 겪는 상황 한 문단에서 두 문단)
## 🔑 (용어)의 정의        ← 굵은 "X는 Y입니다" 완결 문장이 반드시 들어간다
## (이모지) 중심 비유 한 가지로 푸는 절
## (이모지) 가장 가까운 개념과의 비교표
## (이모지) 계산 공식과 예시 또는 실무 적용 절 2개에서 3개
## ⚠️ 자주 하는 실수 또는 오해
## ❓ 자주 묻는 질문      ← H3 질문 3개에서 4개, 물음표로 끝낸다
## 📋 3줄 요약
```

- **본문 1,300단어에서 1,800단어**(`wc -w` 기준). 기존 클래스는 900단어대라 얇다
- 표 2개 이상, 계산 예시나 구체 수치 예시 2개 이상
- 한 문단은 2문장에서 4문장. H2 하나 아래 문단 3개에서 5개
- 병렬 항목 3개 이상은 불릿으로 뺀다
- 내부 링크 3개 이상. `[CTR](/class/digital-marketing-terms/what-is-ctr)` 형태이고 **경로는 `/class/{courseSlug}/{classSlug}`다.** 코스 조각을 짐작해 조립하지 않고 대상 파일의 `courseSlug`를 열어 확인한다
- `## 📋 3줄 요약`의 세 줄은 frontmatter `summary3`와 **같은 문장**으로 쓴다

## 문장 규칙 (기계가 막는 것)

파일을 저장하면 훅이 검사하고 위반이 있으면 저장을 되돌린다. 아래는 이 작업에서 실제로 걸린 것들이다.

- **`-는가/-은가/-인가` 종결 금지.** 표 머리글의 `무엇인가`도 걸린다. `가리키는 것`, `무엇인지`로 쓴다
- **긴 줄표와 가운뎃점 금지.** 쉼표, 콜론, 슬래시로 바꾼다. 예외가 없다
- **`갈래`, `얹히다`, `비로소`, `정본` 같은 문어체 금지.** `갈래`는 `가지`, `묶음`으로 쓴다
- **수 관형사와 추상명사를 붙여 쓰지 않는다.** `세 축` → `세 가지 축`. `두 사람`, `세 단계`처럼 셈 단위가 되는 명사는 그대로 쓴다
- **번역투 금지.** `~에 대한`은 `~의`로, `~를 거쳐`류의 수단 표현은 `~로`로, `가장 흔한 사례 가운데 하나` 꼴은 `흔한 사례입니다`로 쓴다. 이중 피동과 2인칭 대명사도 쓰지 않는다
- **`읽힙니다` 금지.** `~로 보입니다`, `~라는 뜻입니다`로 쓴다
- **`손보다`, `손대다` 금지.** `고치다`, `바꾸다`로 쓴다
- **`뜻이 생깁니다` 금지.** `판단 근거가 됩니다`로 쓴다
- **라벨과 명사구에 단형 부정 금지.** 제목과 표 머리글에서 `안 되는 것` → `되지 않는 것`
- 존댓말(`~습니다`, `~합니다`)로 통일한다
- 인접한 두 문장이 같은 어절로 끝나지 않게 한다

## 근거 수위

- 공식 문서로 확인한 것만 단정형으로 쓴다
- **업종별 평균 CTR, 평균 CPM 같은 기준값을 출처와 기간 없이 적지 않는다.** 확인하지 못했으면 그 표를 넣지 않고, 대신 자기 데이터로 기준선을 잡는 방법을 적는다
- 가격과 버전처럼 시간에 민감한 정보에는 `2026년 9월 기준`을 붙인다
- 계산 예시는 가상 데이터로 만들되 단위와 기간을 적는다

## 중심 비유

- 산출물 하나에 **중심 비유 하나.** 손으로 만질 수 있는 사물에서 고른다(우편, 주방, 집, 상자, 도로, 상점, 저울)
- 비유는 `~듯`, `~처럼`으로 본문 문장 안에 붙인다. 따로 떼어 설명하지 않는다
- 처음 나오는 전문 용어마다 곁가지 비유를 한 번씩 붙일 수 있다. 같은 비유를 두 번 쓰지 않는다
- 기준판은 KPI를 체중계 숫자와 하루 걸음 수로 풀었다. 그 비유를 다른 편에서 다시 쓰지 않는다

## 완료 조건

작업자는 파일을 쓴 뒤 아래 세 가지를 직접 돌리고 결과를 보고에 적는다. HARD가 남아 있으면 끝난 것이 아니다.

```bash
npm run check:prose -- content/classes/{slug}.md
node .claude/skills/prose-inspector/scripts/check-literary.mjs content/classes/{slug}.md
npm run check:summary3 -- content/classes/{slug}.md
```

보고에는 파일 경로, `wc -w` 단어 수, 세 검사 결과, 내부 링크로 건 경로 목록, 확인하지 못해 넣지 않은 수치를 적는다.
