# About 고객사 연혁 익명화 디자인

## 목표

`/about` 페이지에서 고객사 실명과 브랜드 로고를 직접 노출하지 않고, 공식 소개 자료를 바탕으로 한 업종·시장 설명과 대표 이모지, `A사` 식별자를 보여준다. 현재 소속인 `오픈소스마케팅`은 자기소개와 구조화 데이터에서 유지한다. 사용자가 제외 요청한 `레아딜`은 연혁에서 완전히 삭제한다.

## 범위

### 포함

- `src/app/about/page.tsx`의 고객사 연혁 표시 데이터
- About 페이지의 소개·업무·FAQ 문구와 구조화 데이터에 남아 있는 고객사명
- 고객사 로고 이미지와 외부 파비콘 렌더링 제거
- 연혁 고객사 이름과 로고 alt 텍스트의 익명화
- `레아딜` 연혁 항목 삭제
- `/about`의 렌더링 결과와 빌드 산출물 검증

### 제외

- `workHistory`에 포함되지 않는 현재 소속 `오픈소스마케팅`의 자기소개 문구와 `Person` JSON-LD의 `worksFor`
- 다른 글·클래스에 등장하는 제3자 회사명
- 고객사 수, 경력 연도, 업무 설명의 수치 자체
- 고객사별 실제 원본명을 저장하는 별도 데이터베이스나 관리자 기능

## 콘텐츠 정책

1. 화면에 고객사 법인명, 고객사 브랜드명, 고객사 영문명, 고객사 고유 제품명, 로고 파일명, 외부 파비콘 URL을 노출하지 않는다. `GA4`, `GTM`, `Firebase`, `Amplitude`, `BigQuery`, `Looker`처럼 고객사가 아닌 분석·개발 도구명은 경력의 업무 맥락을 위해 유지할 수 있다.
2. 라벨은 `대표 이모지 + 업종·시장·서비스 특징 + A사/B사` 형식으로 작성한다.
3. `국내 최고`, `1위` 같은 검증 범위가 넓은 수식어는 공식 자료가 명시적으로 뒷받침하는 경우가 아니면 사용하지 않는다. 기본 표현은 사실 기반의 중립적인 업종 설명으로 한다.
4. 같은 업종 또는 같은 기업군 안에서 여러 항목을 구분할 필요가 있으면 `A사`, `B사`를 붙인다. 고객사 원본명과 연결되는 일련번호나 내부 코드가 아니다.
5. 기관도 로고와 실명을 사용하지 않고, 기관 유형과 역할을 설명한다. 예: `관광 진흥 공공기관`, `사립 종합대학 A`, `국제구호개발 NGO A`.
6. 업무 제목과 About 페이지의 소개·FAQ 문구는 기존 경력의 의미를 유지하되, 고객사 고유 제품·브랜드명이 들어간 경우에는 일반 업종 표현으로 바꾼다. 이번 변경에서 확인된 치환은 `한국관광공사` → `관광 진흥 공공기관`, `KOTRA아카데미` → `무역·투자 진흥 공공기관 아카데미`, `네이버페이` → `간편결제`이며, 로고·브랜드가 포함된 회사명은 모두 최종 label로 대체한다. 분석·개발 도구명은 고객사 식별자가 아니므로 치환 대상이 아니다.
7. `레아딜`은 대체 라벨을 만들지 않고 해당 연혁 항목 자체를 제거한다.

식별자 배정은 현재 연혁의 시간순서를 따른다. 동일 범주인 대학은 `사립 종합대학 A/B/C`, 사이버대학은 `사이버대학 A/B`로 고정하고, 이미 라벨의 서비스·시장 설명이 서로 다른 항목은 별도 라벨로 구분한다. `레아딜`은 위 매핑에도 포함하지 않는다.

현재 매핑 표의 고객사 행은 73개이며, 구현 후 `workHistory`의 `label` 필드도 정확히 73개여야 한다. 대학·사이버대학처럼 동일 범주의 식별자는 표의 시간순서와 일치해야 한다.

### 금지 토큰과 허용 토큰

검증 시 금지 토큰은 이 표의 `현재 company` 열 전체(73개 매핑 행과 삭제 대상 `레아딜`)와 그 안의 괄호 표기·영문 표기를 포함한다. 즉 회사명·브랜드명을 새 정규식으로 임의 추정하지 않고, 이 표를 기준 데이터로 삼는다. 현재 업무 문구에 있던 고객사 고유 제품명 `네이버페이`, `동원몰`, `더반찬`, `풀무원녹즙`, `킵그로우`, `알고리즙`, `도매꾹`, `오피스키퍼`, `픽앤픽`, `비앤빛안과`, `뉴라이즌`, `hoppin`도 금지 토큰에 추가하며, 매핑 표의 최종 `label`·`work`에는 이 토큰이 없어야 한다.

경력 맥락상 허용하는 외부 도구명은 `GA4`, `GTM`, `Firebase`, `Amplitude`, `BigQuery`, `Looker`, `LookerStudio`, `SEO`, `CRM`, `UTM`이다. 이 허용 목록은 고객사 이름을 예외 처리하기 위한 목록이 아니다.

## 표시 데이터 설계

`workHistory`는 더 이상 `company` 원본명이나 `logo` 식별자를 사용하지 않는다. 각 항목은 최소한 다음 필드를 가진다.

```ts
{
  year: string;
  label: string;
  emoji: string;
  work: string;
}
```

`milestones`는 `label`과 `emoji`를 그대로 전달해 연혁 배지를 렌더링한다. 회사 로고용 `localLogoByCompany`, `logoDomainByCompany`, `companyLogo`는 삭제한다. 연혁 배지에는 이미지 대신 `span` 또는 접근 가능한 텍스트 노드를 사용한다.

## 렌더링 및 접근성

- 이모지는 장식이 아니라 라벨의 시각적 보조 요소로 사용하되, 라벨 텍스트 자체가 의미를 완전히 전달해야 한다.
- 이모지에는 별도 이미지 alt가 필요하지 않으며, 장식용 요소는 `aria-hidden="true"`를 사용한다.
- 고객사 실명을 포함한 `alt`, `title`, `aria-label`, JSON-LD, URL, 외부 이미지 요청을 생성하지 않는다.
- 기존 연혁의 연도·업무 설명·정렬·레이아웃은 유지한다.

## 검증 기준

1. `src/app/about/page.tsx`와 빌드된 About 서버 출력에서, 항목별 매핑 표의 `현재 company` 열에 있는 모든 고객사 토큰과 고객사 영문명·브랜드명이 0건 검색된다. 연혁뿐 아니라 About 소개·업무·FAQ 문구와 JSON-LD도 검사한다. 단, 자기소개와 `worksFor`의 `오픈소스마케팅`은 허용한다. 허용 도구명은 금지 토큰 검사에서 제외한다.
2. `src/app/about/page.tsx`와 빌드된 About 서버 출력에서 `/images/about/logos`, `google.com/s2/favicons`, 고객사 로고 파일명이 0건 검색된다.
3. `레아딜`은 소스와 렌더링 결과에서 0건 검색된다.
4. `sed -n '/const workHistory/,/const milestones/p' src/app/about/page.tsx | rg -c '    label:'`의 결과가 `73`이고, 같은 범위의 `emoji:` 결과도 `73`이다.
5. 모든 연혁 항목이 이모지와 업종형 라벨을 가지며, 대학 식별자는 `사립 종합대학 A`, `사립 종합대학 B`, `사립 종합대학 C`, 사이버대학 식별자는 `사이버대학 A`, `사이버대학 B`로 각각 한 번씩만 나타난다.
6. 렌더링 응답에는 자기소개 문구의 `오픈소스마케팅 컨설팅 랩 차장`과 Person JSON-LD의 `worksFor` 객체 `name: "오픈소스마케팅"`이 모두 유지된다.
7. `npm run lint`, `npm run check:links`, `npm run build`가 통과한다.
8. 빌드 뒤 `rg --files .next/server | rg '/about/|about'`로 확인한 About 서버 출력 파일 전체를 대상으로 같은 금지 토큰 검사를 실행한다. 출력 경로가 달라져도 About 관련 파일을 검사 범위에서 제외하지 않는다.
9. 렌더링 검증은 `npm run start -- --hostname 127.0.0.1 --port 3100`으로 서버를 띄운 뒤 `curl -fsS http://127.0.0.1:3100/about` 응답을 대상으로 수행한다. 응답에는 `국내 보안 소프트웨어 기업 A사`, `🛡️` 같은 최종 라벨·이모지와 `오픈소스마케팅` 보존 문구가 포함되고, 고객사 금지 토큰·`레아딜`·로고 URL은 포함되지 않아야 한다.
10. 기존 미커밋 파일은 변경하지 않는다.
