# AI 교육 안내와 익명 대표 이력 설계

## 승인된 목표
사용자는 이력 근거 확인 → 익명 대표 사례 → 소개 개편 → 교육 안내 1개 → 홈페이지·주요 클래스 연결의 순차 진행을 승인했다. 추가 승인 없이 이 범위의 구현과 검증을 진행한다. 배포와 외부 게시 요청은 이번 범위에 없다.

## 접근
기존 Next.js 사이트에서 /about을 보강하고 /education 한 페이지를 추가한다. 대량 랜딩페이지, 전체 콘텐츠 개편, 외부 홍보, 자동 추천 측정은 보류한다. 기존 디자인을 사용한다.

## 사실과 개인정보
RAG의 원문/메일 발췌에서 본인 역할과 수행 상태를 확인한 대표 사례 3개만 공개한다. 교육 완료와 컨설팅 계획 수립을 구분한다. 회사/기관 이름, 지역, 정확한 날짜, 인원, 가격, 내부 문서 URL은 새 사례에 넣지 않는다. 규모 근거가 없으면 규모를 생략한다. 근거가 확인되지 않은 기존 누적 고객·교육·이벤트 수는 소개에서 제외하고 재검증을 보류한다. 원문 식별자와 고객 매핑은 저장소 밖 개인 검토 폴더에만 둔다.

## 페이지
- /about: 실제 경험을 AI 교육과 연결한 소개, 대표 사례, 교육 안내 경로를 연혁보다 먼저 배치. 기존 익명 연혁은 유지하되 계약 시작 연도임을 표시.
- /education: 비개발자와 마케터 대상 교육 안내. 제공 가능한 교육 주제 3개, 선수 지식, 예시 산출물, 시간·비용·지원 범위는 협의, 진행 방식, 강사, 사례 링크, 메일 문의, 독학 자료. 커리큘럼 제안을 과거 완료 실적으로 표현하지 않는다.
- 홈: 작성자·전문 분야·교육 안내를 짧게 노출. 기존 글 탐색 유지.
- 주요 Claude 과정 3개: 독학과 기업 교육의 차이, 강사 소개·교육 안내 링크.
- 푸터: 교육 안내 상시 링크. 내비 너비 확대는 피한다.

## 구현 경계
src/lib/education.ts에 공개 가능한 사례·교육 문구만 저장한다. 대표 사례 컴포넌트가 about에서 재사용되며 education은 이를 링크한다. 공용 AUTHOR_PERSON_LD를 홈과 과정에도 사용. /education은 Service 구조화 데이터(대상·제공자·페이지와 일치)와 메타·canonical·기본 OG를 제공한다. 사이트맵과 링크 검사기에 새 정적 경로를 추가한다.

## 검증
1. 사실·범위 검토: 계획/완료 혼동, 수치 과장, 타인 작성 자료 귀속 확인.
2. 소스·렌더 HTML에서 고객 토큰과 원문 URL 미포함 검수. 기존 연혁은 별도 익명화 매핑으로 검사.
3. 문체·링크·메타/인물 연결 검수, 빌드·타입 검사와 수정 파일 lint.
4. 데스크톱·모바일에서 교육 안내, 소개, 홈, 주요 과정 확인. 문의는 실제 전송하지 않는다.
5. 기존 사용자 수정 파일을 보존하고, 보류 항목과 검증 한계를 인계한다.
