# 실제 근거 기반 익명 사례 상세 페이지

## 승인된 목표
사용자가 독립 사례 페이지 제안에 동의하고 RAG에서 실제 흔적을 찾아 가능한 작업 과정을 상세히 작성하도록 요청했다. 불확실한 사실은 진행 중 질문하고 확인 가능한 작업은 계속한다. 앞선 설계의 상세 사례 보류를 해제한다.

## 구성
/cases 목록과 /cases/[slug] 정적 상세 페이지를 만든다. 독립 제목, 설명, canonical, Article 및 BreadcrumbList, 사이트맵을 제공한다. about의 대표 3개 요약에서 상세 사례로 직접 연결하고 education의 관련 교육 주제와 홈/푸터에서 접근할 수 있게 한다. 기존 디자인과 글 탐색을 유지한다.

## 사례 선정
근거의 종류와 본인 역할, 수행 상태, 서로 다른 업무를 기준으로 선정한다. 초기 후보는 공공 교육기관 실습 지원, 소비재 기업 공동 교육, 온라인 서비스 구매 측정 진단, 식품 유통 사이트 데이터 구축, 유통 기업 구매금액 정의, 온라인 유통 사이트 인수인계, 온라인 서비스 AI 도입 계획이다. 충분한 근거가 없는 후보는 목록에 수만 늘려 넣지 않는다.

## 원고
각 사례는 배경, 담당 역할, 순서별 과정, 전달한 결과물, 확인된 결과와 한계, 관련 교육과 사례를 담는다. 사례별 확인 근거를 공개 가능한 자료 유형 수준으로 설명한다. 기간/인원/규모/수치/고객명/문서 식별자는 공개하지 않는다. 고객 코드나 화면을 복사하지 않는다. 기술적 발견도 특정 고객의 취약점이나 개인 데이터 수집내역을 드러내지 않도록 업무 결정 수준으로 설명한다.

공동 작업과 본인 작업을 구분하고 계획을 완료로 쓰지 않는다. 코드 수정 예정 메일은 수정 완료 근거가 아니다. 종료 안내는 매출 향상 증거가 아니다. 기존 기술 자료는 당시 작업 기록으로 서술하며 현행 기술 권장안으로 주장하지 않는다.

## 검수
개인 근거표는 저장소 밖에 둔다. 원문/검색 발췌 사용 한계를 기록한다. 독립 문서와 사실 검토, 문체, 개인정보 토큰, 내부 링크, 구조화 데이터, 없는 경로 404, 모바일/태블릿/데스크톱 검수와 빌드를 한다. 로컬에 올려 브라우저를 열고 원고 전문과 전후 보고서를 전달한다. 외부 배포/연락은 실행하지 않는다.

확인 질문에 답변이 없으면 확인된 사실만 작성하며, 신규 AI 교육 제안은 완료 사례에서 제외한다. 상세 조사로 확인된 공동 역할/상태를 기존 about 대표 사례와 education 소개 문구에도 동기화한다.

## 사용자 요청 반영: 독자를 위한 사례 원고
소제목은 정중한 질문형으로 바꾼다. 독립된 공개 근거 설명과 비공개 안내를 본문에서 제거하고, 사실 검증은 개인 근거표와 검수 문서에서 수행한다. 결과를 주장할 때 수행 상태를 지키되, 독자에게 내부 검수 상황을 반복 설명하지 않는다. 각 단계에 관찰한 문제, 판단 이유, 실제 행동, 다음 단계와의 관계를 구체적으로 적는다. 추정 성과나 미확인 완료를 추가하지 않는다. 사례별 시사점을 먼저 설명하고 교육 연결은 짧은 관련 링크로 제시한다. 기존 slug와 canonical은 유지한다.

판단 이유와 단계 간 인과관계도 근거 범위에서 작성한다. 일반적인 실무 설명을 당시 본인이 실제 내린 판단처럼 서술하지 않는다.

## 재개정: 사례별 서사와 읽기 흐름
사용자가 동일한 틀과 인용을 의식한 설명을 지적했다. 공통 역할/과정/결과/교훈 틀을 해제하고 사례마다 핵심 문제에서 시작하는 도입과 2~3개 고유 소제목으로 구성한다. 역할과 결과는 본문 흐름에 포함하고, 반복 요약·단계 번호·일반론·본문 중간 교육 유도는 제거한다. 짧은 사례는 짧은 작업 기록으로 둔다. 제목을 줄이고 헤더 박스/섹션별 굵은 선을 줄이며, 본문 폭과 문단 간격으로 읽기 흐름을 만든다. 기존 사실 범위와 slug/metadata를 유지한다.

slug와 canonical은 유지하고 메타 제목·설명과 구조화 데이터는 새 원고와 동기화한다.

## 2026-09-10 사용자 편집 예시 반영
제목은 산업군+실제 과업으로 구체화한다. 본문은 고객 요구와 실무 진단, 그 접근이 필요한 이유, 실제 적용 방식이 연결되는 전문가의 케이스 공유로 작성한다. 사용자 제공 소비재 교육 예시를 문체/내용 기준으로 삼는다. 일반적 실무 설명과 해당 프로젝트 수행 사실을 구분하되, 공개 근거/비공개 설명을 다시 넣지 않는다. 목록 상단은 어두운 소개 영역, 목록은 밝은 개별 글 영역으로 구분하고 사례별 산업/과업/요약/상태의 위계를 만든다. 본문 가독성과 기존 slug/canonical은 유지한다.

## 제3자 독자 관점 편집
사용자 제공 매출 사례 수정 예시를 전 사례에 적용한다. 상황을 이해할 배경 → 용어의 의미 → 숫자/조건이 문제되는 이유 → 실제 판단과 수행 순서로 설명한다. 공통 목차를 추가하지 않고 기존 문단을 고친다. 일반 예시와 실제 수행, 제안/완료를 구분한다. GA4/이벤트/value/매개변수/GTM/dataLayer/퍼널/온보딩/UTM/SQL/에이전트는 각 독립 글에서 필요한 만큼 설명한다. 목업과 본문의 가상 금액 일치, 확인된6회제안/2사이트 유지. 띠카드 재도입 없음.

## 제목 개정
사용자 요청에 따라 산업 나열형 제목을 도구/과업과 실제 질문에 대응하는 문제 중심 제목으로 변경. URL 유지, H1/검색/공유/Article/목록은 동일 title 데이터 사용. 성과나 완료를 추가 주장하지 않으며 AI 도입은 계획으로 명시.
