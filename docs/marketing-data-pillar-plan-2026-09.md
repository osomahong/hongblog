# 마케팅과 데이터 개념 키워드 선점 계획

마케팅과 데이터 주제의 기존 개념, 정의, 전략 검색어를 클래스와 기둥 글로 한꺼번에 선점하는 실행 계획이다. 작성은 Opus 세션이 맡고, 이 문서는 무엇을 어떤 순서로 쓰고 어떻게 검증해 커밋하는지를 고정한다.

- 작성일: 2026-09-14
- 데이터 확인일: 2026-09-14
- 측정 기간: Google Search Console 2026-06-13 ~ 2026-09-11 (90일), 검색어별 상세는 2026-03-15 ~ 2026-09-11 (180일)
- 데이터 출처: Search Console 실측(`seo-topic-finder` 스크립트), 네이버 검색광고 키워드도구 월간 검색량(PC와 모바일 합계), SerpApi 구글 한국 검색 결과 13건
- 관련 문서: `docs/content-seo-strategy.md`, `.claude/references/content/topic-selection-gate.md`, `.claude/references/content/audience-levels.md`

## 1. 결론

세 묶음으로 73편을 Phase 0 준비 커밋까지 여섯 번에 나눠 커밋한다.

| 묶음 | 편수 | 내용 | 기대 효과 |
|---|---|---|---|
| A 회수 | 16 | 노출은 받는데 클릭이 없는 기존 마케팅 클래스 재작성 | 이미 쌓인 13개월 클릭 신호를 살린다. 가장 빠르다 |
| B 신규 클래스 | 41 | 코스 2개 신설(마케팅 전략 프레임워크, 데이터 분석 기초)과 기존 코스 보강 | 헤드 검색어(`KPI`, `표준편차`, `대시보드`)의 정의 자리를 잡는다 |
| C 기둥 글 | 16 | 12,000자 안팎의 전략, 설계, 비교 글 | 수식어 검색어(`설정 예시`, `높이는 법`, `차이`)와 AI 검색 인용을 잡는다 |

지금 준이아빠블로그의 마케팅 클래스 16편은 90일 노출 36,280회를 받으면서 클릭률이 0%에서 1.5%, 대부분 1% 아래에 묶여 있다. 새 글보다 이 페이지들을 먼저 고치는 편이 기대값이 높다. 신규 키워드는 네이버 월간 검색량으로 측정한 것만 올렸고, 한 자리도 검색량을 짐작해 적지 않았다.

### 2.5 마케팅 일반 주제의 실측 한계

주제 선정 게이트가 경고하는 대로, 고유명사 없는 마케팅 일반 글은 실제로 노출을 받지 못했다. `퍼포먼스 마케팅 측정 가이드` 180일 노출 3회, `제로클릭 마케팅 전략` 7회, `데이터 드리븐 캠페인 전략` 5회, `데이터 시각화 베스트 프랙티스` 5회다.

그래서 이 계획은 한 편도 일반 주제로 잡지 않는다. 모든 페이지가 검색량이 측정된 검색어 하나를 제목 앞에 둔다. 사용자가 개념과 전략 주제를 지정했으므로 게이트는 통과한 것으로 보고, 대신 검색어 형태로 주제를 잡는 방식으로 위험을 줄인다.

## 3. 설계 원칙

### 3.1 클래스와 기둥 글의 역할 분리

같은 개념을 클래스와 기둥 글이 함께 다루면 자기잠식이 된다. 역할을 검색어 형태로 나눈다.

| 구분 | 클래스 | 기둥 글 |
|---|---|---|
| 잡는 검색어 | 헤드와 `뜻`, `계산`, `공식`, `차이` | `설정 예시`, `높이는 법`, `설계`, `총정리`, `비교` |
| 첫 문장 | `X는 Y입니다` 정의 | 정의 한 줄 뒤 곧바로 클래스 링크, 본론은 판단 기준 |
| 분량 | 1,500단어에서 2,000단어 | 4,500단어에서 6,000단어(한글 12,000자 안팎) |
| H2 | 정의, 계산, 차이, 활용, FAQ | 하위 질의 12개 이상 |
| 제목 형태 | `KPI 뜻과 설정 방법: 핵심성과지표 예시` | `마케팅 KPI 설정 총정리: 채널별 예시 30개와 OKR 차이` |

기둥 글 도입부 첫 문단에서 클래스로 링크하고, 클래스 관련 개념 절에서 기둥 글로 링크한다. 두 페이지가 같은 헤드 검색어에 함께 걸리면 클래스를 남기고 기둥 글 제목에서 헤드를 뒤로 뺀다.

### 3.2 분량과 밀도 규격

압도적 분량은 목표가 아니라 결과다. 하위 질의를 빠짐없이 답하면 분량이 따라온다. 반대로 하위 질의 없이 늘린 글은 도움되는 콘텐츠 판정에서 사이트 전체를 누른다.

기둥 글 한 편의 필수 요소다.

- 하위 질의 12개 이상을 H2로 배치. 정의, 비교, 절차, 조건, 비용, 문제, 근거 일곱 가지 축에서 뽑는다
- 한 H2 아래 300자에서 600자 문단 3개에서 5개. 섹션 첫 문장을 지시어로 시작하지 않고 개체명을 다시 쓴다
- 비교표 2개 이상, 계산 예시 3개 이상(가상 데이터, 단위와 기간 명시)
- 원본성 요소 2개 이상: 직접 측정값, 실제 화면 캡처, 다른 곳에 없는 분류표, 실패 사례, 1차 자료 확인
- 자주 묻는 질문 H2 3개에서 5개(FAQPage 발행)
- 3줄 요약(`summary3`), 퀴즈 1개, 시점 표기(`2026년 9월 기준`)
- 본문 내부 링크 4개 이상: 클래스 2개, 인사이트 2개

클래스 한 편의 필수 요소다.

- 정의 한 문장(첫 줄), 기원과 배경 2문단, 계산 공식과 예시 2개, 가장 가까운 개념과의 비교표 1개, 실무 판단 기준 3개, FAQ H2 2개, 3줄 요약, 퀴즈
- 중심 비유 하나(손으로 만질 수 있는 사물), 용어마다 곁가지 비유 한 번씩

### 3.3 제목 규칙

`CLAUDE.md` 제목 규칙을 그대로 따른다. H1 첫 개체와 metaTitle 첫 개체를 같은 표기로 맞추고, 브랜드와 파이프를 넣지 않는다. metaTitle 폭은 36 이하. 제목 후보는 `seo-title-creator`로 뽑되 아래 두 가지를 고정한다.

- 검색어를 앞 30자 안에 둔다. `KPI 뜻과 설정 방법`처럼 검색하는 형태 그대로
- 재작성 클래스는 검색어 형태를 `뜻`, `계산 공식`, `차이`로 바꾼다. 지금 제목(`CAC (Customer Acquisition Cost)`)이 검색 결과에서 답으로 읽히지 않는 원인이다

### 3.4 코스와 카테고리

클래스 `category`에는 `DATA` 값이 없다(`src/lib/types.ts`의 `ClassItem`). 데이터 기초 코스는 `MARKETING`으로 두거나, 착수 전에 타입과 상수, OG 색을 `DATA`로 확장한다. 확장은 파일 3개 안팎이라 Phase 0에서 결정한다. 인사이트 `category`는 `DATA`가 있으므로 데이터 기둥 글은 `DATA`를 쓴다.

GA4 Edu(`/ga4-edu`)는 화면 조작 튜토리얼이고, 이 계획의 GA4 글은 개념 정의다. 겹치지 않도록 GA4 기둥 글에서 조작 절차는 GA4 Edu로 링크한다.

기둥 글 1편(마케팅 KPI)의 H2 배치다. 나머지 글도 같은 방식으로 착수 전에 12개를 먼저 적고 쓴다.

1. KPI 뜻과 핵심성과지표 정의 (정의)
2. KPI와 OKR, 목표, 지표의 차이 (비교)
3. 마케팅 KPI가 필요한 이유와 없을 때 생기는 문제 (근거)
4. 퍼널 단계별 마케팅 KPI 예시 (절차)
5. 채널별 KPI 예시: 검색광고, 메타, 콘텐츠, CRM (절차)
6. 선행 지표와 후행 지표 나누기 (조건)
7. KPI 개수와 기간 정하는 기준 (조건)
8. KPI 목표값 잡는 세 가지 방법 (절차)
9. 허영 지표와 실행 지표 구분 (문제)
10. KPI 대시보드 구성 (절차, 대시보드 글로 링크)
11. KPI가 어긋날 때 점검 순서 (문제)
12. 자주 묻는 질문 3개에서 5개

### 6.1 착수 전 게이트

한 편을 쓰기 전에 아래를 순서대로 한다.

1. `.claude/skills/write-insight/references/writing-craft.md`와 `prose-rules.md`를 읽는다
2. 같은 카테고리 기존 글 2편을 읽고 슬러그를 기록한다. 마케팅은 `conversion-and-conversion-campaign`, `google-ads-enhanced-conversions-guide`, 데이터는 `ga4-direct-none-traffic-guide`, `ga4-bigquery-attribution-models`
3. 하위 질의 12개를 먼저 적는다
4. 클래스는 `.claude/references/content/writing-style-guide.md`의 Class 골격을 쓴다

### 6.2 편별 검증

```bash
npm run check:prose -- content/insights/{slug}.md
node .claude/skills/prose-inspector/scripts/check-literary.mjs content/insights/{slug}.md
npm run check:summary3 -- content/insights/{slug}.md
npx tsx scripts/generate-og.ts --slug {slug}
```

클래스는 경로만 `content/classes/{slug}.md`로 바꾼다. HARD 0건과 낭독 검수를 마친 뒤 다음 편으로 간다. 기계 통과는 시작이고 끝이 아니다.

### 6.3 커밋 전 검증

```bash
npm run check:links
npm run check:titles -- --warn
npm run build
npx tsx scripts/seo-audit.ts
```

빌드가 `class-course-map`을 다시 만들므로 새 코스 클래스는 빌드 후에 링크를 확인한다. `updatedAt`은 묶음 A 전 편에 기록한다. 커밋 메시지는 기존 형식(`feat(classes): ...`, `insight: ...`)을 따르고 Phase마다 한 번 푸시한다. 푸시가 곧 Vercel 배포이므로 푸시는 사용자 확인 뒤에 한다.

### 6.4 자기잠식 점검

Phase 1과 3이 끝난 뒤 한 번씩 돌린다.

```bash
node .claude/skills/seo-topic-finder/scripts/gsc-opportunities.mjs --mode cannibal
```

같은 검색어에 클래스와 기둥 글이 함께 나오면 3.1 규칙대로 기둥 글 제목에서 헤드를 뒤로 뺀다.

## 7. 하지 않을 것

- 검색량을 조회하지 않은 검색어를 근거로 주제를 추가하는 것. 추가 후보는 반드시 `naver-keywords.mjs`로 먼저 잰다
- `conversion 뜻`, `전환 뜻`처럼 사전 의도 검색어를 잡으려는 제목
- 클래스와 기둥 글이 같은 제목 형태를 갖는 것
- 하위 질의 없이 분량만 늘린 글. 도움되는 콘텐츠 판정은 사이트 단위로 걸린다
- 검증 없는 커밋과 사용자 확인 없는 푸시
- 기존 클래스 슬러그 변경. 이미 쌓인 클릭 신호를 버리게 된다
- 매체별 기준값(평균 CTR, 평균 CPM)을 출처와 기간 없이 적는 것
