# GA4 Edu 페이지 아키텍처

튜토리얼 30개를 각각 독립 페이지로 만들 때 쓰는 라우팅, 데이터 모델, 페이지 뼈대를 정한 문서입니다. 커리큘럼은 `ga4-edu-curriculum.md`, 운영 방식은 `ga4-edu-design.md`에 있습니다.

## 1. 라우팅

| 경로 | 내용 | 색인 |
|---|---|---|
| `/ga4-edu` | 허브. 튜토리얼 30개 목록과 단계 안내 | 색인함 |
| `/ga4-edu/[slug]` | 튜토리얼 한 편 | 공개 2편만 색인함 |
| `/ga4-edu/realtime` | 실시간 개요 보고서 재현 화면 | 색인 안 함 |

슬러그는 저장소 규칙대로 영문 케밥 케이스를 씁니다. 주제의 핵심 개체를 그대로 쓰고 단계 표시는 넣지 않습니다. 나중에 단계가 바뀌어도 주소가 유지되어야 하기 때문입니다.

```
/ga4-edu/traffic-acquisition-channels   초급 1번 유입 정보 분석
/ga4-edu/exploration-free-form          중급 1번 자유 형식 보고서
```

`generateStaticParams`로 30개를 모두 정적 생성하고 `dynamicParams = false`를 걸어, 등록되지 않은 슬러그가 라우트로 생기지 않게 합니다.

## 2. 데이터 모델

튜토리얼 메타는 `src/app/ga4-edu/data.ts` 한곳에 모읍니다. MD 파일로 두지 않는 이유는 실습 컴포넌트와 짝을 이뤄야 하고, 본문이 산문이 아니라 구조화된 필드이기 때문입니다.

| 필드 | 쓰이는 곳 | 목적 |
|---|---|---|
| `slug`, `level`, `area`, `order` | 라우팅, 허브 목록 정렬 | 구조 |
| `title` | 화면 제목, 목록 | 사람이 읽는 이름 |
| `seoTitle` | `<title>`, og:title | 검색 노출 |
| `definition` | 도입부 첫 문장, metaDescription 첫 문장, JSON-LD `description` | AEO 삼중 정렬 |
| `summary` | metaDescription 나머지 | 검색 결과 설명 |
| `teaches` | JSON-LD `teaches`, 헤더 메타 | 학습 목표 |
| `terms` | 용어 정의 카드 | AEO 엔티티 명확성 |
| `steps` | 절차 목록 | AEO 피처드 스니펫, GEO 구조화 |
| `faq` | Q&A 단락, FAQPage JSON-LD | AEO 직접 답변 |
| `takeaways` | 3줄 요약 | AEO 핵심 요약 |
| `related` | 관련 튜토리얼 링크 | GEO 주제 권위 |
| `sources` | 참고 자료 | GEO 출처 인용 |
| `isOpen` | 게이트 판정, `robots` | 공개 2편 구분 |
| `status` | 허브 목록 표시 | 제작 진행 상태 |

## 3. 페이지 뼈대

모든 튜토리얼 페이지가 같은 순서를 씁니다. 위에서 아래로 읽으면 실습을 하지 않아도 주제를 이해할 수 있어야 합니다.

| 구역 | 내용 | 맡는 역할 |
|---|---|---|
| 1. 이동 경로 | 허브로 돌아가는 링크 | BreadcrumbList |
| 2. 머리말 | 단계 배지, 제목, 정의 한 문장 | AEO 직접 답변 |
| 3. GA4 화면 | 좌우 끝까지 채운 GA4 재현 화면. 모바일에서는 PC 안내 | 학습 |
| 4. 학습 요약 | 도입 문단, 용어 정의 카드 3개 | SEO 본문 |
| 4-1. 순서 | 단계마다 왼쪽에 설명, 오른쪽에 그 단계의 GA4 화면 캡처 | SEO 본문, 이미지 검색 |
| 5. 자주 묻는 질문 | Q&A 3개 이상 | AEO FAQ |
| 6. 3줄 요약 | 핵심 요약 | AEO 핵심 요약 |
| 7. 이어서 볼 것 | 관련 튜토리얼, 관련 인사이트 | GEO 내부 링크 |
| 8. 참고 자료 | 구글 공식 문서 링크 | GEO 출처 인용 |

### 실습 없이도 읽히는 본문이 필요한 이유

GA4 재현 화면은 자바스크립트로 그려지는 조작 영역이라 검색 엔진과 답변 엔진이 내용을 거의 읽지 못합니다. 4번부터 8번까지가 실제로 색인되는 본문입니다. 이 구역이 비면 페이지가 검색 결과에 나올 근거가 없어집니다.

## 4. 구조화 데이터

페이지마다 세 가지를 넣습니다.

| 타입 | 담는 것 |
|---|---|
| `LearningResource` | 제목, 정의, 학습 목표, 난이도, 소요 시간, 허브와의 `isPartOf` 관계 |
| `FAQPage` | `faq` 필드의 질문과 답변 |
| `BreadcrumbList` | 홈 > GA4 Edu > 튜토리얼 |

`description`은 `definition` 필드를 그대로 씁니다. 메타 설명, 본문 도입부, 구조화 데이터가 같은 개체와 같은 정의 표현을 쓰는 삼중 정렬 규칙을 따릅니다.

## 5. 게이트와 색인

| 상태 | 실습 | 본문 | robots |
|---|---|---|---|
| 공개 2편 | 전체 | 전체 | index, follow |
| 잠긴 28편 | GA4 화면 자리에 구독 안내 | 정의와 학습 목표까지 | noindex, follow |

잠긴 편을 `noindex`로 두는 이유는 두 가지입니다. 구독자만 볼 수 있는 내용을 검색 결과에 올리면 검색으로 들어온 사람이 막힌 화면을 만나고, 사이트맵에 넣지 않는다는 저장소 원칙과도 어긋납니다.

공개 2편은 사이트맵에 넣고, 허브도 함께 넣습니다.

## 6. 학습 방식: GA4 화면을 직접 조작한다

튜토리얼 화면에는 GA4에 없는 요소를 두지 않습니다. 학습자가 보는 것은 GA4와 같은 화면 하나이고, 안내는 두 가지뿐입니다.

| 안내 | 형태 |
|---|---|
| 도우미 말풍선 | GA4 화면 오른쪽 아래에 서 있는 사람 그림과 말풍선. 진행 단계와 지시문 한 줄 |
| 클릭 지점 | 다음에 누를 요소를 두르는 빨간 상자 |

설명 문단, 과제 확인 화면, 판정 카드, 점검 퀴즈, 정리 템플릿은 두지 않습니다. 화면을 직접 조작하는 학습은 GA4 화면에서만 하고, 읽어서 배우는 내용은 화면 아래 본문에 둡니다.

빨간색을 쓰는 이유가 있습니다. GA4는 강조색으로 파랑만 씁니다. 파란 표시를 그리면 GA4 자체 요소와 섞여 눌러야 할 곳이 드러나지 않습니다. 화면에서 빨간색은 튜토리얼이 가리키는 지점 하나뿐입니다.

### 화면 고정

GA4 상단바 오른쪽에 화면 고정 버튼을 둡니다. 누르면 사이트 머리말과 꼬리말이 덮이고 브라우저 창 전체가 GA4가 됩니다. Esc나 고정 풀기로 되돌립니다. GA4 보고서는 가로로 넓어야 표를 다 볼 수 있어서, 학습자가 실습에 들어갈 때 이 버튼을 누르도록 안내합니다. 이 버튼은 GA4에 없는 유일한 요소라 파랑을 쓰지 않고 회색 테두리로 눌러 둡니다.

### 스텝 엔진

튜토리얼 한 편은 스텝 목록입니다. 스텝마다 목표 한 줄, 링을 그릴 지점, 완료 조건을 갖습니다.

```ts
{
  id: "pick_28d",
  instruction: "지난 28일을 고릅니다.",
  ring: (s) => (s.openMenu === "date" ? "date-28d" : "date-chip"),
  isDone: (s) => s.dateRange === "28d" && s.openMenu === null,
}
```

학습자가 화면을 조작하면 GA4 상태가 바뀌고, 그 상태가 완료 조건을 만족하는 순간 저절로 다음 스텝으로 넘어갑니다. 다음 버튼이 없습니다.

판단 스텝에는 `isMiss`와 `missText`를 답니다. 잘못 고르면 화면은 그대로 두고 아래 띠 문구만 잠깐 바뀝니다. 정답을 알려 주지 않고 다시 볼 곳만 가리킵니다.

### 판단이 들어가는 자리

클릭 순서만 따라가는 스텝과 학습자가 표를 읽고 정해야 하는 스텝을 섞습니다. 판단 스텝은 데이터에 함정을 넣어 만듭니다. 초급 1번에서는 참여율이 가장 낮은 채널(Organic Social)의 세션수를 가장 적게 두어, 참여율 열만 보고 맨 아랫줄을 고르면 틀리도록 만들었습니다. 세션 열과 참여율 열을 함께 봐야 답이 나옵니다.

## 7. 컴포넌트 구성

```
src/app/ga4-edu/
  data.ts                      튜토리얼 30편 레지스트리
  page.tsx                     허브
  [slug]/page.tsx              튜토리얼 공통 페이지
  realtime/                    실시간 보고서 재현 (기존 화면 이동)
  ga4-edu.css                  GA4 테마 토큰과 화면 조각

src/components/ga4-edu/
  app/Ga4Chrome.tsx            상단바, 아이콘 레일, 화면 고정 버튼 (보고서와 탐색 공용)
  app/Ga4Shell.tsx             보고서 화면 껍데기. 보고서 트리, 기간, 보고서 머리
  app/Ga4ReportTable.tsx       측정기준 드롭다운, 총계 행, 측정항목 열, 쪽 이동
  app/Ga4Charts.tsx            꺾은선 카드, 가로 막대 카드
  app/Ga4ExploreShell.tsx      탐색 화면 껍데기와 탐색 홈 템플릿 목록
  app/Ga4FreeForm.tsx          변수 칸, 탭 설정 칸, 행과 열과 값을 놓는 칸
  app/Ga4PivotTable.tsx        행과 열이 교차하는 표
  app/tour.tsx                 빨간 상자 전달과 도우미 말풍선
  app/types.ts                 GA4 상태, 탐색 상태, 스텝 타입
  lab/useStepEngine.ts         스텝 판정과 이동을 한 번의 렌더로 처리하는 훅
  lab/progress.ts              localStorage 진행 저장
  lab/LabLoader.tsx            슬러그별 튜토리얼 지연 로딩
  labs/<slug>/data.ts          그 편의 데모 데이터
  labs/<slug>/index.tsx        스텝 정의와 화면 조립
  SubscribeGate.tsx            구독 게이트
```

`useStepEngine`은 상태 종류를 가리지 않습니다. 보고서 화면은 `Ga4State`로, 탐색 화면은
`Ga4ExploreState`로 같은 훅을 씁니다. 새 편을 만들 때는 그 편의 상태 타입과 스텝 목록만
넘기면 됩니다.

### 탐색 화면에서 변수를 옮기는 방법

GA4는 변수를 끌어다 놓아야만 행과 열에 들어갑니다. 실습도 끌어다 놓기를 그대로 받고,
변수를 누른 뒤 놓을 칸을 누르는 길을 함께 엽니다. 화면에 없던 버튼을 더하지 않으면서
끌기가 막힌 환경에서도 진행할 수 있습니다. 값 칸은 측정항목만, 행과 열은 측정기준만
받는 규칙도 GA4와 같습니다.

`app/` 아래 컴포넌트는 30편이 돌려 씁니다. `labs/<slug>/`에는 그 편의 데이터와 스텝만 둡니다.

### AIPBL 실습 엔진을 쓰지 않는 이유

`src/components/ai-practice/lab/`의 셸은 과제 확인, 미션, 점검, 정리 네 단계를 카드 안에서 진행하는 구성입니다. GA4 Edu는 GA4 화면 자체가 학습 표면이라 그 구성이 맞지 않습니다. 진행 저장 방식만 같은 형태로 가져오고 키를 `hongblog-ga4edu-progress`로 나눴습니다.

튜토리얼 컴포넌트는 `LabLoader`에서 슬러그별로 지연 로딩합니다. 30편을 한 묶음으로 내려보내면 첫 화면이 느려집니다.

## 8. 순서 캡처 만드는 법

본문 순서 목록은 단계마다 오른쪽에 그 단계의 GA4 화면 캡처를 답니다. 눌러야 할 곳에 빨간 상자가 그려진 그대로라 글만 읽어도 어디를 만지는지 알 수 있습니다.

캡처는 실습 화면을 그대로 찍어 만듭니다. 손으로 그리지 않습니다.

1. 브라우저를 1600x900으로 맞추고 튜토리얼을 엽니다
2. 애니메이션과 개발 도구 배지를 잠시 끕니다
3. 화면 고정을 눌러 GA4가 창 전체를 채우게 합니다
4. 스텝을 하나씩 진행하며 각 지점에서 창 전체를 찍습니다
5. 가로 1280으로 줄여 `public/images/ga4-edu/<slug>/step-N.png`로 넣습니다

실습을 고치면 캡처도 다시 찍습니다. 화면과 캡처가 어긋나면 학습자가 혼란스러워집니다.

## 9. 설명 문장 작성 기준

용어 정의, 절차 설명, 자주 묻는 질문의 답, 3줄 요약은 모두 같은 기준으로 씁니다. 한 줄로 끊고 넘어가지 않습니다. 읽는 사람이 자기 계정에서 같은 상황을 만났을 때 바로 판단할 수 있을 만큼 적습니다.

한 답변은 아래 순서를 따릅니다.

| 순서 | 하는 일 |
|---|---|
| 1 | 묻는 것을 한 문장으로 정의한다 |
| 2 | 실제로 벌어지는 경우를 세 가지 안팎으로 나눠 적는다 |
| 3 | 예외가 있으면 그 자리에서 밝힌다 |
| 4 | 왜 그렇게 되는지 원인을 짚는다 |
| 5 | 그래서 무엇을 해야 하는지로 닫는다 |
| 6 | 앱이나 특정 도구처럼 사정이 다른 경우를 덧붙인다 |

직접 유입을 묻는 답이 이 순서의 본보기입니다. 유입 정보가 없다는 정의로 열고, 주소 직접 입력과 즐겨찾기와 카카오톡 세 가지로 나누고, 인스타그램과 페이스북은 추천으로 잡힌다는 예외를 밝히고, UTM이 없어서 그렇다는 원인을 짚고, 링크를 공유할 때 UTM 규칙부터 정하라는 지침으로 닫고, 앱은 소스와 매체가 (direct) / (none)이 기본이라는 사정을 덧붙입니다.

### 크기를 숫자로 보여 준다

"영향이 작습니다" 같은 말로 끝내지 않습니다. 참여율 24퍼센트에 세션수 1,760인 채널과 28.7퍼센트에 5,940인 채널을 같은 목표로 올렸을 때 참여 세션이 각각 몇 회 늘어나는지 적습니다. 숫자가 붙어야 읽는 사람이 자기 계정에서 같은 계산을 합니다.

### 쓰지 않는 표현

화면 요소를 개발 용어로 부르지 않습니다. 칩, 열 머리글, 컬럼 같은 말 대신 학습자가 화면에서 보는 그대로 적습니다. "기간 칩을 누릅니다"가 아니라 "오른쪽 위 지난 7일이라고 적힌 곳을 누릅니다"로 씁니다.

## 10. 데모 데이터 규칙

- 모든 편이 가상 계정 `준준상점`으로 진행합니다. 실제 GA4 계정 없이 조작할 수 있습니다.
- 시계열은 난수를 쓰지 않고 결정론적으로 만듭니다. 서버 렌더 결과와 어긋나면 화면이 깜빡입니다.
- 총계 행에서 합계가 뜻이 없는 열(참여율, 세션당 평균 참여 시간)은 가중 평균으로 따로 계산합니다.
