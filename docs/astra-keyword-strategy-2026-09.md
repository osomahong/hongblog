# 아스트라 키워드 상위 노출 전략

GPT-6 아스트라 클러스터에서 이미 받고 있는 노출을 클릭으로 바꾸는 실행 계획이다.

- 작성일: 2026-09-14
- 데이터 확인일: 2026-09-14
- 측정 구간: Google Search Console 2026-06-13 ~ 2026-09-11 (90일), 검색어별 상세는 2026-03-15 ~ 2026-09-11 (180일)
- 데이터 출처: Search Console 실측, 네이버 검색광고 키워드도구 월간 검색량, SerpApi 구글 한국 검색 결과
- 관련 문서: `docs/content-seo-strategy.md`

## 1. 결론

노출은 이미 충분히 받고 있다. 문제는 순위 8위대에 묶여 클릭이 나오지 않는 것이다.

| 항목 | 실측값 |
|---|---|
| 클러스터 노출 (90일) | 17,019 |
| 클러스터 클릭 (90일) | 496 |
| 클러스터 CTR | 2.9% |
| 헤드 검색어 평균 순위 | 8.4 ~ 8.8 |
| 같은 클러스터 4위권 검색어 CTR | 17.7% ~ 22.2% |

순위 8위대와 4위권 사이에 CTR 7배 차이가 있다. 새 글로 순위를 끌어올리는 것이 노출을 더 늘리는 것보다 효과가 크다.

실행 항목은 세 가지다. 신규 글 1편 발행, 기존 비교글 제목과 메타 재정렬, 자기잠식 해소다.

## 2. 현황 진단

### 2.1 클러스터 규모와 성장

검색어 221개, 노출 17,019, 클릭 496이 페이지 14개에 분산돼 있다. 발판은 이미 만들어져 있다.

최근 28일 구간에서 노출이 계속 늘고 있다.

| 검색어 | 최근 28일 노출 | 직전 28일 노출 | 증감 |

| gpt 아스트라 | 3,906 | 280 | +3,626 |
| 아스트라 | 3,874 | 478 | +3,396 |

아직 성장 구간이라서 지금 발행하는 글이 순위를 잡을 여지가 있다.

## 4. 실행 계획

### Phase 1. 신규 글 1편 발행

비어 있는 자리는 하나다. 아스트라를 쓰려는 사람이 막히는 지점을 다루는 글이다.

| 항목 | 내용 |
|---|---|
| 주 타깃 | GPT아스트라, GPT6아스트라, 아스트라사용법, 챗GPT아스트라 |
| 보조 타깃 | 아스트라요금제, 아스트라가격, 챗GPT6 |
| 회수 대상 | 아스트라 뜻 (노출 834, 클릭 0) |
| 성격 | 문제 해결형. 분석이나 전망을 넣지 않는다 |
| 분량 | 6,000 ~ 8,000자. 기존 두 편보다 짧게 간다 |

본문에 들어갈 질문이다. 상위 점유 글 네 편이 공통으로 답하는 항목에, 그들이 다루지 않는 항목을 더했다.

1. 아스트라가 무엇인지 세 문장 요약 (`아스트라 뜻` 회수)
2. 요금제별로 쓸 수 있는 범위 (무료, 플러스, 프로, 팀, 엔터프라이즈)
3. ChatGPT 화면에서 모델을 고르는 순서
4. 목록에 아스트라가 보이지 않을 때 확인하는 순서
5. 회사 계정에서 보이지 않을 때 관리자가 켜야 하는 설정
6. ChatGPT에서는 되는데 API에서 되지 않는 이유
7. API 가격과 요금 계산 예시 (입력 100만 토큰당 10달러, 출력 50달러)
8. 아스트라로 먼저 시험해 볼 작업
9. 자주 묻는 질문

4번, 5번, 7번이 차별점이다. 상위 글 가운데 API 요금을 실제 작업 단위로 계산해 준 글이 없다. 출력 토큰이 입력의 다섯 배라는 점은 기존 비교글에 이미 정리돼 있어서 그대로 활용할 수 있다.

제목 방향이다. 확정은 `seo-title-creator`로 넘긴다.

- GPT-6 아스트라 사용법: 요금제별 제공 범위와 모델 확인 순서 (실제 채택)
- GPT-6 아스트라 요금제 정리: 플러스와 프로에서 쓸 수 있는 범위, API 요금 계산

제목 앞부분에 `GPT-6 아스트라`를 두고, 뒤에 `사용법` 또는 `요금제`를 붙인다. 상위 글 네 편이 모두 이 구조다.

### Phase 2. 기존 비교글 재정렬

`openai-astra-model-comparison`이 클러스터 노출의 대부분을 받고 있다. 이 글의 제목과 메타를 바꾼다.

| 항목 | 현재 | 방향 |
|---|---|---|
| 제목 | GPT-6 아스트라(Astra) 출시 정리: 벤치마크와 가격, 모델 비교 | 출시일과 가격을 앞으로 당긴다 |
| 받는 검색어 | 아스트라 출시일 4.0위, 아스트라 가격 7.9위 | 출시와 가격 두 가지로 좁힌다 |

이 글은 `아스트라 출시일`에서 이미 4.0위다. 출시와 가격을 다루는 글로 성격을 굳히고, 사용법 의도는 Phase 1의 새 글로 넘긴다.

본문은 그대로 두고 제목, `metaTitle`, `metaDescription`, 도입부 세 문단만 바꾼다. 11,797자를 다시 쓰지 않는다.

### Phase 3. 자기잠식 해소

`gpt-6-astra-ai-transition-era`가 `아스트라`와 `gpt 아스트라`에서 비교글과 함께 올라오고 있다. 이 글을 AGI 논쟁과 전망 쪽으로 밀어낸다.

| 작업 | 내용 |
|---|---|
| 제목과 메타 | `아스트라` 단독 노출을 줄이고 AGI, 사무직, 전망 축으로 좁힌다 |
| 내부 링크 | 사용법을 찾는 문장에서 Phase 1 새 글로 보낸다 |
| relatedSlugs | 세 글이 서로를 가리키되 역할이 겹치지 않게 정리한다 |

세 글의 역할을 이렇게 나눈다.

| 글 | 맡는 의도 | 대표 검색어 |
|---|---|---|
| 신규 글 | 쓰는 방법 | GPT아스트라, 아스트라사용법, 아스트라 뜻 |
| 비교글 | 출시와 가격 | 아스트라 출시일, 아스트라 가격, openai 아스트라 |
| 전환기글 | AGI와 전망 | 아스트라 agi, 젠슨황 agi |

## 5. 기대 효과

현재 헤드 검색어 세 개 합계는 노출 10,093, 클릭 235, CTR 2.3%다.

같은 클러스터에서 4위권 검색어의 실측 CTR은 17.7%에서 22.2% 사이다. 보수적으로 12%를 적용하면 클릭이 1,200건대가 된다. 순위가 오르면 노출도 함께 늘어나므로 실제 폭은 더 커질 여지가 있다.

다만 이 계산은 순위 상승을 전제로 한 추정이고 실측이 아니다. 검색 결과 1위와 2위를 공식 문서와 위키가 잡고 있어서 3위 위로는 올라가기 어렵다.

## 7. 남은 한계

- 순위 상승 폭은 추정이다. 경쟁 페이지의 갱신과 구글 색인 반영 시점에 따라 달라진다.
- `아스트라` 단독 검색어의 의도 구성비는 측정하지 못했다. 검색 결과 1페이지 구성으로 추정했다.
- SerpApi 결과는 2026-09-14 기준 한 번의 조회다. 검색 결과는 자주 바뀐다.
- 네이버 검색량은 네이버 기준이고 구글 검색량과 다르다. 상대 비교에만 사용했다.

## 9. 문체 교정 기록

2026-09-14에 hongblog 원본 지침(`references/prose-rules.md`, `references/writing-craft.md`)을 대조해 신규 글을 다시 고쳤다.

| 항목 | 고친 내용 |
|---|---|
| 출처 강박 | 본문의 "도움말에 적혀 있습니다", "공식 발표는 밝혔습니다" 형태 11곳을 3곳으로 줄였다. 2026-09-05에 같은 주제 글에서 받은 지적이다 |
| 비유 운용 | 중심 비유를 사원증과 층으로 하나만 두고, 독립 문장으로 띄운 비유 두 곳을 종속절로 바꿔 원개념과 붙였다. "별관에 가깝습니다" 같은 설명조 종결은 지웠다 |
| 제목 | "모델이 보이지 않을 때"라는 절을 "모델 확인 순서"라는 명사구로 바꿨다. 제목은 검색 키워드형 명사구로 쓴다는 규칙을 따랐다 |
| 헤딩 | "회사 계정에서 보이지 않을 때"에 대상이 없어 "회사 계정에서 아스트라가 보이지 않는 이유"로 바꿨다 |
| 비문 | 주어 없는 서술(사용량은 따로 셉니다), 목적어 누락(캐시가 더 크게 줄여 줍니다), 무생물 주어의 타동사(긴 작업이 많이 씁니다) 등 14곳을 고쳤다 |
| highlights | 안내문으로 바꿨던 비교글 항목을 행동 지침으로 되돌렸다. 요약 카드에는 행동 지침만 둔다는 규칙이 있다 |

전환기글의 메타 첫 문장을 AGI 논쟁으로 바꿨다가 되돌렸다. metaDescription과 본문 도입부, JSON-LD의 개체와 표현을 맞추는 규칙이 있는데 본문 도입부는 그대로 두고 메타만 바꿔 정렬이 어긋났기 때문이다. 자기잠식은 relatedSlugs 정리와 나머지 두 글의 역할 분담으로 다룬다.
