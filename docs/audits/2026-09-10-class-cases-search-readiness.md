# Class·Cases 배포 전 SEO / AEO / GEO 점검

검사일: 2026-09-10. 공개 사이트: https://www.digitalmarketer.co.kr. 신규 Cases는 localhost 빌드이며 아직 공개 사이트에서 404다. 배포하지 않았다.

## 판정

- `/class` 전체의 크롤링 차단이나 본문 렌더링 장애는 발견하지 못했다. 현재 클래스 97개 중 Google URL 검사에서 91개 색인, 6개 미색인이다.
- 성과 차이는 실제로 크지만 URL 경로 깊이 때문이라고 단정할 증거는 없다. 홈페이지에서 클래스와 사례는 모두 링크 2단계로 도달한다.
- `/cases` 7개는 배포 전 HTML·링크·메타·사이트맵 검증을 통과했다. 실제 색인과 AI 답변 인용은 배포 전 검증할 수 없다.
- Course 구조화 데이터에 의미상 잘못된 두 항목을 수정했다. 이 오류를 검색 성과 차이의 원인으로 확정하지 않는다.

## 실측 범위

1. Search Console readonly API: 91일(2026-06-08~09-06), 최근28일(08-10~09-06), 직전28일(07-13~08-09). 페이지 차원 전체조회에서 경로별 집계. 25,000행 한도로 조회, 반환량은 한도 미만.
2. URL Inspection API 110개: 클래스 상세97개 전수, 인사이트10개 비교 표본, 클래스 허브/코스3개. Google의 현재 저장된 검사 결과이며 실시간 URL 테스트는 아니다.
3. 공개 URL113개: 클래스97개, 인사이트8개, 허브/robots/사이트맵/신규cases 등8개. `/cases`를 제외한112개 HTTP200. 공개 클래스97개 canonical 자기주소 일치, noindex/X-Robots-Tag 차단 없음, HTML 본문 존재, 공개 사이트맵 등재.
4. 빌드 HTML398개 기존 SEO 감사, 내부 링크 HTML400개 감사. 새로운 검색 회귀검사는 클래스/코스/인사이트/사례/허브314개 대상.
5. Googlebot/OAI-SearchBot 사용자 에이전트 문자열로 대표 URL을 요청했을 때 HTTP200. 실제 크롤러 IP에서의 접근을 보증하는 검사는 아니다. robots.txt는 모든 사용자 에이전트에 `/`를 허용한다.

초기 Python 요청은 로컬 CA 저장소 문제로 실패했다. 인증서 검증을 끄지 않고 certifi CA로 재검사해 위 결과를 얻었다. 이를 사이트 TLS 장애로 판단하지 않았다.

## 검색 성과 비교

아래는 페이지 차원 전체조회 응답을 경로로 묶은 값이다. 검색에 노출된 페이지 수는 현재 색인된 페이지 수와 다르다.

| 91일 상세 페이지 | 클릭 | 노출 | CTR | 노출 가중 평균순위 | 노출 기록 페이지 |
|---|---:|---:|---:|---:|---:|
| Insights | 65,872 | 1,403,360 | 4.69% | 5.9 | 190 |
| Class | 6,827 | 308,473 | 2.21% | 6.7 | 92 |

클래스 상세 최근28일은 3,632클릭/148,642노출, 직전28일은 2,383클릭/99,629노출이다. 클릭은 약52.4%, 노출은 약49.2% 증가했다. 클래스 전체가 최근 악화 중이라는 해석은 맞지 않는다. 다만 클래스 클릭의77.0%가 상위5개 글에 집중돼 있다.

검색어별 예:
- `앤트로픽`: 클래스 글 12,214노출/23클릭, 평균9.2위. 넓은 브랜드 검색어에서 회사 소개 글이 노출되는 경우다.
- `클로드 프로젝트 사용법`: 클래스 글 1,044노출/288클릭, 평균3.9위. 구체적인 사용 목적에 맞는 질문에서는 클래스도 좋은 클릭 반응을 보인다.
- Insights 상위에는 `orca`, `제미나이 스파크`, `codex cli 설치` 등 제품·사용법 검색어가 나타난다.

이는 검색 의도, 주제 수요, 순위와 콘텐츠 범위 차이를 우선 검토할 근거다. 같은 검색어/기기/국가/기간/순위를 통제한 인과 분석이 아니므로 경로별 CTR을 직접적인 품질 점수로 사용하지 않는다. 쿼리×페이지 기존 리포트는5,000행 제한에 도달했으므로 전체 검색어 분포가 아니라 예시로만 사용했다.

기간 표기도 검수했다. 기존 gsc-report.ts는 양 끝 날짜 포함 계산에서 하루를 더 조회하고 있어 수정했다. 이 보고서의 실제 조회범위6/8~9/6은91일로 표기하며, 비교한 두28일 구간은 각각28일이다.

기기·국가 분해 API도 재조회했으나 해당 응답의 합계가 페이지 전체조회와 일치하지 않았다. 페이지 차원을 포함하고 집계방식을byPage로 고정해도 차이가 남아, 기기·국가 수치를 성과 원인 판정에서 제외했다. 원본은 비공개 검수 폴더에 보관했다.

6개 모두 URL 검사 응답에 마지막 크롤링 시각과 Google 선택 canonical이 없었다. `크롤링됨, 현재 색인 안 됨` 상태가 아니므로 내용 품질 때문에 크롤링 후 탈락했다고 단정하지 않는다. 현재 빌드에서 각 글로 들어오는 링크는7~12개로 고아 페이지가 아니다. 공개 사이트와 Google의 저장된 상태 사이의 차이는 남아 있다.

색인된 클래스 표본/전수 결과에서 Google 선택 canonical이 다른 URL인 경우는 발견하지 못했다. 수정일보다 마지막 크롤링이 오래된 클래스6개도 확인했다(교육자 활용, 프롬프트 기초, 인증, 데이터베이스, REST API, CPC). 본문 업데이트가 검색 결과에 반영됐다고 전제하면 안 된다.

## 이번에 수정한 내용

- Course의 `numberOfCredits` 제거. 개념 수를 학점으로 발행하던 오류였고 개념 수는 기존 커리큘럼 ItemList에 유지한다.
- CourseInstance의 고정 `PT1H` 제거. 화면과 같은 계산값으로 `전체 콘텐츠 예상 읽기 N분`을 발행한다.
- 사례 원고 실제 수정일을 `updatedAt`으로 관리하고 Article.dateModified, OG modifiedTime, sitemap.lastmod 및 화면의 수정일을 동기화한다. 공개일을 임의로 만들지 않는다.
- `scripts/check-search-readiness.ts`와 `npm run check:search` 추가. `postbuild`에 연결해 검색 준비 오류가 있으면 빌드가 실패한다.
- canonical1개/자기주소, 차단메타, H1, 설명/OG, 실제 OG 파일, JSON-LD 파싱/제목, 사이트맵, 초기 HTML 본문, 들어오는 링크, 코스시간, 사례수정일을 검사한다.
- 복제 빌드에 잘못된canonical/noindex/본문누락/그림누락/OG수정일 오류를 삽입해 다섯 가지 실패가 실제로 감지되는지 확인했다.

## 남은 작업과 우선순위

**높음 — 미색인6개와 오래된 크롤링6개**
Google Search Console 실시간 URL 테스트로 현재 수집 가능 여부를 확인하고 적절한 URL에 색인 요청. 이후 마지막 크롤링/색인 상태 변화 추적. 이번 검사에서는 읽기 전용 API만 사용했으며 색인 요청이나 사이트맵 제출을 실행하지 않았다. 이 문제를 해결한다며 정상 URL을 다른 경로로 옮기지 않는다.

**높음 — 검색 의도별 클래스 개선**
노출은 많고 클릭이 적은 앤트로픽/모델비교/CAC 등의 검색어를 분리한다. 브랜드 이동 의도와 정보 탐색 의도를 구분한 후 제목과 첫 설명이 해당 질문을 충족하는지 검토한다. 숫자만 보고 클릭 유도 제목으로 바꾸지 않는다. SEO 기초의 `앞에서 ... 봤습니다` 같은 도입은 단독 방문자도 이해할 배경으로 고친다. 특히 “크롤링은 판단이 거의 없다”, “크롤링됐으니 경로가 아니라 내용만 고쳐야 한다” 같은 단정은 별도 사실 검수가 필요하다. 이번 요청은 감사이므로97개 글을 일괄 윤문하지 않았다.

**배포 후 필수 — Cases 실측**
공개7개 HTTP200, 최종 canonical/robots/X-Robots-Tag/사이트맵과 실제 본문 확인 → Search Console 수집/색인 확인 → 실무 질문별 답변에서 출처URL 채택 여부 기록. 검색엔진/질문/실행일/인용URL을 남기고 반복 측정한다. 한 번의 답변 결과로 인용률을 확정하지 않는다.

**중간 — 사례와 학습 자료의 문맥 연결**
사례별 관련 개념·교육 글을 내용상 필요한 위치에서 연결하고, 관련 교육/개념 글에서도 적합한 사례로 연결한다. 현재는 허브·푸터·관련 사례 링크로 발견이 가능하다. 임의의 대량 링크 추가보다 독자의 다음 질문에 맞는 연결을 우선한다.

**낮음/보류**
사례별 공유 이미지, 추가 장식, 모든 글의FAQ 증설, llms.txt 같은 별도AI파일, 스키마 유형 무작정 추가, URL을/class에서/insights로 일괄 이동. 현재 관측 문제를 직접 해결한다고 볼 근거가 부족하다. 13개 목업은 읽을 수 있는 HTML 보조자료이며 독립적인 성과 증빙이 아니다.

## 공식 기준

- [Google AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features): 색인·스니펫 자격, 텍스트/내부링크, 별도AI마크업 불필요. 노출 보장 없음.
- [크롤링 가능한 링크](https://developers.google.com/search/docs/crawling-indexing/links-crawlable): 실제 href가 있는 연결과 문맥상 관련 링크.
- [Article 구조화 데이터](https://developers.google.com/search/docs/appearance/structured-data/article): 작성자·수정일 등 페이지에 맞는 데이터.
- [numberOfCredits](https://schema.org/numberOfCredits), [courseWorkload](https://schema.org/courseWorkload): 학점과 예상 학습량의 의미.

GSC 수치는 Google 검색 성과다. AEO/GEO의 실제 답변 인용 성과를 측정한 값이 아니다. 검색 색인과 AI 인용은 구분해서 판정한다.
