# 뉴스레터 전체 계획 (스티비 스탠다드 기준)

작성 2026-08-16, 갱신 2026-08-17. 구독자 정보 설계, 웰컴 메일, 온보딩, 전략, 인증 방식을 한 문서에
묶는다.

> **기준 문서는 `docs/superpowers/plans/2026-08-16-newsletter-ai-practice-history.md`다.**
> 이 문서는 배경 설명과 요금 근거를 담고, 구현 작업 목록과 세부 결정은 기준 문서를 따른다.
> 2026-08-17에 아래 결정들을 기준 문서에 맞춰 갱신했다.

## 2026-08-17 갱신 내역

첫 판(2026-08-16)에서 뒤집힌 결정들이다. 이전 판을 참고한 작업물이 있으면 여기부터 맞춘다.

| 항목 | 이전 판 | 확정 |
|---|---|---|
| 실습 공간 | GA4 Edu (별도 브랜치) | **AI-Practice** (main 배포됨) |
| 로그인 시스템 | 1차 범위, 매직링크 설계 | **후속 범위.** 1차는 웰컴 체크인용 일회용 토큰만 |
| goal 허용값 | 6개 | **4개**: `ai-flow`, `ai-work`, `content-marketing`, `build-automation` |
| 이름 수집 | 선택 항목 | **받지 않는다.** 이메일과 동의만 |
| 테이블명 | `subscriber`, `auth_token`, `survey_answer` | `newsletter_subscribers`, `newsletter_checkins`, `newsletter_tokens` |
| 발행 주기 | 격주 1회 | **주 1회**로 시작 |
| DB | 자체 Postgres 신규 상정 | **기존 Neon 인스턴스**에 뉴스레터 테이블 추가 |
| 웰컴 메일 | Neo-Brutalism 라이트 | **AI-Practice 미니멀 다크** 테마로 재작성 완료 |

## 전제와 현재 상태

요금은 [부록](#부록-요금-근거)에서 확정했다. 스탠다드 최소 구간 월 8,900원으로 시작하고, 구독자가
늘면 구간이 올라간다. 발송 횟수는 무제한이라 과금 축은 구독자 수 하나다.

스탠다드에서 열리는 기능은 이렇다.

| 기능 | 스탠다드 | 비고 |
|---|---|---|
| 구독자 API (조회, 추가, 수정) | 가능 | 자체 폼과 원장 동기화의 전제 |
| 웹훅 (구독, 정보변경, 수신거부 등 6종) | 가능 | Neon 동기화 |
| 자동 이메일 (구독자 추가 트리거) | 가능 | 온보딩 드립 |
| 사용자 정의 필드 | 워크스페이스당 99개 | 여유 충분 |
| 이메일 API, 그룹 API | 불가 | 프로부터. 필요 시 Resend로 처리 |

이미 되어 있는 것과 빠진 것을 나눠 둔다.

| 상태 | 항목 |
|---|---|
| 배포됨 | 스티비 구독 페이지, CTA 5곳 (내비, 모바일 내비, 홈, 글 하단, 푸터), `click_newsletter` 이벤트 코드 |
| 작성됨 | 웰컴 메일 (다크 테마, goal 4개, `CHECKIN_TOKEN` 자리표시자) |
| 재작성 대상 | 온보딩 초안 3통 (day1, day2, day3). GA4 교육 중심이라 AI 뉴스레터 전략에 맞지 않음 |
| 빠짐 | 스티비 결제, Neon 뉴스레터 스키마, 체크인 API, 웹훅 수신, 자체 폼, 개인정보처리방침, day7 메일 |

`click_newsletter`의 GTM 게시 상태는 기록이 서로 다르다. 기준 문서는 GTM v12에서 게시됐다고 적었고,
2026-08-15 기록은 미게시였다. 코드를 만들기 전에 GTM 컨테이너에서 회귀 확인만 하면 된다.

## 1. 구독자에게 받을 정보

원칙은 하나다. **가입 순간에는 이메일과 동의만 받고, 나머지는 클릭으로 채운다.** 이름도 받지
않는다. 항목이 늘수록 전환율이 떨어지고, 이름이 필요해지면 별도 프로필 단계에서 다시 검토한다.

### 가입 시점에 받는 것

2026-08-17에 사용자 결정으로 선택 항목 3개가 늘었다. 가입 진입점도 스티비 페이지에서
**자체 폼 팝업**으로 바꾼다 (스탠다드 구독자 API 실측 확인 완료).

| 항목 | 필수 여부 | 이유 |
|---|---|---|
| 이메일 | 필수 | 전부 |
| 광고성 정보 수신 동의 | 필수 체크 | 정보통신망법. `consent_version`과 `consented_at`을 Neon에 남긴다 |
| 산업군, 직무, 연차 | 선택 (드롭다운) | 세그먼트 발송과 콘텐츠 기획 근거. 필수로 걸면 전환율이 떨어지므로 선택으로 둔다 |

### 시스템 필드 (스티비 사용자 정의 필드)

| 키 | 뜻 | 채우는 시점 |
|---|---|---|
| `goal` | 구독 이유 | 웰컴 메일 선택지 클릭 |
| `signup_source` | 구독한 지점 | 가입 시 자동 |
| `stibee_id` | 스티비 구독자 식별자 | 동기화 시 |
| `welcome_token` | 웰컴 체크인용 서명 값 | 구독자 생성 시. Neon에는 해시만 저장 |

`goal` 허용값은 `ai-flow`, `ai-work`, `content-marketing`, `build-automation` 네 개로 고정한다.

### 구독 진입점

지금 CTA는 스티비 페이지로 나간다. 스탠다드 결제 후 자체 폼으로 바꾸면 이탈이 없고, 디자인이
통일되고, `signup_source`가 남고, 구독자 원장이 Neon에 생긴다. `/api/subscribe` 하나에서 Neon
저장과 스티비 구독자 API 호출을 같은 요청으로 처리한다.

> **결제 후 시험할 것.** API로 구독자를 추가할 때 스티비가 구독 확인 메일을 보내는지, 즉시 구독
> 상태가 되는지는 공식 문서에서 확인되지 않았다. API 키를 받은 뒤 직접 호출해 확인하고 결과를
> `docs/newsletter/stibee-field-contract.md`에 기록한다.

## 2. 웰컴 뉴스레터

다크 테마 판이 `docs/newsletter/drafts/day0-welcome.html`에 있다. 제목 후보는 "AI를 다 따라갈
필요는 없습니다"이고, 뉴스레터가 무엇을 보내는지 설명한 뒤 관심 주제 네 개 중 하나를 고르게 한다.

선택지 클릭이 처리하는 일은 이렇다.

- 일회용 서명 토큰 검증 (로그인이 아니라 이 클릭 한 번만 인증)
- `goal`을 `newsletter_checkins`와 구독자 레코드에 기록
- 착지 화면에서 선택 저장 사실과 다음 메일 예고를 보여 줌

토큰은 착지 즉시 폐기하고 주소창에서 지운다. 만료와 재사용은 거절하고, 같은 클릭을 여러 번 눌러도
한 번만 집계한다. `CHECKIN_TOKEN` 자리표시자는 Neon 연동 뒤 스티비 메일머지로 교체한다.

발송은 스티비 자동 이메일로 걸고, 트리거는 구독자 추가, 지연 없이 즉시로 둔다. 토큰 필드가 채워진
뒤에 발송되도록 순서를 확인한다.

## 3. 온보딩 콘텐츠

첫 주 안에 세 가지를 만든다. 여기가 무엇을 보내는 곳인지 각인, 참여 클릭 1회, 회신 경험 1회다.

| 일차 | 상태 | 할 일 |
|---|---|---|
| 0 (웰컴) | 다크 테마 작성 완료 | 토큰 연결만 남음 |
| 1 | GA4 중심 구판 | AI 전략에 맞춰 재작성 |
| 2 | GA4 중심 구판, 가상 수치 | 재작성. 가상 수치는 실측으로 갈거나 예시임을 밝힘 |
| 3 | GA4 중심 구판, 가상 진행률 카드 | 재작성 |
| 7 | 미작성 | 첫 주 마무리 메일 신규 작성 |

각 메일은 결론, 한 가지 적용 방법, 다음 행동 순서를 지킨다. 내부 기획 비유(운동, 코치, 헬스장,
교재, 인바디)는 구독자에게 보내는 문장에 쓰지 않는다.

## 4. 뉴스레터 전략

### 대상과 약속

대상은 AI 시대가 겁나지만 준비하고 싶은 사람이다. 읽고 나서 "그래도 내가 적당히 잘 따라가고 있고,
여기 도움을 받았구나"라는 감정이 남는 것이 목표다. 그래서 매 호는 결론을 먼저 주고, 바로 확인할
수 있는 작은 선택이나 사례를 하나 제공한다.

### 채널 역할 (내부 기획용)

| 채널 | 내부 역할 | 구독자에게 보이는 형태 |
|---|---|---|
| 이메일 | 코치 | 다음에 읽을 내용과 바로 적용할 방법을 안내하는 뉴스레터 |
| 블로그 | 교재 | 검색 가능한 배경 설명과 상세 해설 |
| AI-Practice | 헬스장 | 브라우저에서 직접 따라 하는 실습 환경 |

### 존재 이유

검색으로 들어온 방문자가 글을 한 번 읽고 떠나는 현상이 두드러진다. 방문자를 다시 부를 장치가
사이트 안에 없고, 뉴스레터가 유일한 재방문 채널이다.

### 발행 주기와 고정 코너

주 1회로 시작한다. 제작 부담이 커져 격주로 바꾸면 편집 캘린더와 구독자 안내 문구를 함께 갱신한다.

고정 코너는 넷이다: 이번 호 핵심, 참여 링크, 지난 참여 결과, 자세한 설명 링크.

### 호환성 원칙

국내 구독자는 네이버 메일 비중이 커서 이미지와 자바스크립트를 기대할 수 없다. 표 레이아웃과
인라인 스타일만 쓴다.

### 측정

| 지표 | 어디서 보는지 |
|---|---|
| 오픈율, 클릭률 | 스티비 |
| 체크인 참여율 | Neon (`newsletter_checkins`) |
| 구독 지점별 전환 | GA4 `click_newsletter`의 location |
| 목표별 선택 분포 | Neon |

첫 4주 후 제목, 선택지, 발송 간격을 한 번에 하나씩 개선한다.

## 5. 인증 방식: 1차는 체크인 토큰, 로그인은 후속

**매직링크 로그인과 AI-Practice 실습 잠금은 1차 범위에서 뺐다.** 1차는 웰컴 메일 클릭 한 번을
검증하는 일회용 토큰(`newsletter_tokens`)만 만든다.

로그인이 필요해지는 시점(실습 잠금, 진도 저장)이 오면 `newsletter_tokens`와 분리된 인증 세션
설계를 다시 검토한다. 그때 참고할 이전 판의 설계 요지는 이렇다.

- 비밀번호 없는 매직링크. 토큰은 JWT가 아니라 DB 저장 일회용 (재사용 차단)
- 세션은 HttpOnly, Secure, SameSite=Lax 쿠키
- 잠금은 실습 데이터를 API로 분리하고 쿠키가 있을 때만 응답하는 방식. 설명 본문은 색인을 위해
  계속 연다. 미들웨어로 페이지 전체를 막으면 검색 노출 자산을 잃는다

### 테이블 세 개 (기준 문서 확정안)

| 테이블 | 핵심 컬럼 |
|---|---|
| `newsletter_subscribers` | email, status, signup_source, consented_at, consent_version, stibee_id, goal |
| `newsletter_checkins` | subscriber_id 또는 email, goal, campaign, clicked_at, user_agent_hash |
| `newsletter_tokens` | token_hash, subscriber_id, purpose, expires_at, used_at |

이메일은 정규화해 unique 제약을 두고, 수신거부와 삭제를 보존하도록 status와 시각 컬럼을 둔다.
기존 Neon 테이블 15개는 사용처 확인 전에 삭제하지 않는다.

### 법적으로 빠진 것

**개인정보처리방침이 없다.** 이메일을 Neon에 저장하는 순간 필요하다. 저장소의 `gtm-agent-privacy`는
별개 도구용이라 쓸 수 없다. 가입 폼의 동의 문구와 문구 버전 기록, 수신거부의 웹훅 동기화도 함께
챙긴다.

## 실행 순서

작업 목록과 완료 기준은 기준 문서의 Task 1에서 7을 따른다. 요지만 옮기면 이렇다.

1. 스티비 결제 후 필드와 API 동작 확인 (`stibee-field-contract.md` 기록)
2. Neon 기존 테이블 인벤토리 문서화, 뉴스레터 마이그레이션 생성
3. 체크인 API와 착지 화면 구현
4. 웰컴 메일의 실제 토큰 연결
5. 구독과 웹훅 동기화 구현
6. 온보딩 초안 재작성과 스티비 등록 (구독 직후, 1일차, 3일차, 7일차)
7. GA4/GTM 측정과 4주 운영 리뷰

결제 전에는 API 코드를 만들기보다 스티비 필드 계약과 체크인 URL 규칙을 먼저 확정한다.

## 부록: 요금 근거

| 구독자 수 | 스티비 스탠다드 | Resend | 합계 |
|---|---|---|---|
| 500명 이하 | 8,900원 | 무료 | 월 8,900원 |
| 2,500명까지 | 2만 원대 | 무료 유지 가능 | 2만 원대 |
| 5,000명 | 39,000원 | Pro 약 28,000원 | 67,000원 |
| 10,000명 | 52,000원 | Pro 약 28,000원 | 80,000원 |

Resend는 후속 범위인 매직링크 로그인을 붙일 때만 필요하다. 무료 티어는 월 3,000통에 더해 하루
100통 제한이 걸리므로, 하루 70통에서 80통이 찍히기 시작하면 Pro로 올린다.

주 1회 발송이어도 스티비 과금 축은 구독자 수라 비용이 늘지 않는다. 주 300명에서 400명에게 보내고
온보딩 드립을 더해도 500명 이하면 월 8,900원 그대로다.
