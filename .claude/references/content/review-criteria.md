# 검수 기준

## 1. 사실 확인 (Fact Check)

### CRITICAL 판정 기준
- 명백히 잘못된 기술 설명 (예: "Python은 컴파일 언어입니다")
- 출처 없는 구체적 통계 (예: "90%의 기업이 도입했습니다")
- deprecated/변경된 API/기능 설명
- 법적 문제 가능성 있는 표현

### WARNING 판정 기준
- 모호하거나 과장된 표현 (예: "최고의", "유일한")
- 검증 불가능한 주관적 수치
- 오래된 정보 가능성 (2년 이상 된 도구/서비스 버전)
- **과장된/극적 은유 표현** (예: 변신, 마법처럼, 놀랍게도, 놀라운, 혁명적, 획기적, 차원이 다른, 완전히 새로운, 기적처럼, 엄청나게, 순식간에(강조 부사 용법))
  - 판단 기준: 해당 표현이 일상 대화에서 쓰이는가, 아니면 광고 카피·영화 나레이션 같은가
  - 일상적 실물에 뿌리 둔 은유(요리/집/창고 등)는 허용

### 수정 가이드
- 통계: 출처 추가 또는 "약 N%로 알려져 있습니다" 형태로 완화
- 기술 설명: 정확한 설명으로 교체
- 과장 표현: 객관적 표현으로 변경
- 과장 은유: 실제 동작·현상을 그대로 서술하는 문장으로 교체 (예: "노트북이 서버로 변신한다" → "노트북에서 작은 서버 프로그램이 실행된다")

## 2. 논리 일관성

### CRITICAL 판정 기준
- 글 내 자기 모순 (A 주장 후 not-A 결론)
- 전제 없는 결론 도출
- 인과관계 오류 (상관관계를 인과로 서술)

### WARNING 판정 기준
- 논리 비약 (중간 과정 생략)
- 일반화 오류 (하나의 사례로 전체 결론)
- 전환 부재 (맥락 없이 주제 전환)

### 수정 가이드
- 모순: 하나의 관점으로 통일 또는 양쪽 관점 명시
- 비약: 중간 논리 보충
- 전환: "이와 관련하여", "한편으로는" 등 연결어 추가

## 3. 구조 분석

> **FAQ 예외**: FAQ는 헤딩 없는 대화체(150-300단어)가 정상 구조입니다. 아래 기준 중 서론/결론 부재, 헤딩 없음, 짧은 본문은 FAQ에서 WARNING/CRITICAL이 아닙니다. 단, FAQ가 300단어를 초과하면 WARNING입니다.

### CRITICAL 판정 기준
- 서론/결론 부재 (FAQ 제외)
- 헤딩 계층 혼란 (H3 아래에 H2) (FAQ 제외)
- 전체 구조가 주제에서 이탈

### WARNING 판정 기준
- 너무 긴 문단 (7문장 이상)
- 너무 짧은 섹션 (1문단만) (FAQ 제외)
- 헤딩과 내용 불일치 (FAQ 제외)
- 결론이 본론 내용을 반영하지 않음 (FAQ 제외)
- FAQ가 300단어 초과

### INFO 판정 기준
- H3 추가 권장 (긴 H2 섹션) (FAQ 제외)
- 불릿 리스트로 변환 권장
- 시각적 구분 요소 추가 권장 (표, 코드블록)

## 4. 한국어 교정

### 맞춤법 (CRITICAL)

| 틀린 표현 | 올바른 표현 | 설명 |
|----------|-----------|------|
| 됬다 | 됐다 | '되었다'의 축약 |
| 안됀다 | 안 된다 | 부정 부사 + 띄어쓰기 |
| 왠지 | 웬지 | '왜인지'가 아닌 '웬' |
| 어의없다 | 어이없다 | '어이'가 올바른 표현 |
| 금새 | 금세 | '금시에'의 준말 |
| 오랫만에 | 오랜만에/오래간만에 | |
| 몇일 | 며칠 | |
| 설레임 | 설렘 | 명사형 |

### 띄어쓰기 (WARNING)

| 틀린 표현 | 올바른 표현 | 규칙 |
|----------|-----------|------|
| 할수있다 | 할 수 있다 | 의존명사 '수' |
| 할때 | 할 때 | 의존명사 '때' |
| 할것이다 | 할 것이다 | 의존명사 '것' |
| 해야될 | 해야 될 | 보조용언 띄어쓰기 |
| 갈수록 | 갈수록 | 부사 (붙여씀) |
| 더이상 | 더 이상 | 관형사 + 명사 |

### 외래어 표기 (WARNING)

| 틀린 표현 | 올바른 표현 |
|----------|-----------|
| 컨텐츠 | 콘텐츠 |
| 메세지 | 메시지 |
| 어플 | 앱 |
| 데이타 | 데이터 |
| 악세서리 | 액세서리 |
| 카테고리 | 카테고리 (O) |

### 어투 일관성 (WARNING)

**혼용 패턴 탐지:**
- "~입니다" + "~이다" 혼용
- "~합니다" + "~한다" 혼용
- "~세요" + "~해라" 혼용

**규칙:** 한 글 내에서 하나의 어투만 사용

### 문장부호 (INFO)

- 리스트 항목: 완전한 문장이면 마침표, 아니면 생략 (통일)
- 쉼표: 접속 부사 뒤 ("그러나," "따라서,")
- 소괄호: 부연 설명용, 한 문장에 2회 이상 사용 지양
- 큰따옴표: 인용, 강조 시 사용
- 작은따옴표: 따옴표 안 따옴표

## 5. 퀴즈 검수

### CRITICAL 판정 기준
- correctIndex가 options 배열 범위를 벗어남
- 질문이 글 내용과 무관
- 정답이 명백히 잘못됨

### WARNING 판정 기준
- Post인데 단순 암기형 질문 (의견 분리형이어야 함)
- 하나의 선택지가 너무 명백하게 정답 또는 오답
- explanation이 불충분 (1문장 이하)
- 선택지가 2개 미만 또는 5개 초과

### INFO 판정 기준
- 더 나은 질문 표현 제안
- 선택지 순서 조정 권장

## 심각도 기준 요약

| 심각도 | 기준 | 예시 |
|--------|------|------|
| **CRITICAL** | 독자에게 잘못된 정보 전달 가능 | 사실 오류, 자기 모순, 심각한 맞춤법 |
| **WARNING** | 글의 품질을 떨어뜨림 | 띄어쓰기, 외래어, 논리 비약, 구조 문제 |
| **INFO** | 개선하면 더 좋아지는 부분 | 구조 개선 제안, 시각 요소 추가 권장 |
