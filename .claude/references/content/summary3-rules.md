# 3줄 요약 작성 규칙

인사이트, 클래스, 코스 상세 페이지 본문 위에 붙는 3줄 요약(frontmatter `summary3`)을 쓸 때 적용한다.
2026-08-29 사용자 검토로 확정했다.

## 원칙

**3줄 요약은 본문을 대체하는 요약이다. 본문을 소개하는 글이 아니다.**

읽는 사람이 세 줄만 읽고도 그 글의 핵심을 손에 넣어야 한다. 본문을 읽어야 뜻이 통하는 문장,
글이 무엇을 다루는지 알려 주는 문장은 요약이 아니다.

| 잘못 | 옳음 |
|---|---|
| AI를 사용하는 5가지 방법의 차이점과 용도를 초보자 눈높이로 정리했습니다. | 웹이든 앱이든 터미널이든 달라지는 것은 AI 모델이 아니라 접근 방법입니다. |
| Google 공식 도움말에 따르면 다음 한도가 안내되어 있습니다. | 개발자 앱 등록과 검수, 액세스 토큰 관리가 없어져 계정 로그인만으로 5분에서 10분이면 연결됩니다. |
| 주의할 점 : "Claude"는 서비스 이름이고, "Opus"가 모델 이름입니다. | 2026년 8월 기준 읽기 전용 도구만 57개이므로 처음에는 전부 승인 필요로 두는 편이 안전합니다. |

## 세 줄의 층위

세 줄이 서로 다른 것을 담는다. 같은 이야기를 세 번 하지 않는다.

| 줄 | 담을 것 |
|---|---|
| 1줄 | 대상이 무엇인지. 정의와 핵심 조건(누가, 언제, 규모) |
| 2줄 | 작동 방식이나 핵심 수치 |
| 3줄 | 실무 판단, 주의점, 비슷한 것과의 차이 |

글의 성격에 따라 층위를 바꿔도 되지만, 세 줄이 서로 다른 층위를 맡는다는 원칙은 유지한다.

## 형식

- **한 줄은 한 문장.** 짧은 선언을 앞에 붙여 두 문장으로 만들지 않는다. 그 선언은 뒤 문장에 녹인다
  - 잘못: `방법은 다섯입니다. 웹 챗봇, 데스크톱 앱, 터미널 CLI 순으로 어려워집니다.`
  - 옳음: `웹 챗봇과 데스크톱 앱, 터미널 CLI, 코딩 도구 탑재, MCP 연동 순으로 어려워집니다.`
- **길이 제한은 없다.** 핵심을 담느라 길어지는 것은 허용한다. 다만 부연 설명과 두 번째 사례,
  본문에서 확인하면 되는 세부는 덜어낸다
- **비유를 쓰지 않는다.** 세 줄 안에는 비유를 풀 자리가 없어서 뜻이 흐려진다. 직접 서술로만 쓴다
  - 잘못: `클라우드 API가 장비를 빌려 쓰는 쪽이라면 로컬 모델은 그 장비를 집에 들여놓는 쪽입니다.`
  - 옳음: `전체 정밀도판은 64GB, 압축판은 32GB와 24GB를 요구하며 성능 손실은 각각 0.2%와 1.0%입니다.`

## 금지

| 항목 | 예 |
|---|---|
| 메타 서술 | 정리했습니다, 다룹니다, 알아봅니다, 살펴봅니다, 소개합니다, 담았습니다 |
| 뒤를 가리키는 문장 | 다음과 같습니다, 아래와 같습니다, 다음 한도가 안내되어 있습니다 |
| 도입부 상황 묘사 | 보고서를 열었을 때 건수가 늘어 있으면 먼저 문제가 생겼다고 생각하게 됩니다 |
| 비유 | ~듯, ~인 셈입니다, 빗대면, 비유하면 |
| 목록 머리말 | 주의할 점 :, 정리하면 : |

## 필수

- 줄마다 확인 가능한 사실(수치, 이름, 조건)이 하나 이상 들어간다
- 앞뒤 문맥 없이 그 줄만 떼어 읽어도 뜻이 통한다
- 세 줄이 서로 다른 층위를 맡는다

## 문체는 본문과 같은 기준

3줄 요약도 hongblog 글쓰기 지침을 그대로 따른다. 요약이라고 느슨하게 쓰지 않는다.

- `check:prose` HARD 0건, `check-literary.mjs` HARD 0건
- em dash와 가운뎃점 0건
- 쉼표 3개 이하. 항목 나열이 들어가는 줄도 3개를 넘기지 않게 접속으로 묶는다
- 국립국어원 외래어 표기법. `데스크탑`이 아니라 `데스크톱`
- 낭독 검수로 호응과 주어를 확인한다. 실제로 교정한 사례는 아래와 같다

| 고치기 전 | 고친 뒤 | 사유 |
|---|---|---|
| 같은 Claude 모델을 쓸 수 있고 달라지는 것은 | 웹이든 앱이든 터미널이든 달라지는 것은 | 한 문장에 주어가 둘이라 호응이 깨짐 |
| Meta MCP는 통로로 설정 변경을 맡깁니다 | 설정 변경을 맡길 수 있는 메타 공식 연결 통로입니다 | MCP가 맡기는 것이 아니라 사용자가 맡김 |
| 전체 정밀도는 64GB | 전체 정밀도판은 64GB를 요구하며 | 정밀도가 64GB인 것이 아님 |
| 맥에서 돌고 | 맥에서 돌아가고 | 구어체 |
| 시작 조건과 단계와 변수로 | 시작 조건과 단계, 변수로 | 같은 조사 3연속 |
| 색인에 손해가 됩니다 | 색인에 불리합니다 | 군더더기 |

## 검사

```bash
npx tsx scripts/check-summary3.ts content/insights/{slug}.md   # 파일 하나
npx tsx scripts/check-summary3.ts --all                        # 전체
```

`summary3`가 없으면 `src/lib/summary.ts`가 본문에서 자동으로 뽑는다. **자동 추출은 이 규칙을
만족하지 못한다.** 도입 문장과 소제목 구간 첫 문장을 그대로 가져오기 때문에 메타 서술과 뒤를
가리키는 문장이 섞인다. 자동 추출은 `summary3`를 아직 쓰지 않은 글이 빈 채로 나가지 않게 하는
임시 장치이고, 품질이 필요한 글은 `summary3`를 직접 적는다.

## 통과 예시

2026-08-29에 사용자 승인을 받은 5세트다. 새 요약을 쓸 때 이 수준을 기준으로 삼는다.

**AI를 쓸 수 있는 방법 5가지**

1. 웹이든 앱이든 터미널이든 달라지는 것은 AI 모델이 아니라 접근 방법입니다.
2. 웹 챗봇과 데스크톱 앱, 터미널 CLI, 코딩 도구 탑재, MCP 연동 순으로 어려워집니다.
3. 글쓰기는 웹 챗봇, 파일 작업은 데스크톱 앱, 코딩과 자동화는 터미널 CLI, 업무 도구 안에서는 MCP를 씁니다.

**서치콘솔 크롤링됨 항목에 JS 파일이 많을 때**

1. 이 항목에 쌓이는 URL은 대부분 페이지가 아니라 구글이 화면을 그려 보려고 받아 간 JS 파일과 CSS 파일입니다.
2. 한 사이트에서는 155건 가운데 144건이 파일이었으므로 건수가 아니라 URL 목록을 내려받아 페이지만 골라내야 합니다.
3. 정적 파일을 robots.txt로 막으면 목록에서는 사라지지만 구글이 화면을 그리지 못해 색인에 불리합니다.

**메타 뮤즈 글리머 로컬 실행 조건**

1. 뮤즈 글리머는 메타가 2026년 8월 10일 Apache 2.0으로 공개한 파라미터 296억 개 로컬 에이전트 모델입니다.
2. 전체 정밀도판은 64GB, 압축판은 32GB와 24GB를 요구하며 성능 손실은 각각 0.2%와 1.0%입니다.
3. 24GB판은 RTX 4090이나 통합 메모리가 넉넉한 맥에서 돌아가고 M4 Max 기준 초당 37.8토큰이 나옵니다.
