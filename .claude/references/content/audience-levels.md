# 읽는 사람 5부류 기준표: 제품을 만든 비마케터의 마케팅 이해 범위와 관심사

글을 쓰기 전에 **누구를 향해 쓰는지**를 정하는 기준이다. 2026-08-25 기준으로 잡았고 `blog-topic-creator`, `write-insight`, `seo-title-creator`, `sns-writer`가 공통으로 쓴다.

## 이 기준표가 생긴 이유

AI가 코딩과 디자인과 문서 작업을 대신해 주면서 자기 제품을 만들고 직접 운영하는 사람이 많아졌다. 이들 대부분이 만드는 일보다 알리는 일을 어려워한다. 원인은 두 가지다.

- **자기 제품이 좋아 보이는 편향.** 만든 사람 눈에는 쓸모가 자명해서, 알리지 않아도 알아볼 거라고 기대한다.
- **마케팅을 향한 막연한 기대.** 광고 한 번, 인플루언서 한 명, 바이럴 한 방으로 풀릴 거라는 기대가 있고, 그 기대가 깨지는 순서대로 사람이 이동한다.

그래서 이 기준표는 직업 마케터의 경력 연차가 아니라 **알리는 일에서 어디까지 겪어 봤는지**로 나눈다. 직업 마케터는 3부류부터 들어오고, 부류마다 어디에 해당하는지 대표 인물에 적었다.

## 부류 구분의 축

축은 **어떤 기대가 깨졌는지**다. 기대가 깨질 때마다 다음 부류로 옮겨 가고, 궁금해하는 것과 찾는 도구가 함께 바뀐다.

| 부류 | 이름 | 한 줄 정의 | 대표 인물 | 갖고 있는 기대 | 관심 툴 | 관심 전략 | 관심 스킬 |

## 1부류: 만든 사람

### 이해하고 있는 것

- 인스타그램과 네이버와 유튜브에 각각 광고가 있다는 것
- 검색하면 위에 나오는 글이 유리하다는 것
- 조회수와 팔로워와 좋아요가 성과 지표라는 감각
- AI로 소개 글과 이미지를 만들 수 있다는 것

### 궁금해하는 것

- 만든 것을 어디에 올려야 사람이 보는지
- 소개 글을 어떻게 써야 하는지, AI에 어떻게 시키면 되는지
- 광고비가 얼마나 드는지, 소액으로도 되는지
- 도구 이름을 들었을 때 그것이 무엇이고 무료인지 (예: `GA4가 뭔가요`, `GTM 설치`)
- 전문 용어의 뜻 (전환, CPC, 리타게팅, 퍼널)
- 다른 메이커는 어떻게 첫 사용자를 얻었는지

### 궁금해하지 않는 것

- 측정의 정확도를 다루는 주제 (기여 모델, 증분 측정, 서버사이드 태깅)
- 도구 간 미세한 차이 (탐색 보고서 세그먼트 조건, 트리거 우선순위)
- 플랫폼 정책 변경의 배경
- 광고 계정 구조

### 관심 툴과 전략과 스킬의 깊이

| 구분 | 내용 | 깊이 |
|---|---|---|
| 툴 | 챗GPT, 클로드, 제미나이 | 소개 문장과 랜딩 카피를 시키는 수준. 프롬프트 한 줄 |
| 툴 | 노션, 프레이머, 버셀 | 랜딩 페이지 한 장을 무료로 올리는 수준 |
| 툴 | 인스타그램, 쓰레드, X | 개인 계정에 출시 글을 올리는 수준 |
| 툴 | 디스콰이엇, 프로덕트헌트, 오픈채팅 | 소개 글을 한 번 올리는 수준 |
| 전략 | 출시 알림, 지인 공유, 커뮤니티 소개 글 | 한 번 알리고 반응을 기다린다 |
| 스킬 | 한 줄 소개, 첫 화면 문장, 대표 화면 하나 | 기능 나열을 사용자의 문제 문장으로 바꾸는 것이 전부다 |

### 기대가 깨지는 계기

올렸는데 조용하다. 지인 몇 명이 좋다고 하고 끝난다. 여기서 "좋으면 퍼진다"가 깨지면 2부류로 간다.

### 검색하는 말의 형태

`사이드 프로젝트 홍보`, `앱 출시 알리기`, `랜딩 페이지 무료`, `GA4 뭐야`, `AI 마케팅 도구 추천`처럼 대상이 일반명사거나 도구 이름 하나에 `뜻`, `무료`, `추천`이 붙는다.

### 맞는 글 형태

용어 정의 클래스, 도구 소개와 무료 플랜 정리, 첫 사용자를 얻는 순서 안내. 정의 문장이 첫 줄에 있어야 하고 비유는 실물 하나로 고정한다.

## 2부류: 올려 본 사람

### 이해하고 있는 것

- 출시 글 하나로는 아무 일도 일어나지 않는다는 것
- 광고 관리자와 서치콘솔에 로그인해 숫자를 읽는 법
- 캠페인, 광고 세트, 광고의 3단 구조
- 클릭률과 전환율의 뜻
- UTM 링크를 만드는 법 (뜻은 몰라도 만든다)

### 궁금해하는 것

- 소액 광고로 반응을 볼 수 있는지, 얼마부터 의미가 있는지
- 네이버 블로그와 인스타그램과 쓰레드 가운데 어디에 힘을 줘야 하는지
- 검색에 걸리려면 무엇을 해야 하는지
- 광고 관리자와 GA4의 숫자가 왜 다른지
- 설정 화면에서 어떤 값을 골라야 하는지 (입찰 전략, 전환 이벤트, 잠재고객)
- AI로 콘텐츠를 매일 올리면 효과가 있는지
- 인플루언서나 협찬이 값을 하는지

### 궁금해하지 않는 것

- 측정 구조를 처음부터 설계하는 일 (데이터 레이어, 이벤트 분류 체계)
- 채널 사이에서 예산을 옮기는 판단
- 도구 벤더의 로드맵이나 API 변경
- 리텐션과 온보딩 (아직 사용자가 없다)

### 관심 툴과 전략과 스킬의 깊이

| 구분 | 내용 | 깊이 |
|---|---|---|
| 툴 | 메타 광고, 네이버 검색광고, 구글 애즈 | 게시물 홍보와 검색광고 하나를 소액으로 돌리는 수준 |
| 툴 | GA4, 서치콘솔 | 설치하고 방문 수와 노출 수를 보는 수준 |
| 툴 | 네이버 블로그, 유튜브 쇼츠, 쓰레드 | 주기적으로 올리기 시작하는 수준 |
| 툴 | 챗GPT, 클로드 | 콘텐츠와 광고 문구를 대량으로 뽑는 수준 |
| 전략 | 소액 광고 테스트, 검색어 하나 잡기, 꾸준한 게시, 협찬 | 채널을 하나씩 시도해 보고 안 되면 다음으로 옮긴다 |
| 스킬 | 타깃 한 문장, 가치 제안, 검색어 조사, 광고 문구 3개 | 누구에게 무엇을 말할지가 처음 생긴다 |

### 기대가 깨지는 계기

광고비를 썼는데 클릭은 있고 가입은 없다. 콘텐츠를 두 달 올렸는데 방문이 제자리다. "광고 돌리면 온다"가 깨지면 3부류로 간다.

### 검색하는 말의 형태

증상 문구가 많다. `GA4 전환 안 잡힘`, `메타 광고 전환 GA4 차이`, `session_source_medium not set`, `구글애즈 전환 추적 설정`, `쓰레드 도달 안 나옴`. 화면 이름과 오류 메시지를 그대로 친다.

### 맞는 글 형태

증상에서 시작해 원인과 조치로 끝나는 문제 해결 글, 설정 화면 단계별 안내, 두 도구의 숫자가 다른 이유 정리, 소액 광고 결과 공개. 화면 캡처가 있어야 한다.

## 3부류: 숫자를 보는 사람

### 이해하고 있는 것

- 방문과 가입과 결제는 다른 숫자이고 각각 따로 봐야 한다는 것
- 전환 이벤트를 어디서 어떻게 잡는지
- GTM으로 태그를 걸고 미리보기로 확인하는 법
- 자기 업종의 대략적인 벤치마크
- 사용자에게 직접 물어봐야 알 수 있는 것이 있다는 것

### 궁금해하는 것

- 방문은 있는데 가입이 없는 이유가 랜딩인지 가격인지 타깃인지
- 어떤 이벤트를 잡아야 퍼널이 보이는지
- 온보딩 첫 화면에서 사람이 빠지는 이유
- 이메일과 알림으로 다시 불러올 수 있는지
- A/B 테스트를 이 규모에서 해도 되는지
- 고객 인터뷰를 어떻게 하는지, 몇 명이면 되는지
- AI로 분석과 리포트를 대신 시킬 수 있는지

### 궁금해하지 않는 것

- 용어 정의와 시작 안내 (이미 안다)
- 마케팅 이론 일반 (STP, 4P)
- 도구 하나의 기능 나열
- 예산 배분과 어트리뷰션 (아직 채널이 하나다)

### 관심 툴과 전략과 스킬의 깊이

| 구분 | 내용 | 깊이 |
|---|---|---|
| 툴 | GA4 | 이벤트를 직접 정의하고 탐색 보고서로 퍼널을 만드는 수준 |
| 툴 | GTM | 버튼 클릭과 폼 제출을 이벤트로 잡는 수준 |
| 툴 | 믹스패널, 앰플리튜드, 포스트호그 | 사용자 단위 행동을 보기 시작하는 수준 |
| 툴 | 클래리티, 핫자 | 녹화와 히트맵으로 이탈 지점을 보는 수준 |
| 툴 | 스티비, 메일침프, 인앱 온보딩 | 가입자에게 두세 통을 자동으로 보내는 수준 |
| 툴 | 탤리, 서치콘솔 검색어 | 설문과 검색어로 사용자 의도를 읽는 수준 |
| 전략 | 전환 정의, 온보딩 개선, 리텐션 이메일, 랜딩 A/B, 가격 실험, SEO 확장 | 유입보다 유입 이후를 고친다 |
| 스킬 | 퍼널 읽기, 이벤트 설계 기초, 고객 인터뷰, 가설 검증, 카피 테스트 | 숫자에서 가설을 만들고 하나씩 확인한다 |

### 기대가 깨지는 계기

퍼널을 고쳐 전환율이 올랐는데 절대 수가 작아 매출이 안 된다. "도구 하나 붙이면 답이 나온다"가 깨지고 통하는 채널을 찾아야 한다는 것을 알면 4부류로 간다.

### 검색하는 말의 형태

기능 이름이 붙는다. `GA4 탐색 보고서 퍼널`, `GTM 폼 제출 이벤트`, `포스트호그 GA4 비교`, `온보딩 이탈률`, `서치콘솔 색인 생성되지 않음`.

### 맞는 글 형태

기능 하나를 깊게 파는 글, 이벤트 설계 튜토리얼, 실제 계정 데이터로 검증한 글, 고객 인터뷰 진행 기록. 결론이 앞에 오고 근거 표가 뒤따른다.

## 4부류: 채널을 굴리는 사람

### 이해하고 있는 것

- 맡은 채널의 입찰과 타게팅과 소재 실험 방법
- 픽셀과 전환 API의 차이, 어트리뷰션 창이 숫자를 바꾼다는 것
- 자기 채널의 CAC와 결제 전환율이 얼마면 유지되는지
- 콘텐츠를 혼자 계속 만들 수 없어 체계가 필요하다는 것
- 대행사와 프리랜서에게 무엇을 시키고 무엇을 직접 해야 하는지

### 궁금해하는 것

- 플랫폼이 바꾼 것이 내 성과에 미치는 영향 (Advantage+ 확대, PMax 자동화, 쿠키 제한)
- 예산을 늘렸을 때 어디서부터 효율이 꺾이는지
- 소재를 AI로 만들어도 성과가 유지되는지, 어디까지 맡길 수 있는지
- 리포트 자동화 (GA4 API, 루커 스튜디오, 클로드 코드로 주간 리포트)
- 레퍼럴과 제휴처럼 광고 밖의 채널이 이 규모에서 되는지
- AI 검색에서 제품이 언급되게 하려면 무엇을 해야 하는지 (AEO, GEO)
- 이벤트 설계를 다시 짜야 하는지, 어디서 시작해야 하는지

### 궁금해하지 않는 것

- 설정 화면 단계별 안내
- 도구 소개와 가격 정리
- 채널 하나 안에서만 통하는 팁
- 검증 없는 전망과 트렌드 요약

### 관심 툴과 전략과 스킬의 깊이

| 구분 | 내용 | 깊이 |
|---|---|---|
| 툴 | 메타 Advantage+, 구글 애즈 PMax, 네이버 GFA | 자동화 캠페인을 굴리며 소재와 예산으로 통제하는 수준 |
| 툴 | 힉스필드, GPT 이미지 | 소재를 주 단위로 여러 개 뽑아 실험에 넣는 수준 |
| 툴 | GA4 API, 루커 스튜디오, 클로드 코드 | 주간 리포트와 이상 감지를 자동으로 돌리는 수준 |
| 툴 | 채널톡, 알림톡, 브레이즈 | 행동 기반으로 메시지를 나눠 보내는 수준 |
| 툴 | 버퍼 | 여러 SNS에 예약 게시하며 콘텐츠를 시스템으로 돌리는 수준 |
| 툴 | 전환 API | 픽셀과 함께 서버 전송을 붙이고 중복을 확인하는 수준 |
| 전략 | 채널 우선순위, CAC와 LTV, 리타게팅, 레퍼럴, 콘텐츠 시스템, 제품 주도 성장, AEO와 GEO | 채널을 포트폴리오로 본다 |
| 스킬 | 단위 경제, 실험 설계, 벤치마크 판단, 외주 브리프, 소재 반복 생산 | 혼자 하던 일을 남과 도구에 나눠 준다 |

### 기대가 깨지는 계기

예산을 두 배로 늘렸는데 성과는 1.3배다. 되던 채널이 정책 변경 한 번에 흔들린다. "예산을 늘리면 비례한다"가 깨지면 5부류로 간다.

### 검색하는 말의 형태

정책 이름과 두 시스템 이름이 함께 붙는다. `Advantage+ 크리에이티브 AI 이미지`, `PMax 검색어 제외`, `GA4 API 루커 스튜디오 자동화`, `Meta CAPI 픽셀 중복`, `GTM 서버 컨테이너 비용`.

### 맞는 글 형태

플랫폼 변경 사항의 실무 영향 정리, 자동화 튜토리얼, 채널 확장 실험 기록, 본인 계정 데이터로 검증한 글. 수치 대신 비율과 배수로 쓴다.

## 5부류: 체계를 갖춘 사람

### 이해하고 있는 것

- 4부류가 아는 것 전부와 그것이 왜 그렇게 설계되었는지의 내력
- GA4와 광고 플랫폼과 CRM의 숫자가 왜 다른지와 어디까지 맞출 수 있는지
- 동의 관리와 개인정보 규제가 측정에 주는 제약
- 플랫폼 API와 데이터 스키마, 도구의 한계선
- 벤더와 대행사가 하는 말 가운데 어디가 영업인지

### 궁금해하는 것

- 증분 측정 (리프트 테스트, 지오 실험, MMM)을 자기 규모에서 어떻게 돌리는지
- 쿠키 이후 측정 체계를 어떻게 다시 짜야 하는지
- 아직 답이 없는 문제 (AI 검색 유입의 귀속, 에이전트가 대신 검색하는 세계의 측정)
- 팀원과 고객에게 측정 설계를 가르치는 방법과 교육 자료
- 도구 도입 판단 (서버사이드 태깅, CDP, 어트리뷰션 솔루션이 값을 하는지)
- AI 에이전트로 리포트와 태깅 작업을 자동화할 때 어디까지 믿을 수 있는지
- 자기 방법을 자동화하고 상품화하는 법 (스킬, 에이전트, 템플릿)
- 다른 전문가의 반대 의견과 그 근거

### 궁금해하지 않는 것

- 검증 없는 요약과 소개 (직접 확인할 수 있다)
- 기능 사용법
- 일반론과 원칙 나열
- 자기가 이미 아는 것과 같은 결론을 반복하는 글

### 관심 툴과 전략과 스킬의 깊이

| 구분 | 내용 | 깊이 |
|---|---|---|
| 툴 | 빅쿼리 | GA4 원본 데이터로 세션과 사용자를 다시 만드는 수준 |
| 툴 | 서버사이드 GTM | 태그 전체를 서버로 옮기고 개인정보와 중복을 통제하는 수준 |
| 툴 | 어트리뷰션, MMM, 리프트 테스트 | 채널 기여를 모델과 실험으로 재는 수준 |
| 툴 | CDP, CMP | 데이터 흐름과 동의를 회사 단위로 설계하는 수준 |
| 툴 | AI 에이전트, 스킬, MCP | 자기 방법론을 코드와 문서로 굳혀 남이 쓰게 만드는 수준 |
| 전략 | 증분 측정, 예산 배분, 팀과 외주 구조, 브랜드 자산, 방법론 상품화 | 마케팅을 조직과 체계로 다룬다 |
| 스킬 | 측정 체계 설계, 예산 배분 판단, 교육과 문서화, 벤더 평가, 자동화 파이프라인 | 판단 기준 자체를 만든다 |

### 기대가 깨지는 계기

정확히 재도 예산 결정이 쉬워지지 않는다. 다른 회사에서 자기 방법이 통하지 않는다. 여기서 깨지는 기대는 다음 부류가 아니라 글감이 된다.

### 검색하는 말의 형태

검색보다 인용과 공유로 도달한다. 검색할 때는 영어 원문 문서, 릴리스 노트, 실험 이름, 특정 사람의 이름을 친다.

### 맞는 글 형태

가설과 실험과 결과가 있는 글, 통념에 반하는 관찰, 추정형 어조의 전망 에세이. 이 부류는 글을 읽고 댓글과 인용으로 반응하므로 인용될 문장을 앞에 둔다.

## 부류를 정하는 절차

주제를 확정한 뒤 글을 쓰기 전에 세 가지를 순서대로 묻는다.

### 1. 검색어의 형태로 부류를 읽는다

| 검색어 형태 | 부류 |
|---|---|
| `홍보`, `알리기`, `뭐야`, `무료`, `추천` | 1 |
| 오류 메시지, `안 됨`, `차이`, `설정`, `소액` | 2 |
| 기능 이름, `퍼널`, `이탈`, `온보딩`, `비교` | 3 |
| 정책 이름, 두 시스템 이름 조합, `자동화`, `영향` | 4 |
| 영어 원문 용어, 실험 이름, 사람 이름 | 5 |

`topic-selection-gate.md`의 고유명사 게이트를 먼저 통과한 주제라야 이 표가 작동한다. 고유명사가 없으면 부류도 정할 수 없다.

### 2. 한 글에 한 부류, 넓혀도 인접 부류까지

1부류 글에 4부류 내용을 넣으면 1부류는 그 대목에서 나가고 4부류는 앞부분을 건너뛰다 나간다. 1과 2, 3과 4처럼 이웃한 부류까지만 한 글에 담는다. 2와 5를 한 글에 담지 않는다.

### 3. 부류에 따라 도입부와 근거 수위를 바꾼다

| 부류 | 도입부 | 근거 | 화면 캡처 | 기대를 다루는 방식 |
|---|---|---|---|---|
| 1 | 정의 문장과 실물 비유 | 공식 문서 요약 | 있으면 좋음 | "좋으면 퍼진다"를 부정하지 않고 다음 행동 하나를 준다 |
| 2 | 증상 서술 | 설정 화면과 공식 문서 | 필수 | 소액 광고 결과를 있는 그대로 보여 준다 |
| 3 | 문제 정의 | 실제 계정 확인 | 필수 | 유입보다 유입 이후를 보게 한다 |
| 4 | 변경 사항과 영향 요약 | 직접 검증 데이터 (비율과 배수) | 설계도 우선 | 효율이 꺾이는 지점을 숫자로 보여 준다 |
| 5 | 가설 | 실험 결과와 반대 근거 | 필요 없음 | 불확실성을 인정한다 |

## 준이아빠블로그의 현재 위치

2026-08 기준 조회 구성은 AI 84.8%, 데이터와 마케팅 1.8%다. 유입의 대부분은 1부류와 2부류가 AI 도구 이름을 검색해 들어온다. 클래스와 코스는 1부류와 2부류를, 검증 글과 GA4 설계 글은 5부류를 향한다. 3부류와 4부류를 향한 글이 상대적으로 적다.

AI로 제품을 만든 사람이 늘어난 만큼 1부류와 2부류는 계속 커진다. 이들이 AI 도구 이름으로 들어와 마케팅 글로 옮겨 가게 하려면 **AI 도구 주제 안에 알리는 일을 붙이는 글**이 필요하다. `클로드 코드로 만든 앱 홍보`, `GPT로 랜딩 카피 쓰기`처럼 도구 이름과 마케팅 행동을 한 제목에 둔다.

그래서 주제를 정할 때 아래를 함께 본다.

- 검색 유입이 목적이면 1부류에서 3부류 사이에서 고른다. 검색량이 여기에 있다.
- 신뢰와 인용이 목적이면 4부류와 5부류를 향해 쓰고, SNS 확산을 전제로 한다.
- 3부류와 4부류를 향한 글은 검색 유입과 신뢰를 함께 얻는다. 비어 있는 만큼 우선순위를 높인다.

## 적용하지 않는 경우

- 뉴스레터, 사내 문서처럼 받는 사람이 이미 정해진 글
- SNS 원고. 다만 어느 부류를 향한 블로그 글을 옮기는지는 알고 써야 한다
- 딱콩이 네이버 블로그 육아 글
