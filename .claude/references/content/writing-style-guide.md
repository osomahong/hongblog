# 콘텐츠 타입별 작성 규칙

2026-08-08에 범위를 좁혔다. 그 전에는 공통 문체 규칙을 `prose-rules.md`와 나눠 갖고 있었고, 같은 규칙이 두 곳에 조금씩 다르게 적혀 어느 쪽을 따를지가 그때그때 달랐다. 공통 문체는 전부 기준 문서로 넘기고 여기에는 **타입별 규칙만** 남긴다.

## 규칙이 어디에 있는지

| 주제 | 기준 문서 |
|---|---|
| 금지 기호, 헤딩, 문장 규칙, 추상 표현, 군더더기, 비문 유형, 담백함과 근거 수위, 정의 문장, 지칭 | `.claude/skills/write-insight/references/prose-rules.md` |
| 중심 비유, 문장과 어휘, 개념 도입 순서, 도입부, 정보 계층, 글 유형별 골격 | `.claude/skills/write-insight/references/writing-craft.md` |
| 검수 게이트 절차 | `.claude/skills/write-insight/SKILL.md` 4단계 |
| 문어체 사전, 낭독 검수 | `.claude/skills/prose-inspector/` |

여기 있는 규칙과 기준 문서가 어긋나면 기준 문서를 따르고, 이 문서를 고친다.

## 어투 예외

기본은 존댓말(합쇼체)이며 `prose-rules.md` 3절이 기준이다. 타입별 예외만 적는다.

- LifeLog: 해요체 허용 (`~예요`, `~해요`)
- 코드 주석: 반말 허용

## 자기 지칭

자기 지칭은 `준이아빠블로그`로 쓴다. 블로그를 가리키는 지시 표현을 쓰지 않는다. AI 답변 엔진이 문장을 인용할 때 브랜드가 함께 옮겨지게 하기 위함이다. `check-literary.mjs`에 HARD로 등록되어 있다.

글 자체를 가리키는 `이 글은 ~를 정리합니다`도 가능하면 `지금부터 ~를 정리합니다`나 주제 명시형으로 푼다.

## 타입별 구조

Post(인사이트)의 골격은 `writing-craft.md` 7절이 기준이다. 여기에는 나머지 타입만 둔다.

### Class (용어사전)

```
## 정의
- 1~2문장 핵심 정의

## 상세 설명
- 개념의 배경, 등장 맥락
- 3~5문단

## 활용 예시
- 실무 적용 사례
- 코드 예시 (해당 시)

## 관련 개념
- 비교 개념, 상위와 하위 개념
```

본문 150단어 이상. H2 면제. AEO 점검은 직접 답변과 엔티티 명확성만 본다.

### FAQ

- 길이 150~300단어
- 마크다운 헤딩(`##`, `###`) 사용 금지
- 문단 구분은 빈 줄로만
- 이미지 삽입 대상이 아니다

### Course

목차 페이지 성격이므로 metaTitle과 metaDescription만 검증한다. 본문 길이와 H2는 면제다.

## 퀴즈

### Post (인사이트)

- 글에서 다룬 경험과 분석을 근거로 의견이 나뉘는 질문을 낸다
- 모든 선택지가 일리 있어야 한다. 명백한 오답을 넣지 않는다
- explanation에서 글의 맥락을 근거로 답을 설명한다
- `~일까요?`, `~라고 생각하시나요?` 형태의 열린 질문

### Class (용어사전)

- 핵심 개념 이해도를 확인하는 질문
- 비슷한 개념 간 차이를 구별하는 형태
- `~의 역할은?`, `~과 ~의 차이는?` 형태

### 공통

퀴즈 1개, 선택지 3~4개(4개 권장), explanation 2~3문장, `correctIndex`는 0부터 센다.

## 이미지

2026-08 개정. 그 전에는 자동 생성 일러스트 2장을 넣는 규칙이었으나, 지금은 **외부에서 찾은 실제 예시 이미지**를 쓴다. 자동 삽입 스크립트(`inject-images-all.ts`)는 저장소에 없다.

절차와 판정 기준은 `write-insight/SKILL.md` 3단계가 기준이다. 요약하면 이렇다.

- 실제 인터페이스 화면, 결과물 스크린샷, 공식 다이어그램을 쓴다
- 추상 일러스트, 상징 그림, 자체 생성 SVG, 의미 없는 헤더 아트를 쓰지 않는다
- `public/images/insights/{slug}/`에 내려받는다. 외부 핫링크를 쓰지 않는다
- alt는 이미지가 무엇을 보여주는지 한 문장으로 쓴다
- FAQ는 이미지 대상이 아니다

배치 밀도는 `writing-craft.md` 6절에 있다. 절차를 설명하는 글은 단계마다 한 장을 붙인다.

## 스크린샷 개인정보

- 타인의 이름, 프로필 사진, 개인적인 정황(개인 상담 대화, 개인 계정 목록, 신분증 관련 화면)이 보이는 스크린샷은 블러 여부와 관계없이 쓰지 않는다
- 쓸 수 있는 것: 개인 식별 요소가 없는 표준 UI 화면(알림 팝업, 버튼, 공식 도움말 문서)
- 오래된 UI 캡처는 현재 화면과 다를 수 있음을 본문에 밝히거나 쓰지 않는다
