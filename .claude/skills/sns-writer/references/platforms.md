# 플랫폼별 규격과 작성법

2026년 8월 기준. 한 문장 요약: **쓰레드는 정보를 풀어 주고, 인스타는 정보를 압축해 닫는다.**
길이만 줄인 같은 글을 양쪽에 올리면 두 채널 모두에서 반응이 없다.

## 1. 쓰레드(Threads)

이 계정은 **정보성 계정**이다. 일상 잡담 계정의 반말 문화를 따라가지 않는다.
톤은 **합쇼체 + 두괄식 + 스레드 체인**이다.

**목적은 블로그 유입과 팔로워 확보다.** 본문을 다 옮기지 않는다. 피드에서 읽는 사람은
깊은 설명을 견디지 않으므로, 재미있는 것 2~3개를 가볍게 던지고 세부는 블로그로 넘긴다.
읽고 나서 "핵심은 알았는데 설정 방법이 궁금하다"는 상태를 만드는 것이 이상적이다.

### 규격

| 항목 | 값 |
|---|---|
| 게시물 1개 | 500자 상한. **각 편은 120~350자. 350자를 넘기면 지루해진다** |
| 체인 길이 | 훅 1개 + 본문 2~4개. 짧을수록 완독률이 높다 |
| 편당 아이디어 | **하나만.** 한 편에서 두 가지를 설명하고 있으면 하나를 버리거나 편을 나눈다 |
| 링크 | 글자 수에 포함되지 않음. 첫 링크만 미리보기 카드로 표시 |
| 태그 | 게시물당 1개, `#` 기호 없이. 카피 본문에 넣지 않고 따로 안내한다 |
| 이미지 | 각 편에 도표나 스크린샷 1장을 붙이면 좋다 |

### 작성 규칙

- **두괄식이 절대 규칙이다.** 첫 게시물 첫 줄에 그 글에서 가장 자극적인 사실을 그대로 꺼낸다. 궁금증만 만들고 정보를 감추는 훅은 쓰지 않는다.
- **가볍게 쓴다.** 문장은 짧게, 한 문단은 1~2문장으로 끝낸다. 배경 설명과 조건 나열은 지루함의 주범이다. "왜 그런가"는 한 줄이면 충분하고, 더 깊은 이유는 블로그가 맡는다.
- **읽는 사람의 상황으로 말한다.** "인스턴스를 교체할 때"보다 "월요일 아침에 리포트가 준비돼 있습니다"가 낫다. 기술 용어가 두 개 이상 들어간 문장은 다시 쓴다.
- **합쇼체로 쓴다.** "~습니다", "~입니다"가 기본이다. 사이사이 "~인데요", "~거든요" 같은 부드러운 종결을 섞어 리듬을 만든다. 반말은 쓰지 않는다.
- **번호를 붙인다.** 본문 편은 `1/`, `2/`로 시작하고, 번호 뒤에 그 편의 핵심을 한 문장으로 적는다.
- **수치는 무기다.** 월 20달러, 15개처럼 구체적인 값 한두 개가 신뢰를 만든다. 다만 수치를 늘어놓으면 표가 되므로 편당 한두 개만 쓴다.
- **세부를 다 풀지 않는다.** 조건이 세 개면 가장 중요한 하나만 말하고 "나머지 조건은 글에 정리해 뒀습니다"로 넘긴다. 핵심(결론)은 주되 세부(방법, 이유)는 남기는 것이 유입을 만든다.
- **링크는 마지막 편에 붙인다.** 링크 자체에 페널티는 없다(2024년 통설은 폐기됐고 2025년 메타 발표로는 링크 포함 글이 텍스트 전용보다 17% 나은 성과를 낸다). 다만 앞 문장이 왜 읽어야 하는지 이미 설명하고 있어야 한다.
- **참여 유도 문구는 쓰지 않는다.** "좋아요 눌러 주세요", "댓글 달아 주세요"는 다운랭크 대상이다. 팔로우 권유는 예외다(아래 참고).

### 체인 구조

**첫 게시물(훅)** — 세 덩어리로 짧게 끊는다. 여기만 250자 안팎으로 짧게 간다.

```
[핵심 사실 한 줄. 가장 자극적이고 유용한 것]

[요약 2~3줄. 무엇을 어떻게 했는지]

[스레드 예고 한 줄] 🧵
```

예시(구조 참고용):
```
오픈AI가 말하는 동안에도 듣는 GPT-Live를 6개월 만에 만들었습니다.

음성 프레임은 전용 고속 경로로 보내고, 깊은 추론은 뒤에서 비동기로 돌렸습니다.
서버가 바뀌어도 대화가 끊기지 않도록 상태도 미리 옮겼습니다.

어떻게 가능했는지 오픈AI의 엔지니어링 블로그를 읽어봤습니다. 🧵
```

**본문 편(1/, 2/...)** — 한 편에 아이디어 하나. 120~350자.

```
N/ [그 편의 핵심 한 문장. 결론부터]

[읽는 사람의 상황에서 그게 왜 중요한지 1~2문장]

[구체적인 예시나 수치 1~2문장]
```

편을 닫을 때 설명을 더 보태지 않는다. 결론과 예시가 끝나면 그대로 끝낸다.

**마지막 편** — 세부는 블로그로 넘기고, 팔로우 유도와 링크로 닫는다.

```
N/ [마지막 소재 또는 한 줄 정리]

[블로그로 넘기는 한 문장. "설정 순서와 나머지 조건은 글에 정리해 뒀습니다" 형태]

[팔로우 유도 한 줄]

[링크]
```

🧵 이모지는 첫 게시물 끝의 스레드 예고에만 쓴다. 이건 관례라 예외로 허용하며,
`references/writing-rules.md`의 이모지 2개 제한에 포함되지 않는다.

### 팔로우 유도

계정을 키우는 단계라 팔로우 유도를 넣되, **체인 전체에 두 번까지만** 쓴다.
중간에 한 번, 마지막 편에 한 번이 적당하다. 세 번을 넘기면 홍보 계정으로 읽힌다.

지켜야 할 것:

- **앞 문장의 내용에 붙여 쓴다.** 방금 설명한 것과 이어지는 자리에 놓아야 본문을 해치지 않는다. 예를 들어 기본값 함정을 설명한 뒤라면 "이런 기본값 함정은 도구마다 하나씩 있어서 발견할 때마다 정리해 올리고 있습니다"처럼 잇는다.
- **무엇을 올리는 계정인지 함께 말한다.** 팔로우할 이유가 되는 정보가 그 문장 안에 있어야 한다. "팔로우해 주세요"만 있으면 광고다.
- **한 문장으로 끝낸다.** 두 문장 이상 쓰면 본문 흐름이 끊긴다.
- **좋아요와 댓글은 요구하지 않는다.** 쓰레드 알고리즘이 참여 유도 미끼로 판정해 노출을 깎는다. 팔로우 권유는 여기 해당하지 않는다.

쓸 만한 형태:

| 위치 | 예시 |
|---|---|
| 중간 | 이런 기본값 함정은 도구마다 하나씩 있어서, 발견할 때마다 정리해 올리고 있습니다. |
| 마지막 | AI 도구를 실무에 붙이는 방법을 계속 정리하고 있으니 팔로우해 두시면 새 글이 보입니다. |

인스타그램은 해시태그 바로 앞에 한 번만 넣는다. 저장 유도와 나란히 두되 문장은 따로 만든다.

## 2. 인스타그램 피드 캡션

### 규격

| 항목 | 값 |
|---|---|
| 캡션 | 2,200자 상한 |
| 더보기 전 노출 | **약 125자** (모바일 2줄). 이 안에서 승부가 난다 |
| 해시태그 | **최대 5개**, 권장 3~5개. 2026년 1월부터 전 계정 적용 |
| 본문 링크 | 클릭되지 않는다 |
| 캐러셀 | 최대 20장, 슬라이드별 개별 캡션 가능 |

### 작성 규칙

- **첫 125자에 검색 키워드를 넣는다.** 해시태그보다 캡션 안의 키워드가 노출을 만든다. "GA4 이벤트 설정"을 다룬 글이면 그 표현이 첫 문장에 그대로 있어야 한다.
- **읽을 사람을 앞에서 좁힌다.** "블로그 유입은 늘었는데 전환이 그대로인 분들" 같은 대상 지정이 검색 키워드와 궁합이 좋다.
- **"~해요"체를 쓴다.** 쓰레드의 합쇼체보다 한 톤 부드러운 설명체다.
- **완결형으로 닫는다.** 한 편으로 정보가 완성되어야 한다.
- **해시태그는 3~5개, 어근이 겹치면 하나만.** `#마케팅 #마케팅공부 #마케팅팁`처럼 늘어놓지 않는다. `#일상 #소통` 같은 광범위 태그는 값이 없다. 5개를 넘기면 탐색 탭과 릴스 추천에서 빠진다.
- **링크는 본문에서 죽는다.** 세 가지 우회 중 하나를 고른다. 저장 유도("나중에 볼 수 있게 저장해 두세요")가 정보성 글에 가장 안정적이고, 프로필 링크 유도가 그다음, 댓글 키워드 DM 유도는 도달까지 같이 올리지만 운영 부담이 있다.

### 길이 기준

| 게시물 유형 | 캡션 길이 |
|---|---|
| 단일 이미지 | 125~150자. 캡션이 콘텐츠 본체다 |
| 교육형 캐러셀 | 300~800자. 정보는 슬라이드에 있고 캡션은 요약과 CTA만 맡는다 |
| 상세 해설 | 800~1,500자 |

지정이 없으면 단일 이미지 기준(125~150자)으로 쓰고, 글이 단계별 가이드나 도구 비교면 캐러셀 기준을 제안한다.

### 기본 구조

```
[훅 1줄. 125자 이내, 검색 키워드 + 대상 지정]

[본문 2~4줄. 문제 상황, 이 글이 주는 것, 구체적 근거 한 줄]

[CTA 1줄. 저장 또는 프로필 링크]

[해시태그 3~5개]
```

## 3. 링크드인

**독자가 다르다.** 쓰레드와 인스타는 관심사로 모인 익명 피드지만, 링크드인은
동료와 업계 사람들이 실명으로 보는 공간이다. "재미있는 도구"가 아니라
"업무가 어떻게 달라지는지"가 글의 축이 되어야 한다.

### 규격

| 항목 | 값 |
|---|---|
| 본문 | 3,000자 상한. **실전 목표 400~900자** |
| 더보기 전 노출 | 약 200자(데스크톱 기준, 모바일은 더 짧다). 첫 두 줄에서 승부가 난다 |
| 해시태그 | 3~5개, 본문 끝 |
| 링크 | 본문에 넣으면 도달이 깎인다는 통설이 있으나 확정적이지 않다. 본문 끝에 넣는 것을 기본으로 하되, 사용자가 원하면 "링크는 댓글에" 방식을 안내한다 |
| 톤 | 합쇼체. 실명 공간이므로 세 플랫폼 중 가장 정제된 문장 |

### 작성 규칙

- **첫 200자 안에 결론을 넣는다.** 더보기가 접히기 전에 "그래서 업무에 뭐가 달라지는데"의 답이 보여야 한다.
- **실무 장면으로 연다.** 도구 소개("스파크가 출시됐습니다")가 아니라 업무 변화("월요일 아침 리포트 취합이 사라졌습니다")로 시작한다.
- **짧은 문단 3~4개로 끝낸다.** 문단 사이는 빈 줄. 개조식 목록을 한 번 쓰는 것은 좋지만 글 전체를 목록으로 채우지 않는다.
- **판단을 담는다.** 링크드인 독자는 요약보다 "그래서 도입할 만한가"라는 의견에 반응한다. 어디까지 검증됐고 무엇은 아직 이르다는 선 긋기가 이 계정의 전문성이 된다.
- **개인 경험 화법을 지어내지 않는다.** "직접 3주 써 보니" 같은 문장은 실제로 한 일이 블로그 본문에 있을 때만 쓴다.
- **팔로우 유도는 마지막 한 문장.** "AI 도구의 실무 적용을 계속 정리하고 있습니다" 정도로 절제한다. 쓰레드식 권유("팔로우해 두시면 새 글이 보입니다")보다 한 톤 낮춘다.

### 기본 구조

```
[업무 변화 한 문장. 결론부터]

[무엇이 그걸 가능하게 했는지 1~2문단]

[구체적 예시 또는 개조식 목록 하나]

[판단: 도입할 만한가, 무엇을 주의해야 하는가]

[블로그 안내 + 팔로우 유도 한 문장]

[링크 (?ref=lkdn)]

[해시태그 3~5개]
```

## 4. 링크 추적 파라미터

채널별 유입을 구분하기 위해 블로그 링크에 ref 파라미터를 붙인다.

| 플랫폼 | 형식 |
|---|---|
| 쓰레드 | `https://www.digitalmarketer.co.kr/insights/<slug>?ref=thd` |
| 링크드인 | `https://www.digitalmarketer.co.kr/insights/<slug>?ref=lkdn` |
| 인스타그램 | 링크 없음 |

## 5. 축별 대조

| 축 | 쓰레드 | 인스타그램 | 링크드인 |
|---|---|---|---|
| 형태 | 훅 1편 + 본문 2~4편의 짧은 체인 | 캡션 한 편 | 본문 한 편 |
| 길이 | 각 편 120~350자 (훅은 250자 안팎) | 단일 125~150자, 캐러셀 300~800자 | 400~900자 |
| 톤 | 합쇼체. 가볍게 던지는 설명 | "~해요"체. 압축된 정리 | 합쇼체. 가장 정제된 문장 |
| 전개 | 두괄식. 재미있는 것 2~3개만, 편당 하나 | 첫 125자에 키워드와 대상, 뒤에 요약 | 첫 200자에 업무 변화 결론 |
| 깊이 | 결론과 예시까지. 방법과 이유는 블로그로 | 핵심과 주의점만 | 예시와 판단(도입할 만한가)까지 |
| 해시태그 | 1개, `#` 없이, 본문 밖에 안내 | 3~5개, 본문 끝 | 3~5개, 본문 끝 |
| 링크 | 마지막 편에 `?ref=thd` | 없음 | 본문 끝에 `?ref=lkdn` |
| CTA | 팔로우 유도와 블로그 안내로 닫는다 | 행동 요청("저장해 두세요") | 절제된 소개 한 문장 |
| 성공 지표 | 링크 클릭, 팔로우 전환, 답글 | 저장, DM 공유, 프로필 방문 | 링크 클릭, 댓글, 리포스트 |

## 6. 훅 유형 7가지

정보성 글에 실제로 통하는 유형이다. 클릭베이트 없이 궁금하게 만드는 것만 골랐다.

쓰레드 훅과 인스타 첫 줄 모두 합쇼체나 해요체로 쓴다. 차이는 어투가 아니라 정보의 밀도다.

| 유형 | 쓰레드 훅(합쇼체) | 인스타 첫 줄(해요체) |
|---|---|---|
