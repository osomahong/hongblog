# 카드뉴스와 썸네일 글자 규칙

인스타 카드뉴스, 쓰레드 썸네일, 링크드인 썸네일 안에 들어가는 모든 글자에 적용한다.
`make_cards.mjs`와 `make_thumb.mjs`가 그리기 전에 `check_cards.mjs`를 자동으로 부르고,
HARD가 있으면 그리지 않는다.

## 왜 따로 있나

2026-08-24에 GA4 교육 카드가 비문인 채로 나갔다. 원인은 두 가지였다.

1. hongblog 문체 게이트는 `content/*.md`만 본다. 카드 글자는 `cards.json`에 있어 아무도 검사하지 않았다.
2. 카드는 문장이 아니라 개조식이라, 블로그용 규칙(합쇼체, 완결 문장)을 그대로 대면 오히려 어긋난다.

그래서 사전은 hongblog와 공유하고, 개조식 규칙만 여기에 따로 둔다.
문어체 사전을 여기에 복사하지 않는다. 사전이 두 벌이 되면 같은 비문이 다시 난다.

## 문체: 개조식

블로그 본문은 합쇼체, 카드 글자는 개조식이다. 카드는 글자가 적어 종결어미가
지면을 잡아먹고, 줄바꿈이 어긋나면 어미만 다음 줄로 넘어가 문장이 끊겨 보인다.

| 나갔던 것 | 고친 것 |
|---|---|
| GA4 계정이 없으면 화면을 볼 수 없습니다 | GA4 계정 없으면 화면도 못 봄 |
| 순서대로 클릭해 보세요 | 순서대로 클릭 |
| 어디부터 시작할까요? | 초급, 중급, 심화 |
| 연습할 계정이 없어서 | 연습할 GA4 계정이 없음 |
| 지금까지는 | 막히는 곳은 GA4 계정 |

닫는 형태는 명사(`GA4 계정`), 명사형 어미(`없음`, `만듦`), 동사 명사형(`열기`, `누르기`) 셋 중 하나다.
한 카드 안에서는 형태를 섞지 않는다.

## 기계가 잡는 것 (HARD)

- 합쇼체 종결: `습니다`, `입니다`, `합니다`, `됩니다`
- 해요체 종결: `해요`, `세요`, `어요`, `예요`, `네요`
- 마침표 종결. 개조식에는 마침표를 찍지 않는다
- 물음표 종결. 카드 제목과 소제목은 명사형 선언으로 쓴다
- 조사 종결: `~는`, `~이`, `~을`, `~로`. 문장이 끊겨 보인다
- 연결어미 종결: `~어서`, `~면서`, `~는데`, `~지만`, `~니까`. 뒷말을 기다리게 된다
- 금지 기호: `—`, `·`, `…`
- hongblog 공용 문어체 사전에 걸리는 어휘 전부

## 기계가 물어보는 것 (WARN)

- 카드 하나에 개체가 없음. `GA4`, `클로드 코드` 같은 이름이 하나도 없으면 그 카드만 봐서는 무엇에 관한 말인지 모른다. 인스타는 한 장씩 넘겨 보므로 카드마다 대상을 다시 말해야 한다
- 지시어(`이것`, `그런`, `이런`). 카드에는 앞뒤 맥락이 없어 가리킬 대상이 없다
- `것`, `점`으로 얼버무린 명사화
- 마지막 줄에 두 글자 이하만 남는 줄바꿈

## 사람이 보는 것 (낭독 검수)

기계로 잡을 수 없어 소리 내어 읽는다. 실제로 나갔던 비문이 근거다.

| 항목 | 나갔던 것 | 고친 것 |
|---|---|---|
| 주어 누락 | 화면이 처음이면 초급 | GA4 화면이 처음이면 초급 |
| 주어 누락 | 계정 없으면 화면도 못 봄 | GA4 계정 없으면 화면도 못 봄 |
| 주어 누락 | 구글 데모는 관리 화면 잠김 | 구글 데모 계정은 관리 화면이 잠김 |
| 목적어에 안 쓰는 동사 | 측정기준 목록 펴기 | 측정기준 목록 열기 |
| 목적어에 안 쓰는 동사 | 이탈률 열 붙이기 | 이탈률 열 추가하기 |
| 대상이 모호한 명사 | 탐색이 안 되면 중급 | 탐색 보고서가 어려우면 중급 |
| 조사 누락 | 회사 계정은 설정 못 건드림 | 회사 계정은 설정을 못 건드림 |

읽을 때 순서:

1. 주어 확인. 무엇의 화면인지, 무엇의 숫자인지 카드만 보고 아는지 본다
2. 주어와 서술어의 호응 확인
3. 그 목적어에 실제로 쓰는 동사인지 확인
4. 조사 확인. 은/는과 이/가를 바꿔 읽어도 뜻이 같으면 조사가 헐거운 것이다
5. 카드를 순서대로 이어 읽어 말이 되는지 확인

## 넘침

글자 폭은 폰트에서 읽은 실제 자폭으로 잰다. 글자 수로 세지 않는다.
한글은 1em이고 영문 소문자는 0.5em대라, 같은 글자 수라도 실제 폭이 두 배까지 벌어진다.
2026-08-24에 마지막 카드의 주소가 빨간 상자 밖으로 삐져나온 원인이 이것이었다.
상자 폭을 560px로 박아 두었는데 `digitalmarketer.co.kr/ga4-edu`의 실제 폭은 584px이었다.

지금은 렌더러가 알아서 처리한다.

- 색 상자는 글자를 재서 그 폭으로 만든다. 상자를 먼저 정하고 글자를 넣지 않는다
- 글자가 넘치면 크기를 한 단계씩 줄인다
- 다 줄여도 안 들어가면 `assertInside`가 PNG를 쓰지 않고 멈춘다

그래서 `cards.json`에서 고칠 것은 폭이 아니라 글의 길이다. 줄이 잘게 쪼개지면
글자가 작아지므로, 한 줄은 14자 안팎으로 잡는다.

## 렌더 후

PNG를 Read로 직접 열어 본다. 검사기는 글자만 보고 사진은 못 본다.
글자가 사진의 밝은 부분과 겹쳐 안 읽히면 다른 사진으로 바꾼다.
