# blog-topic-creator

새 글의 주제를 정하는 관문. 여기서 확정된 주제가 `write-insight`로 넘어간다.
주제 선정 방식이 요청마다 달라서 생기는 혼선을 없애기 위해, 시작할 때 방향부터 고른다.

## 0. 방향 분기 (가장 먼저)

네 방향이 있다. D는 이 스킬이 처리하지 않고 넘긴다.

| 방향 | 내용 |
|---|---|
| **A. 핫토픽** | 최근 며칠의 AI/마케팅 화제를 리서치해 후보를 제안한다 (지금까지의 기본 방식) |
| **B. SNS용 주제** | SNS에서 반응이 나올 주제를 기준으로 발굴한다. 블로그 글이 SNS 카피의 원천이 된다 |
| **C. 직접 지정** | 사용자가 주제를 준다. 리서치 없이 바로 글쓰기로 넘어간다 |
| **D. 검색 데이터** | 사이트가 이미 받고 있는 검색 데이터에서 빈자리를 찾는다. **`seo-topic-finder`로 넘긴다** |

A와 D는 근거가 다르다. A는 바깥에서 지금 화제인 것을, D는 우리 사이트가 이미 노출되고 있는데 아직 글이 없는 자리를 본다. 둘 다 "글감 추천"으로 불리지만 나오는 후보가 겹치지 않는다.

분기 판정:

1. **호출에 주제가 이미 있으면 C다.** "코덱스 신기능으로 글 써줘"처럼 주제가 보이면 묻지 않고 C로 진행한다.
2. **`hot` 또는 `sns` 인자가 있으면 해당 방향으로 바로 간다.**
3. **검색 데이터 신호가 있으면 D다.** 검색어, 검색량, 노출, 순위, 서치콘솔, GSC, 자기잠식, 커버리지 갭이 언급되면 묻지 않고 `seo-topic-finder`로 넘긴다.
4. **그 외에는 AskUserQuestion으로 묻는다.** 선택지 네 개: "핫토픽으로 (최근 화제 리서치)", "검색 데이터로 (우리 사이트가 이미 노출되는 자리)", "SNS용 주제로 (쓰레드/인스타 반응 기준)", "직접 정할게요". 텔레그램 요청이면 이 질문도 텔레그램으로 보낸다.

## A. 핫토픽 모드

최근 화제 중에서 이 블로그가 다룰 만한 것을 찾는다.

1. WebSearch로 최근 7일 안의 소식을 조사한다. 검색어에 현재 연도를 넣는다.
   - 축: AI 모델/도구 출시와 업데이트, 가격 변동, 마케팅 플랫폼 변경(GA4, 구글애즈, 메타), SEO/검색 동향
   - 공식 발표(회사 블로그, 저장소, 문서)가 확인되는 것을 우선한다. 커뮤니티 소문만 있는 것은 후보에서 뺀다.
2. **이미 다룬 주제인지 확인한다**: `node .claude/skills/sns-writer/scripts/find_post.mjs "<키워드>"`로 기존 글을 검색한다. 겹치면 버리거나 "기존 글 업데이트" 후보로 분류한다.
3. 후보 3~5개를 표로 제시한다: 주제, 무슨 일이 있었는지 한 줄, 카테고리(MARKETING/AI_TECH/DATA), 시의성(오늘 안 쓰면 식는지).
4. 사용자가 고르면 확정.

핫토픽은 유통기한이 짧다. 가격 인하, 신모델 출시 같은 뉴스성 주제는 "오늘 쓰지 않으면 가치가 떨어진다"고 표시한다.

## B. SNS용 주제 모드

**기준이 다르다.** 핫토픽은 "지금 화제인가"를 보지만, SNS용은 "피드에서 스크롤을
멈추게 하는가"를 본다. `sns-writer` 스킬의 소재 기준을 주제 선정에 앞당겨 적용하는 것이다.

1. `.claude/skills/sns-writer/references/platforms.md`의 훅 유형 표를 읽는다. 주제 자체가 훅 유형에 올라타는지가 판정 기준이다:
   - **의외성**: 통념과 반대인 사실이 핵심인 주제 (기본값 함정, 상위 모델이 더 나쁜 지표)
   - **손해 회피**: 모르면 돈이나 시간을 잃는 주제 (요금 함정, 제재 사례, 설정 실수)
   - **수치 대비**: 극적인 숫자 비교가 있는 주제 (7.5배 비용 차이, 3시간이 25분으로)
   - **바로 써먹기**: 오늘 실무에 옮길 수 있는 설정이나 절차
2. 소스 두 곳에서 후보를 모은다:
   - 웹 리서치: 위 네 유형에 해당하는 최근 소재
   - 기존 글 재활용: `find_post.mjs --latest 30`으로 최근 글을 훑고, SNS 카피를 아직 안 만든 글 중 훅이 강한 것을 "새 글 없이 SNS만 만들기" 후보로 함께 제시한다
3. 후보 3~5개를 표로 제시한다: 주제, 예상 훅 한 줄(실제 쓰레드 첫 문장 형태로), 훅 유형, 신규 글인지 기존 글 재활용인지.
4. 사용자가 고르면 확정.

예상 훅을 표에 쓰는 이유: 주제가 좋아 보여도 훅 문장이 안 나오면 SNS용으로는 실패한 주제다. 훅이 먼저 나오는지로 검증한다.

## C. 직접 지정 모드

1. 주제가 이미 명확하면 되묻지 않는다.
2. 범위가 넓으면("AI에 관해 써줘") 한 번만 좁힌다: 카테고리와 핵심 질문 하나를 확인한다.
3. 바로 확정으로 넘어간다.

## 확정과 핸드오프

주제가 정해지면:

1. 한 줄로 정리해 보여 준다: 주제, 카테고리, 핵심 포인트 1~2개, (B 모드면) 예상 훅.
2. `write-insight` 스킬로 넘긴다. B 모드에서 "기존 글 재활용"을 골랐다면 write-insight 대신 `sns-writer`로 넘긴다.
3. 글이 완성되어 배포된 뒤 SNS 카피가 필요하면 `sns-writer`가 이어받는다. B 모드로 시작한 글은 배포 후 SNS 카피 제작까지 한 흐름으로 제안한다.

이 스킬은 주제만 정한다. 글 작성 규칙(문체, 검수 게이트)은 전부 write-insight의 영역이고
여기서 관여하지 않는다.
