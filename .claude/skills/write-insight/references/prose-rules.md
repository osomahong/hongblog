# 문체 규칙 (모든 글 공통)

hongblog의 모든 글에 적용하는 문장 규칙을 한곳에 모았다. 인사이트, 클래스, 코스, 그리고 UI 카피와 메타 필드까지 대상이다.

**이 문서가 존재하는 이유:** 같은 지적이 반복해서 나왔기 때문이다. 규칙이 여러 곳에 흩어져 있으면 글을 쓸 때 절반만 적용된다. 새 지적을 받으면 여기에 먼저 적고, 기계로 잡을 수 있는 것은 `check-literary.mjs` 사전에도 등록한다.

2. 제목과 헤딩
3. 문장 규칙

## 1. 기호 금지

두 기호는 예외 없이 쓰지 않는다. 본문, 제목, frontmatter의 모든 필드, 이미지 alt, 표 셀, 불릿, 인용블록, 3줄 요약까지 전부 해당한다.

| 기호 | 대체 |
|---|---|
| em dash (`—`) | 콜론(`:`). 콜론이 어색하면 마침표나 쉼표로 풀어 쓴다 |
| 가운뎃점 (`·`) | 쉼표(`,`). `VS Code·커서` → `VS Code, 커서` |

작성 후 반드시 확인한다. 둘 다 0건이어야 한다.

```bash
grep -n "—" content/insights/{slug}.md
grep -n "·" content/insights/{slug}.md
```

## 2. 제목과 헤딩

### 본론은 명사형, 독자 질문 섹션은 해요체 질문형

2026-08-08에 개정했다. 그 전 규칙은 질문형 헤딩을 전면 금지했는데, `check-prose.ts`는 반말 의문형만 막고 있었고 기존 글 935개 H2 가운데 156개가 이미 질문형이었다. 문서만 현실과 어긋나 있었다.

**본론 헤딩은 명사형이나 선언형으로 쓴다.**

- **명사형 종결**: `~사용법`, `~비교`, `~3가지 이유`, `~흐름`, `~정리`
- **선언형 종결**: `~정리했습니다`, `~로 충분합니다`

설명을 이어가는 섹션에 흐름 접속사를 붙인 구어체 헤딩을 달지 않는다.

| 금지 | 대체 |
|---|---|
| 그래서 가장 잘 쓰는 사람들은 어떻게 쓴다고 하나요? | 쓰레드에서 화제가 된 클로드 코드 헤비 유저들의 6가지 고민 |
| 그런데 대부분의 사람은 이렇게 씁니다 | 대다수 일반 사용자의 클로드 코드 사용법 |
| 그럼 따라가야 할까요? | 헤비 유저를 따라가지 않아도 되는 3가지 이유 |

**독자의 의문을 그대로 옮기는 섹션은 해요체 질문형으로 쓴다.** 다음 두 자리에만 해당한다.

1. **자주 묻는 질문 섹션.** 독자가 실제로 던질 질문을 헤딩에 그대로 올린다.
2. **핵심 쟁점을 여는 섹션.** 글 전체가 답하려는 질문이 하나로 좁혀질 때 그 질문을 헤딩으로 쓴다. 글당 두 개를 넘기지 않는다.

| 자리 | 예 |
|---|---|
| FAQ | `쿠키가 없어지면 UTM은 못 쓰나요?` |
| FAQ | `타겟 광고는 정말 불가능해지나요?` |
| 핵심 쟁점 | `왜 Claude Code를 최종 선택하게 되었을까요?` |

`~할까?`, `~하나?` 같은 반말 의문형은 어느 자리에서도 쓰지 않는다. `check-prose.ts`에 HARD로 등록되어 있다.

**질문형 헤딩은 검색 노출과 직결된다.** `src/lib/extract-faq.ts`가 물음표로 끝나는 H2와 H3를 FAQPage JSON-LD로 추출한다. 명사형 헤딩만 쓰면 그 글은 FAQPage가 발행되지 않는다.

**나머지 헤딩은 전부 명사형이다.** 설명 섹션에 질문형을 남발하면 FAQ 스키마에 답변이 아닌 문단이 섞여 들어간다.

### 문어체 의문형 종결 금지 (-는가, -은가, -던가, -인가)

`왜 재는가?`, `무엇이 다른가` 같은 종결은 논설문 어투라서 제목, 헤딩, 파트명, 표 머리글, 본문 질문 목록 어디에도 쓰지 않는다. 2026-08-06 투슬리 GA4 온보딩 커리큘럼에서 26곳 반복된 것을 사용자가 지적해 확정했다. `check-literary.mjs`에 HARD로 등록되어 있다.

| 위치 | 대체 | 예 |
|---|---|---|
| 헤딩, 제목, 파트명 | 명사형 | 왜 재는가 → 측정하는 이유 |
| 본문의 질문 나열, 표 셀 | `-는지` 절 | 완료율이 다른가 → 완료율이 다른지 |
| 청중이나 독자에게 직접 보여주는 질문 | 해요체 | 왜 재는가 → 왜 측정할까요 |

### 헤딩 압축 금지

대상을 생략하거나 관형절을 압축하지 않는다. 사용자가 "전형적인 AI 비문"으로 지목한 패턴이다.

| 잘못 | 문제 | 고침 |
|---|---|---|
| 시작 전에 알아 둘 제약 | 무엇에 관한 제약인지 없음 | Meta MCP를 쓸 때 알아둬야 할 제한적인 점 |
| 링크가 얕은 페이지를 보완합니다 | `링크가 얕은`이 무엇을 수식하는지 모름 | 링크를 적게 받는 페이지의 발견을 돕습니다 |

판정 방법은 하나다. **그 헤딩만 떼어 놓고 봐도 무엇에 관한 이야기인지 알 수 있는가.** 모르면 대상을 넣는다.

### 글 제목은 검색 키워드형 명사구

선언형 어미보다 실제 검색어 형태를 우선한다. `~원인과 대응 순서를 정리했습니다`보다 `~원인과 대응법 정리`가 낫다.

마케팅 수사, 감탄사, 호기심 유발 표현을 쓰지 않는다.

| 금지 | 대체 |
|---|---|
| 충격! AI가 검색을 죽이고 있다 | AI Overviews 도입 이후 오가닉 CTR은 61% 하락했습니다 |
| 당신이 몰랐던 SEO의 비밀 5가지 | SEO에서 자주 오해되는 5가지 사실 |
| 마크다운, 들어는 봤는데 뭔가요? | AI 시대에 마크다운이 중요한 이유 |

## 3. 문장 규칙

### 선언형 강조 마무리 금지

`이것이 ~의 전부이자 핵심입니다`, `~가 정확히 이 지점입니다` 같은 힘주는 마무리를 쓰지 않는다. 설명이 끝나면 그대로 문단을 끝낸다.

### 사실 서술도 한 단계 완화

예외가 있을 수 있는 서술에는 여지를 남긴다.

| 강함 | 완화 |
|---|---|
| 수십 분씩 혼자 작업합니다 | 작업하기도 합니다 |
| 표준이고 | 표준 대안이고 |
| 공식 기능으로 들어오고 있습니다 | 공식적인 기능으로 자리잡으려 하고 있습니다 |

### 문어투와 번역투 동사 회피

- `질문이 나옵니다` → `질문이 떠오릅니다`
- 기계나 프로그램이 주어가 아니면 `돌아갑니다` 대신 `진행됩니다`

### 라벨과 명사구에는 장형 부정을 쓴다

제목, 카드 라벨, 표 머리글의 `안 남는 것`, `안 되는 것`은 `남지 않는 것`,
`되지 않는 것`으로 쓴다. 단형 부정(`안`+동사)은 구어의 것이라 문서 라벨에서
말투가 된다. 대화체 본문과 인용문의 구어는 예외다.
(2026-08-12 사용자 지적, 투슬리 온보딩 덱)

### 수 관형사와 추상명사를 직접 붙이지 않는다

`세 지식`, `두 재료`, `다섯 값`처럼 단위명사 없이 눌러 쓴 압축은 AI식 비문이다.
단위명사를 붙이거나(`세 가지 지식`, `두 가지 재료`) 수사를 뒤로 뺀다(`값 다섯 가지`).
`두 사람`, `세 단계`, `다섯 건`처럼 셈 단위가 되는 명사는 그대로 쓴다.
(2026-08-12 사용자 지적, 투슬리 온보딩 덱)

### 읽는 사람을 3인칭으로 지칭하지 않는다

`사람은 기다리기만 해야 할까요?` 대신 `우리는 기다려야만 할까요?`처럼 글쓴이를 포함한 `우리`로 쓴다.

`독자`라는 단어를 쓰지 않는다. `이 글을 읽는 분들`, `여러분`으로 쓴다.

### "낯설다"에는 비교 기준을 붙인다

`cmux라는 이름이 낯설 수 있습니다` 대신 `cmux라는 이름은 tmux보다 상대적으로 낯설 수 있습니다`처럼 무엇에 비해 낯선지 명시한다.

### AI식 안내 지시문 금지

읽는 사람의 행동을 지시하는 문형은 AI 특유의 투라서 쓰지 않는다.

- `소리 내어 답한다고 생각하면서 읽어 주세요` → 삭제
- `떠올리면서 읽어 주세요` → `떠올리면 답하기 쉽습니다`

선택은 읽는 사람에게 둔다.

### 병렬 설명 3개 이상은 불릿으로 분리

산문 한 문단에 `A는 ~, B는 ~, C는 ~`로 나열하지 않는다. `- **용어**: 설명` 형식으로 나눈다. AEO 인용 가치가 올라간다.

### 같은 말 반복 금지

한 문장에 같은 동사 어근을 세 번(`쓰면~쓰더라도~쓰는`), 인접한 두 문장에 같은 종결어(`보겠습니다. ~보겠습니다.`)를 쓰지 않는다.

### 군더더기 제거

확신 어조는 유지하되 잉여 단어는 덜어낸다.

| 군더더기 | 정제 |
|---|---|
| Q&A 쌍, 질문과 답변 페어 | Q&A |
| ~예시로 씁니다 | ~예시로 들어 설명합니다 |
| ~으로 연결해 보여드리겠습니다 | ~보여드리겠습니다 |
| 이 글의 본문에서는 | 이 글에서는 |
| 결론적으로 말씀드리면 | 결론은 |

**`~라고 할 수 있습니다`는 군더더기가 아니다.** 공식 문서로 확인한 사실을 이 형태로 쓰면 회피이므로 `~입니다`로 바꾼다. 판단이나 평가를 담은 문장은 이 형태가 맞다. 판정 기준은 5절의 근거 수위다.

### 정의 문장 속 압축 용어는 직후에 풀이한다

도입 정의 문장에 `해싱된 자사 고객 데이터`처럼 전문 개념 두 개 이상이 압축된 표현이 들어가면, 도입 직후에 그 표현을 단어 단위로 나눠 푸는 섹션이나 문단을 둔다. 각 단어를 불릿으로 풀고 마지막에 완결형 재정의를 굵게 쓴다. 2026-08-12 향상된 전환 글에서 사용자 교정으로 확정했다.

### 현상 서술 뒤에 함의와 업계 맥락을 한 줄 붙인다

`~가 보고서에서 빠질 수 있습니다`처럼 현상을 서술하고 끝내지 않는다. 그 현상이 무엇을 뜻하는지(광고 성과의 근거가 사라진다), 업계에서 흔히 말하는 어떤 흐름과 이어지는지(서드파티 쿠키 약화)를 한두 문장으로 연결한다. 연결 문장의 사실 관계는 반드시 확인한 뒤 완화형으로 쓴다. 2026-08-12 사용자 교정.

### 기술 용어의 비유는 직접 설명과 병기한다

해싱 같은 보안, 기술 용어를 곁가지 비유(도장 자국)로만 반복하지 않는다. 두 번째 등장부터는 `사람의 눈으로는 식별할 수 없는 해싱값(암호화된 값)`처럼 직접 설명으로 바꾸거나 병기한다. 비유는 감을 잡는 용도이고, 뜻을 확정하는 것은 직접 설명이다. 2026-08-12 사용자 교정.

### 비문 유형 (교정 이력에서 추출)

낭독 검수에서 이 표를 대조한다. 전부 실제로 지적받아 고친 것이다.

| 유형 | 잘못된 예 | 고친 예 |
|---|---|---|
| 호응 어긋남 | 시간이 지나도 코드를 정리하면 됩니다 | 시간이 지난 뒤에도 코드를 정리하면 갚을 수 있습니다 |
| 비유 의미 붕괴 | 빌린 것이 이자로 돌아온다 | 빌려 쓴 시간에 이자가 붙는다 |
| 주어 누락 | 다행인 점은 눈에 보인다는 것입니다 | 다행인 점은 이 부채가 눈에 보인다는 것입니다 |
| 동사 3연속 | 쓰면 지저분하게 쓰더라도 쓰는 동안 | 직접 쓰면, 결과물이 지저분하더라도 그 과정에서 |
| 무생물 주어에 타동사 | 엉킨 코드는 이해를 깎아냅니다 | 엉킨 코드는 따져 보기 어렵고, 그만큼 이해도 어려워집니다 |
| `밖에` 중의성 | 무엇을 하기로 했는지 밖에 적어 둔 | 무엇을 하기로 했는지를 바깥에 적어 둔 |
| 처음 언급에 `다시` | 뒷부분에서 다시 다루겠습니다 (처음인데) | 뒷부분에서 풀어 보겠습니다 |
| 검증 불가 단정 | 이 표현을 제목에 처음 올린 연구 | 이 표현이 널리 알려지는 계기가 된 연구 |
| 은유 대신 직접 서술 | 시스템의 그림을 그리지 못합니다 | 시스템의 구조를 이해하기 어렵습니다 |
| `이해가 줄어들다` | 이해가 더 줄어듭니다 | 이해가 더 어려워집니다 |
| 이미지 참조 호응 어긋남 | 위 도해처럼 설정은 2026년에 두 번 바뀝니다 (도해는 한 번의 통합만 그림, `~처럼 바뀐다` 호응 불성립) | 설정은 2026년에 두 차례 바뀝니다. 위 도해는 그 가운데 6월 통합을 정리한 것입니다 |
| 이미지 참조 뒤 주어 누락 | 구글이 공식 문서로 안내한 일정입니다 (앞 문장 주어와 붙어 읽힘) | 구글이 공식 문서로 안내한 일정은 다음과 같습니다 |

## 4. 추상 표현 금지

일상 대화에서 쓰지 않는 단어는 쓰지 않는다. 신문 칼럼이나 자기계발서 톤을 피한다.

| 금지 | 권장 |
|---|---|
| 풍경 | 사용 패턴, 사용법, 하루, 일과, 모습 |
| 협상하다 | 부딪히다, 맞춰 일하다 |
| 리듬 | 작업 속도, 페이스 |
| 사이클 | 완주하다, 처음부터 끝까지 끝내다 |
| 결, 정수, 본질 | 핵심, 중요한 점, 진짜 의미 |
| 빚어내다, 다가서다, 길어 올리다 | 만들다, 가까워지다, 끄집어내다 |
| 카테고리 | 종류, 방식, 분류 |
| 패러다임, 메커니즘, 모멘텀 | 흐름, 작동 방식, 추진력 |
| 디스럽션, 게임체인저 | 변화, 판도를 바꾸는 |
| 거대한 흐름, 시대의 물결 | 최근 변화, 요즘 추세 |
| 레이어, 페어, 스택 | 기능, 요소, 쌓인 구조 |
| 갈리다, 갈라지다 | 달라지다, 나뉘다 |
| 손보다, 손대다, 손이 가다, 손에 익다 | 고치다, 바꾸다, 들이는 시간, 익숙해지다. `check-literary.mjs`에 HARD 등록됨 |
| 흔들리다, 묻히다, 변화를 가리다 (수치, 상태를 가리킬 때) | 줄어들다, 잘 보이지 않다, 달라지다 |
| 데려오다, 붙잡다, 실마리 (유입, 방문자를 가리킬 때) | 유입되다, 바로 나가다, 먼저 확인할 곳 |
| 뜻이 생기다, 뜻이 맞다, 그 몫이다, 감각을 잡다 | 판단 근거가 되다, 비율이다, 방법을 익히다 |
| 명부 대조, 대장 대조 같은 한자어 압축 (설명, 표 셀에서) | 데이터 확인, 목록에서 확인 |
| 도해 | 이미지, 그림. 절대 쓰지 않는다. `check-literary.mjs`에 HARD 등록됨 |
| 자리 (도구, 환경, 화면을 가리킬 때) | 작업 공간, 환경, 화면 |
| 독자 | 여러분, 이 글을 읽는 분들 |
| 유저, 사용자 (글의 수신자를 가리킬 때) | 여러분, 방문자 |
| 본문 (글 전체를 가리킬 때) | 콘텐츠 |

`여러분`은 쓴다. 금지되는 2인칭은 `독자`와 `당신`이다. 기술 설명상 영어 용어가 표준인 경우(`<head>`, JSON-LD, canonical)는 그대로 쓴다.

### 과장된 극적 은유 금지

`변신`, `마법처럼`, `놀랍게도`, `놀라운`, `혁명적`, `획기적`, `차원이 다른`, `상상을 초월하는`, `완전히 새로운`, `세상을 바꾸는`, `기적처럼`, 강조 부사로 쓴 `엄청나게`와 `순식간에`를 쓰지 않는다.

| 금지 | 대체 |
|---|---|
| 내 노트북을 웹 서버로 변신시킨다 | 내 노트북에서 작은 서버 프로그램이 실행된다 |
| AI가 마법처럼 코드를 짜준다 | AI가 코드를 대신 작성한다 |
| 놀랍게도 3초 만에 완성됩니다 | 3초 만에 완성됩니다 |

**요리, 집, 창고, 부엌, 공장, 도로 같은 일상 실물에 뿌리를 둔 비유는 계속 권장한다.** 구체적이고 사실적이기 때문이다.

비유를 쓰는 방법은 `writing-craft.md` 1절에 있다. 요약하면 글마다 중심 비유를 하나 정해 여러 섹션에 걸쳐 확장하고, 곁가지 비유는 한 번씩만 쓴다. 중심 비유를 두 개 이상 세우지 않는다.

### 판단 기준

1. 그 단어를 일상 대화에서 쓰는가
2. 비유 없이 직접 설명할 수 있는가
3. 같은 비유를 두 번 이상 쓰는가
4. 외래어 추상명사를 한국어로 옮길 수 있는가
5. 문어체 동사를 일상 동사로 바꿀 수 있는가

## 5. 담백함과 근거 수위

### 1인칭 관찰과 수집 표현 금지

`제가 모은`, `모아 봤습니다`, `바꿔 봤습니다`, `추렸습니다`를 쓰지 않는다. `사례들을 바탕으로`, `정리했습니다`, `정리하면 다음과 같습니다`로 쓴다.

### 근거에 따라 단정 강도를 조절한다

**공식 문서로 확인된 내용만 단정형(`~입니다`)으로 쓴다.** 커뮤니티나 경험담 기반 서술은 완화한다.

| 근거 | 표현 |
|---|---|
| 공식 문서 | ~입니다, 실제로 구글도 ~라고 설명합니다 |
| 커뮤니티, 경험담 | ~생길 수 있습니다, ~공통점이 존재합니다, ~사례들이 있는 |

문서 제목을 정확히 모르면 단정하지 않는다. `크롤링 예산 문서에서` 대신 `크롤링 관련 문서에서`로 쓴다.

### 검증 불가 단정 금지

`처음으로`, `최초로`, `가장` 같은 주장을 출처 없이 쓰지 않는다. 확인이 안 되면 `널리 알려진 계기가 된` 수준으로 완화한다.

### 연출성 장면 묘사와 감정 수식 제거

`빨간 알림이 떠 있습니다` 같은 장면 연출, `~는 마음으로 정리했습니다` 같은 감정 표현을 쓰지 않는다. 상황 설명은 한 문장으로 압축한다.

### 같은 안내를 두 번 하지 않는다

앞 문장과 의미가 겹치는 당부나 안내 문장은 삭제한다.

### Sources에는 공식 문서만

출처 목록에는 공식 도움말, 정책 문서, 공신력 있는 기관 자료만 올린다. 커뮤니티 글과 개인 블로그는 본문에서 `~라는 사례가 있습니다`로만 언급하고 목록에 넣지 않는다.

### highlights는 행동 지침 2개 내외

수치와 시한 정보는 본문에서 다루고, 요약 카드에는 `무엇을 먼저 하라`, `무엇을 하지 마라` 성격의 항목만 남긴다.

### GA4 실수치 노출 금지

본문에 GA4 세션이나 페이지뷰 실수치를 적지 않는다. 비율과 배수 표현만 쓴다.

## 6. AEO, GEO 정의 문장

모든 문장 생성에 적용한다. 본문뿐 아니라 metaTitle, metaDescription, excerpt, ogDescription, JSON-LD까지 대상이다.

1. **도입부와 metaDescription의 첫 문장은 핵심 개체를 포함한 `X는 Y입니다` 단정형 정의로 쓴다.**
2. **메타, 본문 도입부, JSON-LD의 개체와 정의 표현을 일치시킨다.** 삼중 정렬이다.
3. **행동 유도 문구를 쓰지 않는다.** `알아보세요`, `확인하세요`, `시작해 보세요`는 인용 가치가 없다.
4. **자체 용어는 첫 등장에 괄호 정의를 붙인다.** 예: `AIPBL(프로젝트 기반 AI 실습)`.

### 초보자 안내 브리지

전문 개념을 다루는 섹션 초입에 1~2문장을 넣는다.

1. 낯섦 인정: `~라는 개념은 ~보다 상대적으로 낯설 수 있습니다` (비교 기준을 반드시 붙인다)
2. 완결형 재정의: `쉽게 말하면 ~입니다`
3. 예고: `이 블로그에 실제 적용된 ~를 그대로 보여드리겠습니다`

음성 검색과 AI Overviews가 그대로 답변으로 가져갈 수 있는 완결 문장으로 쓴다.

### 시점 명시

가격, 플랜, 버전, 시장 수치처럼 시간에 민감한 정보에는 `2026년 8월 기준`처럼 시점을 적는다.

## 7. 글 유형별 톤

기본 톤 위에 유형별 조정을 얹는다.

### 클로드 코드, AI 코딩 입문 글

`고급 운영 전략` 톤을 쓰지 않는다. 다음 5단 흐름을 따르고 희망적으로 마무리한다.

헤비 유저 풍경 → 일반 사용자 상황 → 친절한 비교 → 따라갈 필요 없다 → 각자의 속도

### 자기 사이트 데이터 검증 글 (SEO, AEO, GEO, GA4)

- 제목과 메타는 간결한 사실
- 도입부 동기는 순수한 궁금증으로 쓴다. 누군가를 공격하거나 비판하는 표현(`자칭 전문가`, `답답했다`, `의심`)을 절대 쓰지 않는다
- 컨설팅이나 경력 언급은 본문 한 곳에서만, 출처를 추상화해서 1회
- 인용블록(`>`) 단정형 첫 문장 5개 이상, Q&A형 단락 4개 이상을 본문 곳곳에 배치한다. 추측형 종결 0건

### 추정, 예측, 역사 비교형 에세이

- 추정형 어조: `~로 보입니다`, `~할 가능성이 적지 않아 보입니다`, `단정하기 어렵습니다`
- 외부 매체와 기관 인용을 최소화한다. `한 조사`, `최근 발표된 한 연구` 정도로 쓰고 인물명과 저서명만 유지한다
- Q&A 단락을 쓰지 않는다. 의문은 줄글에 녹인다
- 인용블록 첫 문장도 가설이나 관찰 형태로 쓴다
- 결론에 불확실성을 명시적으로 인정한다

검증 글과 튜토리얼에는 이 조정을 적용하지 않는다.

### 앤트로픽 공식 교육 자료 정리 (CLAUDE_EDUCATION)

첫 단락에 앤트로픽 공식 교육 자료를 한국 입문자가 보기 편하게 정리한 글임을 알리고, 본문 끝에 참고 자료 섹션을 둔다.

## 8. 지칭과 명명

| 항목 | 규칙 | 잘못 → 고침 |
|---|---|---|
| 자기 지칭 | 이 사이트의 클래스는 강의가 아니라 교육 목적 콘텐츠다 | `이번 강의 주제입니다` → `이 글에서 다룹니다` |
| 상호 참조 | 번호가 아니라 개념 이름으로 부른다 | `6강에서 다시 나옵니다` → `정규 URL을 다룰 때 다시 나옵니다` |
| 대명사 | 주체 이름을 적는다 | `자기가 아는 주소만` → `크롤러 봇이 알고 있는 주소만` |
| 비유 헤딩 | 비유만 단독으로 쓰지 않고 원개념을 함께 적는다 | `골목을 도는 우편배달부` → `크롤러봇, 배송을 담당하는 배송기사` |
| 조어 | 사전에 없는 조합을 만들지 않는다 | `세대 명단` → `등록된 주소록` |
| 처음 언급 | 아직 다루지 않은 내용에 `다시`를 붙이지 않는다 | `다시 다루겠습니다` → `이어서 다루겠습니다` |
