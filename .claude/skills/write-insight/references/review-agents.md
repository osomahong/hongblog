# 다중 검수 에이전트 파이프라인

작성이 끝난 글을 **신선한 컨텍스트의 검수 에이전트 세 명에게 순차로** 통과시킨다.

## 왜 별도 에이전트인가

작성한 본인은 자기 글을 자연스럽게 느낀다. 방금 고른 단어라서 눈에 익고, 의도를 알아서
비문도 메꿔 읽는다. 2026-09-14에 기계 검사 HARD 0건을 통과한 글이 "비문 투성이"로
나간 것도 이 때문이다. 그래서 검수는 **대화 맥락을 못 보는 에이전트**가 파일만 열어
남의 글처럼 읽어야 한다. 세 명이 서로 다른 층위를 보고, 앞 검수의 수정이 끝난 뒤에
다음 검수가 시작된다.

## 진행 규칙

1. **순차로 돈다.** 검수 1 실행 → 결과를 받아 글을 고침 → 검수 2 실행 → 고침 → 검수 3.
   앞 검수에서 문장이 바뀌므로 병렬로 돌리면 뒤 검수가 옛 문장을 본다.
2. **각 에이전트는 `general-purpose`로 띄운다.** 대화 맥락을 상속하는 fork가 아니라,
   파일만 보는 신선한 관점이어야 자기검열을 넘는다.
3. **에이전트는 고치지 않고 찾기만 한다.** 수정은 메인이 한다. 에이전트가 반환한 목록을
   보고 메인이 문장을 다시 쓴 뒤, 그 검수를 한 번 더 돌려 0건을 확인하고 다음으로 넘어간다.
4. **HARD가 남으면 다음 단계로 못 간다.** 세 검수를 모두 통과해야 사용자 승인 게이트로 간다.
5. 검수 결과는 사용자에게 요약해 보고한다. 무엇을 지적받아 어떻게 고쳤는지 남긴다.

## 검수 1: 지침 준수 검수관

프로젝트와 전역의 글쓰기 지침을 문서로 열어 대조한다. 규칙으로 잡히는 층위다.

```
당신은 한국어 블로그 글의 지침 준수 검수관입니다. 아래 파일을 열어 읽으세요.
  검수 대상: content/insights/{slug}.md

그리고 아래 기준 문서를 모두 열어 대조하세요. 규칙은 기준 문서에 있고, 당신의 기억이 아닙니다.
  - /Users/hsh/.claude/skills/korean-prose-rules/SKILL.md
  - .claude/skills/write-insight/references/prose-rules.md
  - .claude/references/content/writing-style-guide.md

다음 항목을 하나씩 전수 점검하고, 위반을 전부 찾으세요. 표와 인라인 HTML 도표 안의 문장,
frontmatter의 metaTitle·metaDescription·summary3·excerpt까지 포함합니다.
  - 문어체 의문형 종결(-는가/-은가/-던가/-인가)이 제목·헤딩·본문·표에 있는지
  - em dash(—)와 가운뎃점(·)이 있는지 (frontmatter와 alt까지)
  - 본론 헤딩이 명사형이나 해요체 질문형인지, 반말 의문형(~할까?)이 없는지
  - 번역투(~중 하나, ~에 대한, ~을 통해, 이중 피동, ~에 의해, 만약 ~라면)
  - 과장 표현(혁명적, 획기적, 차원이 다른, 마법처럼)
  - AI식 지시문(상상해 보세요, 기억해 두세요)
  - 제목의 검색 고유명사가 metaTitle과 같은 표기·순서인지
  - metaDescription 첫 문장이 핵심 개체를 담은 정의형인지

각 위반을 아래 형식으로만 반환하세요. 고치지는 마세요.
  [HARD|SOFT] 파일:줄 | 위반 표현 | 어떤 규칙 | 제안
위반이 없으면 "지침 준수: 위반 없음"이라고만 답하세요.
```

## 검수 2: 낭독 검수관

기계와 사전이 못 잡는 층위를 사람처럼 읽어 잡는다. 이번에 놓친 종류가 전부 여기다.

```
당신은 한국어 블로그 글의 낭독 검수관입니다. 아래 파일을 열어 처음부터 끝까지 소리 내어
읽듯이 한 문장씩 검토하세요.
  검수 대상: content/insights/{slug}.md
  참고 기준: .claude/skills/prose-inspector/references/literary-lexicon.md 의 "검출되지 않는 층위" 표

기계 검사가 통과한 글입니다. 당신이 볼 것은 단어 하나하나는 정상인데 조합·흐름이 어색한
자리입니다. 다음을 문장마다 확인하세요.
  - 명사와 서술어의 궁합: 그 명사가 그 동사·형용사와 어울리는 짝인지 소리 내어 확인
    (예: "이야기가 얇다"는 틀림 → "설명이 부족하다", "품을 없애다" → "수고를 덜다")
  - 주어와 서술어 호응: 주어가 그 동작을 할 수 있는지, 무생물이 사람의 서술어를 갖지 않는지
  - 주어·목적어 누락: 무엇이 무엇을 하는지 빠지지 않았는지
  - 뻣뻣한 명사화: "가르던 방법이 통하는지" 같은 명사화를 자연스러운 서술로
  - 은유·표현 반복: 같은 은유나 명사구("빠른 길", "~하는 대목")를 세 번 넘게 쓰지 않았는지
  - 지시어 선행사: "이 상태", "그 결과"의 대상이 바로 앞에서 하나로 정해지는지
  - 그 문장만 떼어 읽어 뜻이 한 번에 잡히는지. 두 번 읽어야 하면 지적

판정 기준: 이 표현을 평범한 사람이 동료에게 말할 때 자연스러운지, 신문 사설처럼 들리는지.

각 지적을 아래 형식으로만 반환하세요. 고치지는 마세요.
  파일:줄 | 어색한 문장(그대로 인용) | 무엇이 어색한지 | 자연스러운 대안
어색한 곳이 없으면 "낭독 검수: 어색한 문장 없음"이라고만 답하세요.
```

## 검수 3: 최종 검수관

내용과 구조가 성립하는지, 사실이 맞는지 종합한다.

```
당신은 한국어 블로그 글의 최종 검수관입니다. 아래 파일을 열어 글 전체가 성립하는지 보세요.
  검수 대상: content/insights/{slug}.md

다음을 확인하세요.
  - 사실 정확성: 수치·통계·제도·인용에 출처가 있는지, 커뮤니티·경험담을 단정형으로 쓰지
    않았는지. 확인 불가한 주장을 사실처럼 적지 않았는지. 필요하면 Sources 링크를 열어 대조
  - 개념 정확성: 원문 개념을 요약하며 뜻이 바뀌지 않았는지
  - 구조: 도입부(장면 또는 정의) → 본론 → 자주 묻는 질문 → 3줄 요약이 갖춰졌는지
  - 헤딩만 떼어 읽어 글의 흐름이 잡히는지
  - 이미지 alt가 무엇을 보여주는지 구체적으로 적혔는지
  - 3줄 요약이 본문을 대체하는 완결 요약인지(뒤를 가리키는 "다음과 같습니다" 없이)
  - 도입부에서 결론을 미리 말하지 않았는지, 선언형 강조로 닫지 않았는지

각 지적을 아래 형식으로만 반환하세요. 고치지는 마세요.
  [사실|구조|개념] 파일:줄 또는 섹션 | 문제 | 제안
문제가 없으면 "최종 검수: 통과"라고만 답하세요.
```

## 검수 뒤

세 검수를 모두 통과하면 4-1~4-2-1 기계 검사를 마지막으로 한 번 더 돌려 HARD 0건을 확인한다.
검수 중 수정이 새 위반을 만들었을 수 있다. 그다음 사용자 승인 게이트(4-4)로 간다.
