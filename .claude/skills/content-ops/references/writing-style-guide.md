# 작성 스타일 가이드

## 어투 규칙

### 기본 어투
- **존댓말(합쇼체)** 사용: ~입니다, ~합니다, ~됩니다
- 절대 반말 혼용 금지 (~이다, ~한다 ❌)
- **"독자"라는 단어 사용 금지**: 거리감을 만드는 호칭이라 본문 톤과 맞지 않는다
- 대체 호칭: "여러분", "이 글을 읽는 분들", "이 글을 보시는 분들"
- 메타 서술에서 본문 자체를 가리킬 때는 "이 글"로 통일 (예: "이 글은 실제 예시로 설명합니다")

### 예외
- LifeLog: 편안한 존댓말(해요체) 허용 (~예요, ~해요)
- 코드 주석: 반말 허용

## H2 헤딩 종결 톤 규칙 (AEO·FAQPage 자동 추출 필수)

`src/app/insights/[slug]/page.tsx`의 `extractFaqPairs()`는 물음표(`?` 또는 `？`)로 끝나는 H2만 질문으로 인식해 FAQPage JSON-LD의 `mainEntity` Q&A 페어로 발행한다. 물음표 하나 차이로 AEO·음성 검색 인용 대상에서 제외되므로 아래 규칙을 엄격히 적용한다.

### 필수 규칙

- 모든 질문형 H2는 **반드시 `?`로 끝낸다** (마크다운 렌더링에서 `？` 전각 물음표도 허용)
- 종결 톤은 **존댓말 의문형**으로만 작성: `~을까요?`, `~할까요?`, `~인가요?`, `~나요?`, `~걸까요?`
- **반말 의문형 금지**: `~는가`, `~하는가`, `~되는가`, `~할까`, `~인지`, `~뭘까`, `~인가`
- **중간 물음표 + 명사구 끝 금지**: `## CTR이란? 광고 소재가 관심을 끌고 있는가` 같은 패턴은 물음표가 끝에 없어 FAQPage 추출 실패. 한 질문으로 합치거나 재작성한다
- 질문형 비율은 **H2의 70% 이상**을 유지 (기존 AEO 체크리스트 3번 항목)

### before / after

| 금지(반말·부적합) | 권장(존댓말·추출 가능) |
|------------------|---------------------|
| ~~## Cowork는 어떻게 작동하는가~~ | ## Cowork는 어떻게 작동할까요? |
| ~~## 검색어는 왜 사라졌는가~~ | ## 검색어는 왜 사라졌을까요? |
| ~~## 누가 MCP를 알아야 하는가~~ | ## 누가 MCP를 알아야 할까요? |
| ~~## CTR(클릭률)이란? 광고 소재가 관심을 끌고 있는가~~ | ## CTR(클릭률)은 광고 소재가 관심을 끌고 있는지 어떻게 알려줄까요? |
| ~~## API 공부, 어디서부터 시작할까~~ | ## API 공부는 어디서부터 시작해야 할까요? |
| ~~## 어디까지 가능하고, 어디부터 조심해야 할까요~~ (물음표 누락) | ## 어디까지 가능하고, 어디부터 조심해야 할까요? |

### 명사구 헤딩이 적합한 경우

"Sources", "3줄 요약", "코드 예시" 등 **요약·보조 섹션**은 질문형으로 바꾸지 않는다. 본문의 핵심 논지를 다루는 H2만 질문형 + 물음표 규칙을 적용한다.

## 금지 어휘 목록 (추상 용어·거리감 호칭)

아래 단어들은 본문·excerpt·meta 필드 모든 곳에서 금지한다. 대체 표현이 명확하고, AEO 인용 시에도 자연어 인용 가치를 떨어뜨린다.

| 금지 단어 | 이유 | 대체 표현 |
|----------|------|----------|
| 독자 | 거리감 있는 호칭 | 이 글을 읽는 분들, 여러분 |
| 레이어 | 영어 추상 용어, 비전공자 혼란 유발 | 기능, 요소, 구성 |
| 페어(쌍) | 영문 번역투 군더더기 | Q&A (단독으로), 묶음 |
| 스택 | 영어 추상 용어 | 쌓은 것, 쌓인 구조 |
| 본문 (콘텐츠 집필 맥락에서 글 전체를 가리킬 때) | "콘텐츠"가 더 포괄적 | 콘텐츠 |
| 유저·사용자 (글의 수신자를 가리킬 때) | 제품 개발 용어 느낌 | 이 글을 읽는 분들, 방문자 |

**예외**: 기술 설명상 영어 용어가 표준인 경우(`<head>`, JSON-LD, canonical 등)는 그대로 사용한다.

## 군더더기 제거 규칙

불필요한 수식·번역투는 AEO 답변 인용 확률을 떨어뜨린다. 아래 패턴은 자동 정제 대상이다.

| 군더더기 | 정제 |
|---------|------|
| Q&A 쌍 | Q&A |
| 질문·답변 페어 | 질문과 답변, Q&A |
| ~예시로 씁니다 | ~예시로 들어 설명합니다 |
| ~으로 연결해 보여드리겠습니다 | ~보여드리겠습니다 |
| 이 글의 본문에서는 | 이 글에서는 |
| 결론적으로 말씀드리면 | 결론은 |
| ~라고 할 수 있습니다 (단정 회피형) | ~입니다 |

원칙: **확신 어조를 유지하되 잉여 단어는 모두 덜어낸다**.

## 리스트 활용 규칙

병렬 구조를 가진 설명은 문단이 아니라 불릿 리스트로 분리한다. AEO 답변 엔진은 리스트 구조를 정보 단위로 명확히 파싱한다.

### 리스트로 전환해야 하는 신호
- 한 문단에서 "A는 ~, B는 ~, C는 ~" 형태로 3개 이상 항목을 나열하는 경우
- 각 항목이 **독립된 완결 문장**으로 설명되어야 할 때
- 비교·분류·열거가 본문의 주요 정보일 때

### 리스트 작성 포맷
- 각 항목의 앞머리에 **볼드 용어**를 배치 (예: `**<title>**: 검색 결과 스니펫의 기본 소스입니다`)
- 항목별 설명은 1~2문장의 완결 문장으로
- 3~7개 항목이 이상적

### before / after

**before (병렬 산문)**:
> 각 태그의 역할은 명확합니다. `<title>`은 검색 결과 스니펫의 기본 소스입니다. `canonical`은 중복 콘텐츠 신호를 고정합니다. `og:*`는 공유 미리보기를 만듭니다.

**after (불릿 리스트)**:
> 각 태그의 역할은 다음과 같이 나뉩니다.
>
> - **`<title>`**: 검색 결과 스니펫의 기본 소스입니다.
> - **`canonical`**: 중복 콘텐츠 신호를 한 URL에 고정시킵니다.
> - **`og:*`**: 링크 공유 시 카드 형태 미리보기를 만듭니다.

## 금지 기호

- `—` (em dash) 사용 금지: 제목, 본문, excerpt, highlights 등 모든 텍스트 필드에서 사용하지 않는다
- `---` (수평 구분선) 사용 금지: 콘텐츠 본문에서 구분선을 넣지 않는다. 섹션 구분은 H2 헤딩으로만 한다
- 대체 표현: em dash 대신 쉼표, 마침표, 콜론(`:`) 등으로 문장을 나눈다

## 금지 수사·은유 표현

### 원칙
- 은유는 **일상 대화에서 실제로 쓰이는 비유만** 사용한다.
- 판단 기준: "이 표현을 평범한 사람이 동료에게 말할 때 자연스러운가?" 아니면 "광고 카피나 영화 나레이션 같은가?" 후자면 쓰지 않는다.
- 현상을 있는 그대로 서술하는 것이 기본. 화려한 수사는 담백체 기조를 해친다.

### 금지 단어 목록 (과장·극적·비현실적)
- **변신, 변환된다, 탈바꿈한다**: 장치·프로그램의 상태 변화를 극화하는 표현
- **마법처럼, 마법같이**: 원인·과정을 감춘 채 결과만 강조하는 표현
- **놀랍게도, 놀라운, 놀랍도록**: 독자 반응을 강제하는 부사·형용사
- **혁명적, 획기적, 차원이 다른, 완전히 새로운**: 검증 불가능한 격상 표현
- **상상을 초월하는, 세상을 바꾸는, 기적처럼**: 광고성 수사
- **엄청나게, 순식간에**(강조 부사 용법): 구체 수치로 대체 가능한 과장 부사

### before / after

| 과장된 은유 | 담백한 서술 |
|------------|-----------|
| 내 노트북을 웹 서버로 잠깐 변신시킨다 | 내 노트북 안에서 작은 서버 프로그램이 실행된다 |
| AI가 마법처럼 코드를 짜준다 | AI가 코드를 대신 작성해준다 |
| 놀랍게도 3초 만에 결과가 나옵니다 | 3초 만에 결과가 나옵니다 |
| 혁명적인 방식으로 데이터를 처리합니다 | 기존과 다른 방식으로 데이터를 처리합니다 |
| 엄청나게 빠른 속도로 응답합니다 | 100ms 이내에 응답합니다 |

### 허용되는 은유 (계속 권장)
일상적·구체적·실물에 뿌리 둔 비유는 오히려 이해를 돕는다. 아래 유형은 계속 쓴다.
- 요리·주방·식당 (부엌, 레시피, 재료, 창고 등)
- 집·건물 (방, 문패, 안방, 현관 등)
- 일상 사물 (상자, 서랍, 서류함 등)
- 교통·도로 (길, 번지수, 표지판 등)

판별 기준: "이 비유의 원재료가 일상에서 실제로 만질 수 있는 구체 사물인가?" 그렇다면 사용 가능.

- "~일까요?", "~라고 생각하시나요?" 형태의 열린 질문

### Class (용어사전) 퀴즈
- 핵심 개념 이해도를 확인하는 질문
- 비슷한 개념 간 차이를 구별하는 형태
- "~의 역할은?", "~과 ~의 차이는?" 형태

### 공통
- 퀴즈 1개, 선택지 3-4개 (4개 권장)
- explanation 2-3문장
- correctIndex는 0-based 인덱스

## 이미지 규칙

- Post, Class, LifeLog에 자동으로 2개의 일러스트가 삽입됨 — **이미지 생성은 필수 단계** (FAQ 제외)
- **`--no-images` 플래그 사용 금지** — 콘텐츠 생성 스크립트 실행 시 이미지 생성을 건너뛰어서는 안 됨
- 이미지 스타일: 플랫 디자인, 깔끔한 개념도/다이어그램
- 이미지에 텍스트 포함하지 않음
- Alt text: 한국어 30-80자, "~를 보여주는 개념도" 형태
- 배치: 글 전체의 1/3, 2/3 지점에 균등 배치
- 첫 번째 이미지는 ogImage(SEO/소셜 미리보기 썸네일)로 자동 설정됨
- 생성 실패 시 이미지 없이 콘텐츠 진행 (비차단 처리)
- 기존 이미지 없는 콘텐츠: `npx tsx scripts/inject-images-all.ts`로 일괄 보강 가능
